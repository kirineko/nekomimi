# extension-process-host Specification

## Purpose

为不断增长的用户代码提供可终止的独立执行生命周期，通过版本化宿主服务协议保留调用证据和授权边界，同时兼容现有 SDK 并明确进程隔离的真实能力限制。

## Requirements

### Requirement: 独立执行与兼容

系统 SHALL 在独立进程执行可执行扩展，协商当前宿主声明的 SDK 和进程协议版本，并提供 SDK 3 的公共工具、命令、钩子、状态、模型和声明式 UI API；未知能力 SHALL 在注册前拒绝。SDK 版本和进程协议版本 SHALL 分别检查，不要求两者采用相同版本号。进程隔离 MUST NOT 被描述为 OS 权限沙箱。

旧 V1/V2 SDK 扩展不保证兼容；不受支持的清单 SHALL 在执行工厂前拒绝，并提供当前版本资料入口，不自动改写扩展文件、加载旧代码或赋予新权限。

#### Scenario: 当前 SDK 扩展运行
- **WHEN** 用户显式授权与当前 SDK 3 及进程协议匹配的扩展
- **THEN** 公共工具、命令、钩子、状态、模型及声明式 UI 在独立进程和受控宿主服务边界内执行，身份及执行证据保持关联。

#### Scenario: 旧扩展升级运行
- **WHEN** 用户尝试启用使用不受支持 V1/V2 SDK 的扩展
- **THEN** 宿主给出版本诊断及 SDK 3 资料入口，不执行工厂、不改写原文件、不静默生成兼容层；未来能力或私有接口同样明确拒绝。

### Requirement: 宿主 RPC 证据与授权

系统 SHALL 为宿主调用绑定包、资源 revision、运行和调用身份，先记录意图再执行效果，并实施宿主能力/目标范围检查、取消和有界流量控制；过期或伪造的进程消息 MUST NOT 产生新副作用。

#### Scenario: 旧进程迟到响应
- **WHEN** 重载或取消后旧进程发送工具请求或完成响应
- **THEN** 系统保留必要诊断并拒绝新的执行与状态覆盖，不将消息归入新运行。

### Requirement: 故障清理

系统 SHALL 在进程阻塞、超时、崩溃或取消时停止接收新调度并执行平台支持的终止与强制清理；确认清理失败时 SHALL 报告 degraded，结果缺失的副作用标为 unknown。

#### Scenario: 扩展无限循环
- **WHEN** 扩展在回调中同步死循环或拒绝正常退出
- **THEN** Web 与宿主仍可响应取消，进程被有界清理；未能确认的操作不显示成功且不自动重跑。

### Requirement: 注册和版本切换

系统 SHALL 让候选注册在隔离空间完成并原子切换活动注册；仍被挂起工作流引用的版本不得被普通更新清除，明确撤销授权优先于保留运行版本。

#### Scenario: 候选重复注册
- **WHEN** 候选声明重复工具或清理失败
- **THEN** 旧有效注册不被部分替换；无法安全继续时显示降级原因。
