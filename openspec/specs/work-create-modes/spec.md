# work-create-modes Specification

## Purpose
使用户清楚区分处理自身项目与开发 Nekomimi 的两类任务，让每次操作绑定正确目标、有效能力和授权范围，并在重启及模式导航后保持隔离而不依赖模型自行判断权限。

## Requirements

### Requirement: 模式与目标身份
系统 SHALL 将 work 或 create 模式、目标身份和会话身份持久绑定，在创建后不原地改变该会话的模式；工作目标 SHALL 标识项目，创造目标 SHALL 标识开发目录、目标宿主及候选类型。

#### Scenario: 重启后继续
- **WHEN** 用户重新打开创造会话
- **THEN** 仍显示原创造目标和宿主，不能退回用户项目 cwd 后继续执行。

#### Scenario: 更换模式
- **WHEN** 用户从工作界面选择创造模式
- **THEN** 打开或创建关联创造会话，原工作历史及草稿不被改成创造内容，不自动提交任务。

### Requirement: 工作能力集
工作模式 SHALL 默认仅提供项目任务所需和已启用的能力，不暴露产品候选管理、核心切换或开发资料正文；SHALL 允许使用已交付能力，不要求载入创造过程。

#### Scenario: 普通项目修复
- **WHEN** 用户在 work 会话修复项目测试
- **THEN** 实际请求不含创造管理工具或 SDK 开发流程，项目规则和启用的审查命令仍可用。

### Requirement: 创造能力集
创造模式 SHALL 按目标提供版本匹配资料、候选校验及获准试运行能力，扩展优先；核心源码修改 SHALL 使用独立目标，缺少源码或适配版本时明确阻塞。

#### Scenario: 源码不可用
- **WHEN** 创造任务要求修改核心但未提供匹配源码
- **THEN** 返回缺失条件，不修改安装目录、不自动下载或执行未知版本。

#### Scenario: 宿主构建变化
- **WHEN** 恢复创造任务或读取开发资料时，绑定的宿主构建、SDK 或数据契约与当前宿主不一致
- **THEN** 在加载工厂或派发前拒绝，不用当前资料悄悄替换原目标版本，要求明确选择新目标会话。

#### Scenario: 开发根目录包含受保护目标
- **WHEN** 调用方选择包含原用户项目的父目录或当前宿主安装内的目录作为创造目标
- **THEN** 在创建和执行准入时拒绝，不让受控文件工具通过扩大根目录覆盖原项目或运行中的安装。

### Requirement: 模式不授予权限
系统 SHALL 在宿主操作执行层校验模式、目标及现行授权；能力发现、进入模式、读取规则或交接 MUST NOT 自动扩权。可信 shell 和扩展的实际隔离限制 SHALL 明示。

#### Scenario: 工作模式伪造激活请求
- **WHEN** 调用方绕过 UI 提交创造管理操作
- **THEN** 服务端在副作用前拒绝并记录原因。

#### Scenario: 嵌套调用与已知资料 ID
- **WHEN** 工作模式的扩展尝试嵌套调用创造工具、请求重载或读取已知 SDK 资料 ID
- **THEN** 宿主在工具意图和执行前拒绝并记录模式原因，不能通过命令包装绕过。

#### Scenario: 模式声明与工作流继续
- **WHEN** 工作模式请求仅适用于创造模式的 SDK 工具、命令或工作流，或尝试继续绑定创造模式的工作流
- **THEN** 能力目录不提供该声明，实际执行拒绝，持久工作流的模式不能被调用参数改写。

#### Scenario: 创造目录越界
- **WHEN** 创造工具尝试写入未经授权的用户项目或用户级配置
- **THEN** 受控写入口拒绝，不因 create 模式放行；任意可信代码的隔离能力不得虚假宣称。
