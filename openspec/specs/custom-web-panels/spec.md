# custom-web-panels Specification

## Purpose

让用户通过对话构建定制面板、工具结果展示和主题，在获得更丰富交互的同时保持宿主权限与页面隔离，并确保插件缺失后原会话仍可阅读和导出。

## Requirements

### Requirement: 面板与主题贡献

系统 SHALL 支持版本化自定义 Web 面板、工具结果 renderer 和受约束主题 token，通过 SDK 类型、构建及预览后随能力包激活；原状态/卡片/表单保持可用。

#### Scenario: 创建审查面板
- **WHEN** 用户要求把审查结果显示为带筛选和确认按钮的面板
- **THEN** 生成的候选可预览和修复，激活后按声明插槽显示，主题修改不破坏宿主必要操作的可见性。

### Requirement: 客户端隔离与桥接

系统 SHALL 将自定义组件隔离于宿主 DOM、认证 cookie 和凭证，通过带实例/版本身份的受控桥接请求操作；消息源、授权、大小、频率与运行状态须验证。

#### Scenario: 组件尝试越权
- **WHEN** 面板试图读取宿主 cookie、伪造另一实例或直接请求未授权操作
- **THEN** 访问或消息被拒绝，宿主仍可关闭面板和取消任务，不执行越权副作用。

### Requirement: 交互与工作流关联

系统 SHALL 将面板回答关联到持久交互/工作流身份，使用幂等命令和权威状态回传；前端刷新、组件重建或多窗口重发不得重复推进。

#### Scenario: 两个窗口同时确认
- **WHEN** 同一工作流的面板在两个窗口提交不同回答
- **THEN** 只接受一个有效版本，另一窗口得到冲突并刷新权威状态。

### Requirement: 故障与历史回退

系统 SHALL 保存自定义 UI 的结构化数据、文本回退与版本信息；组件崩溃、禁用或删除后历史仍可通用查看和导出，导入或离线 HTML MUST NOT 执行包代码。

#### Scenario: 卸载后导出
- **WHEN** 用户卸载包含审查 renderer 的包后查看并导出旧会话
- **THEN** 仍能读取结果、回答及证据；导出不下载或运行原组件，缺失数据明确诊断。
