## Why

当前工作台输入区出现双重聚焦边框，导航、消息、工具与检查面板缺少统一视觉层级；文件修改虽有 patch 证据，却仍以原始文本展示，用户无法顺畅浏览项目产物。将整体界面提升与搜索、文件浏览和可读 diff 一起设计，可让“提出任务—观察执行—检查修改—打开产物”成为完整工作流。

## What Changes

- 整体重新设计工作台：保留猫咪 logo、紫色品牌与渐变字标，统一颜色、字体、间距、圆角、控件和状态；覆盖会话侧栏、顶部栏、空态、消息、工具卡、输入框、设置、导出、诊断与检查面板。
- Composer 使用单一圆角表面与整体聚焦反馈，自动增高、清晰发送/停止状态，保持中文输入法、草稿及提交保护。
- 右侧集成“文件 / 变更 / 执行详情”面板；文件树按需浏览、刷新、显示隐藏项、定位修改文件，双击或键盘操作用本机默认程序打开文件。
- edit/write 成功结果展示持久化证据生成的逐次 diff：文件名、增删统计、行号、上下文、折叠和完整查看；变更页按会话及轮次导航，不声称覆盖全部磁盘变化。
- 增加 DeepSeek 服务端搜索驱动的 `web_search` 工具，统一工具注册、提示词贡献、有界模型结果、来源展示及取消；内部 Messages 请求接入共用模型记录入口。
- 保持旧 Journal、证据入口、会话继续和导出可读；缺失历史证据明确标记，不用当前文件补造历史。

### Scope and Non-goals

对应 `spec.md` §3.2/3.3 模型与工具证据、§4.2 工具提示词、§8.1–8.3 Web 与本地服务。§5.2 讨论项目文本搜索，本次新增可配置的内置网页搜索，不替换其中的 bash + rg 基线。

不包含 bash/外部编辑器变更捕获、Git 工作区 diff/暂存/回滚、浏览器内代码编辑、文件删除移动、全盘浏览、远程机器文件打开、TUI、主题切换或框架替换。外部文件变化首版手动刷新；搜索不扩展为网页抓取或递归研究代理。本次无意引入破坏性协议变更。

## Capabilities

### New Capabilities

- `deepseek-web-search`: 可观察、可取消、有来源证据的内置网页搜索。
- `workspace-file-browser`: 当前项目文件树与本机默认程序打开。
- `file-change-presentation`: 基于 Journal 的 edit/write 逐次 diff 与会话变更导航。

### Modified Capabilities

- `web-readable-presentation`: 整体视觉体系、右侧面板和响应式交互。
- `web-task-workbench`: 输入框聚焦、尺寸与草稿交互。
- `model-call-evidence`: 区分主 Responses 调用与搜索 Messages 调用，保持统一证据入口。

## Impact

- 前端主要涉及 `src/web/App.tsx`、组件、样式、API 与展示投影；增加文件树、diff 和来源卡，不引入完整 IDE。
- 服务端涉及 `src/server/app.ts`、路径边界校验、目录读取及跨平台打开器；新增受认证保护的工作区 API。
- 核心涉及 `src/tools.ts`、`src/context.ts`、`src/provider.ts`、配置、Journal 关联及 `src/projection/session.ts`；抽取模型调用记录层，保留不同协议适配器。
- 优先复用 React 和已固定的 diff 依赖；新增依赖需确认公开接口、版本与 npm 包兼容性。参考 Deepy 位于同级 `../deepy`，dsh 位于 `reference/dsh`，均非运行时依赖。
- 验证覆盖模型请求保真、历史与导出、文件打开边界、搜索失败与取消、响应式浏览器流程和四种视口视觉复核。真实搜索及各操作系统默认程序打开需单列实测证据，不能用 mock 冒充。
