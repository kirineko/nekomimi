## Context

动机见 proposal.md。实际代码中 `Customization.tsx` 同时管理轮询、全部 action、候选预览、模型表单和资源列表，每 1500ms 刷新管理快照；`WorkflowManagement.tsx` 与 `CustomPanel.tsx` 提供嵌入管理内容。现有样式只为定制面板设置宽高、滚动和资源边距，基础 `select` 没有完整视觉定义。现有 `Brand.tsx` 和 `nekomimi.svg` 已提供可复用猫耳身份。

`test/browser/customization.spec.ts` 覆盖真实本地服务下的资源、Provider、工作流、包、面板预览与 OAuth，包含依赖页面直接显示表单和 `selectOption` 的定位。本次导航变化必须同步这些用例，不能只补静态截图。

## Goals / Non-Goals

**Goals:** 建立范围局限于定制面板的视觉与交互基础，缩短默认页面，明确操作层级，保留全部既有功能和服务端权威状态。默认采用轻量猫系二次元方向，这是基于现有品牌的设计假设。

**Non-Goals:** 不扩展后端协议，不重做聊天里的 `ExtensionInteractions`，不重绘第三方面板 iframe，不加入重型组件库或装饰资源下载；新增表单草稿不写入 localStorage。

## Decisions

### 1. 四分类外壳与明确的功能归属

保留「定制能力」名称，采用固定头部、页签导航和一个正文滚动区域，避免整个窗口中多层长滚动。桌面目标宽度 820px、最大高度 88dvh，窄屏宽度为视口减两侧 12px；小屏页签采用 2×2 排列，保证完整中文标签。所有尺寸是设计目标，以验收无溢出为准。

| 分类 | 默认内容 | 按需展开 |
| --- | --- | --- |
| 模型 | 三个用途摘要、已保存配置摘要、新增按钮 | 配置编辑、高级模型操作（旧配置迁移、跨协议分支） |
| 资源 | 扩展/技能/规则/MCP 卡片、状态、重载入口 | 来源/版本/遮蔽/诊断、扩展候选审查、用户目录写入授权；MCP 卡片关联 OAuth 状态与授权 |
| 能力包 | 候选与已安装包摘要 | 检查结果、权限与文件差异、安装、回退、导出、卸载 |
| 工作流与面板 | 工作流状态摘要、可用面板 | 启动输入、等待回答、未知结果核对、迁移与证据、显式面板预览 |

页签显示待授权/错误/待处理的数量或文字标记；顶部保留加载、全局失败、降级和待生效反馈。初次载入失败显示重试入口，不能显示成“无资源”。候选工厂预览只能由原显式授权动作触发。

备选：仅给原长表单换颜色无法改善信息负担；独立设置路由则扩大导航改造。本次保留模态容器。

### 2. 猫系视觉规则与局部样式

复用 `CatMark`，标题左侧放小型猫耳徽章，副标题用短句；背景使用近白色，卡片使用极浅紫，紫色承担主操作，樱粉仅用于小面积装饰，少量星点限定在标题区域且 `aria-hidden`。不以全屏渐变、角色立绘或大段拟人文案占据内容空间。

正文 14px、标签 12–13px、标题 20px，文字沿用 `--ink` / `--muted` 深色体系；卡片圆角 14–16px，控件圆角 10px，常用控件高度目标 40px，间距遵循 8/12/16/24px。正文对比目标至少 4.5:1，焦点和控件边界至少 3:1。每个局部任务最多一个填色主按钮，其余为描边或文字操作；危险操作保留明确文字。

新建定制面板样式模块并在现有基础样式之后载入，使用 `.customization-panel` 和专属浮层类作用域。宿主工作流及面板管理中的原生输入、select、textarea、checkbox 也统一外观，原生语义可以保留；模型选择浮层另行实现。避免修改全局 `button`。减少动态效果时移除装饰与过渡，默认仅使用短时透明度或颜色过渡。

### 3. 模型摘要、选择器与新增编辑

默认内容示意：

```text
猫耳  定制能力                         关闭
模型   资源 · 待授权 2   能力包   工作流与面板

模型搭配                              ＋ 新增配置
主对话       默认 DeepSeek · 原设置           更换
辅助调用     默认 DeepSeek · 原设置           更换
自动命名     默认 DeepSeek · 原设置           更换

已保存配置   [配置摘要卡片… / 空状态]
高级模型操作                            展开
```

更换按钮打开有命名的 listbox 浮层，选项包含配置名、Provider/模型和选中标记；每个用途一次只打开一个选择器，支持方向键、Home/End、Enter、Escape，焦点移动不提交，确认选项才调用原 `provider-select`。Provider 与模型字段复用统一选择控件；列表较长时提供本地文本过滤，零结果显示明确提示。列表不跳出模态焦点范围，窄屏限定可用宽高。对工作流声明式下拉仅统一样式，避免改写其提交语义。

新增按钮打开分类内编辑卡片。基本字段：配置名称、Provider、模型、服务地址、可选密钥；高级区：请求路径。按现有协议默认 `/responses` 或 `/chat/completions`，最终端点与路径在提交按钮上方始终显示，并明确保存即授权。无 Provider 时链接到资源分类，不自动启用。仍保留 HTML required、pattern、URL 校验及服务端校验；保存失败要有可定位错误。

编辑状态与管理快照分离：轮询不重置草稿、焦点和分类；同次打开面板切换分类保留草稿，返回时继续编辑；显式取消或关闭清除草稿及密钥，成功保存收起并清除。请求进行中禁用重复提交，关闭不解释为撤销服务端写入；重开通过读取服务端结果恢复状态。

备选：给所有控件自绘选择器会扩大键盘和动态表单维护成本，因此自定义交互聚焦模型选择；仅给模型用途换皮原生下拉则无法实现易读的配置摘要选项。

### 4. 状态与公开接口边界

`Customization` 保留统一 refresh/action 和管理快照；提取分类呈现、模型编辑及选择器组件，业务 id 与表单状态不因轮询或页签变化重新生成。服务端返回的 profile selection、revision、活动资源和收据为已提交配置的权威；本地仅保存临时 UI 状态，不乐观宣布授权或已生效。运行历史仍以 Journal 为唯一权威，摘要只是投影，不由前端构造执行证据。

保留 `/customization` 所有现有 action、revision、contentHash、scope、authorize 和工作流 commandId。网络结果未知时显示错误或待核对并刷新，不自动重复提交。分类显隐不执行管理写入、不重跑步骤；注意面板组件挂载带来的现有行为，不能因切换页签重新触发候选工厂预览。等待表单的输入与幂等标识在同次面板打开期间保持稳定。

密钥仅作为现有服务端凭证写入接口的瞬时用户输入，禁止进入快照、日志、持久化浏览器状态与回显。现有 `saveProfile` 先保存 credential 再保存 profile，二者非原子：失败后清除密钥输入并说明配置未保存；若凭证步骤已确认成功，本次草稿保留非敏感 credentialRef 以供显式重试，不能因清空密钥而丢失引用；结果未知时让用户重新输入并显式提交，不承诺回滚凭证。该限制不通过新增后端事务隐式扩展范围。

只使用现有 React、DOM 与 CSS 公开接口，不读取框架内部或添加运行依赖。授权文字放在实际授权操作旁；隐藏长说明不能隐藏本机权限和直接 Node API 行为不保证记录的事实。

### 5. 焦点、可访问性与验证

打开时记录入口并聚焦面板标题或首个页签，约束 Tab 到可见对话框，背景 inert 或等效屏蔽；页签提供 tablist/tab/tabpanel 关联和方向键导航。Escape 先关闭选择浮层，再关闭面板；恢复焦点到对应触发器或主入口。装饰无语义，按钮具有文字或可访问名称，结果使用 status，错误使用 alert，刷新不能重复播报不变信息。

浏览器验收使用本地 fixture，涵盖空数据、多资源、长名称、错误、待授权、待生效、未知结果、加载和请求失败。在 1440×900、390×844、360×800 以及桌面 200% 缩放检查模型首页、编辑器、资源和工作流截图；检查 4.5:1/3:1 对比目标、无横向溢出及减少动态效果。确认默认视图不渲染完整编辑表单，并完成选择→保存→重开闭环。已有 Provider 工具回合、历史分支、OAuth、能力包、工作流和预览隔离测试必须继续通过。

## Risks / Trade-offs

- [风格偏好尚未通过实物确认] → 使用现有猫耳品牌和克制配色，实施时提交截图，视觉微调不改变功能范围。
- [自定义选择器的键盘与浮层裁剪] → 限定复用范围，增加键盘、焦点、窄屏与长列表测试。
- [分组隐藏异常或卸载组件丢失回答状态] → 页签状态标记和统一反馈；草稿/commandId 保留在稳定生命周期，显式测试轮询和切页。
- [凭证与配置两步保存部分成功] → 如上保留已确认引用并明确失败，验证重试；不把关闭描述成撤销。
- [全局基础样式优先级干扰] → 专属作用域，检查聊天与基础设置回归。截图与跨浏览器效果本轮尚未验证，须在实施阶段完成。

## Migration Plan

不迁移配置或 Journal。先拆分外壳和状态，再接入分类与模型交互，最后局部视觉与浏览器验收；合并前运行类型检查、单元测试、浏览器测试和严格规格验证。回滚前端改动即可恢复原布局，期间已保存配置仍由现有后端读取。本 change 的完成不包含版本标签或发布。
