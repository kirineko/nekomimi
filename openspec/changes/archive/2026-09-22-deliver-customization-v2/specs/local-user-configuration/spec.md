## MODIFIED Requirements

### Requirement: 文件配置与显式凭证

系统 SHALL 从版本化配置文件加载 Provider profiles、模型选择和非敏感端点设置，从独立凭证文件加载用户显式保存且按 Provider 关联的 API key，不从环境变量或 dotenv 读取或迁移模型凭证及产品配置。无凭证时允许查看历史，提交模型任务 SHALL 返回配置引导。显式测试依赖注入不访问用户真实配置。

#### Scenario: 仅环境变量中存在凭证

- **WHEN** 凭证文件为空而环境变量包含 API key
- **THEN** 产品仍报告未配置，既不发送请求也不把该值自动写入文件。

#### Scenario: 配置损坏

- **WHEN** 配置文件无法解析或版本不受支持
- **THEN** 显示明确错误，不静默覆盖原文件，不回退环境变量或隐式执行任务。

### Requirement: 配置入口与凭证隔离

系统 SHALL 提供 Web 设置面板及 CLI 交互配置入口，支持 Provider profile、模型与服务地址配置以及 API key 保存、替换和清除；模型选择 SHALL 来自已启用 Provider 的有效目录，新增端点须经过校验及授权。读取接口仅提供是否已配置及非敏感设置，不回显已保存凭证；凭证不得写入日志、浏览器持久存储或导出。写入 SHALL 遵守已有连接授权及同源限制。

#### Scenario: 保存并重启

- **WHEN** 用户在 Web 保存有效配置并重启服务
- **THEN** CLI 与 Web 均可使用该配置；页面不显示原密钥，保存失败不得显示成功或破坏旧配置。

#### Scenario: 运行中替换或清除凭证

- **WHEN** 用户在任务运行时更新配置
- **THEN** 已接受运行沿用捕获的配置，新任务使用新配置；清除后依赖该凭证的新模型任务被拒绝，旧凭证仍从该运行产生的证据中排除。

#### Scenario: 旧配置升级到多 Provider

- **WHEN** 用户首次用 V2 打开只有 V1 model/baseUrl/API key 的配置
- **THEN** 原设置映射到默认 DeepSeek profile 且保留备份，默认任务行为不变；迁移失败保留原文件，不猜测或覆盖凭证。

#### Scenario: Web 修改模型与端点

- **WHEN** 用户在 Web 设置选择已启用 Provider 的模型或修改服务地址
- **THEN** 显示可用能力和非敏感配置，验证端点授权后保存，后续运行使用新选择；页面不回显已存密钥，另一个 Provider 的凭证不被隐式复用。
