## Purpose

把用户定制的多类资源组织为可复现的能力包，使安装、更新、分享、卸载和回退具有明确来源、作用域、依赖及版本，不破坏现有项目与用户资源的优先关系。

## ADDED Requirements

### Requirement: 组合与作用域

系统 SHALL 支持包含扩展、Skills、Rules、MCP 配置、Provider、工作流和 UI 的版本化能力包；包内资源 SHALL 保留独立身份和作用域，项目覆盖用户及同层冲突规则继续生效，包内 Rules 不得自动变成所有项目的全局指导。

#### Scenario: 安装带规则的能力包
- **WHEN** 一个能力包把规则绑定到 src/ 并提供同名用户 Skill
- **THEN** 规则仅对安装时绑定的目标范围生效；项目同名 Skill 优先且覆盖关系可查看。

### Requirement: 可复现来源与依赖

系统 SHALL 支持本地目录、npm 包与 Git 来源，记录精确版本或 commit、完整性摘要及依赖锁；远端标签 SHALL 解析为固定 revision。获取和检查包 MUST NOT 隐式运行包的安装脚本或构建钩子。

#### Scenario: 浮动来源变化
- **WHEN** 相同 npm tag 或 Git branch 在后续指向不同内容
- **THEN** 既有锁定安装保持原版本，更新操作显示新 revision 与内容差异。

#### Scenario: 恶意包内容
- **WHEN** 包包含越界归档路径、外部 symlink、超限文件或隐式执行脚本
- **THEN** 安装拒绝危险内容或脚本执行，保留旧锁和活动版本，不向工作区或用户目录越界写入。

### Requirement: 事务更新与授权

系统 SHALL 在候选中下载、检查和构建，再提交匹配的资源清单与锁定版本；失败或取消不得留下半激活包。更新 SHALL 展示资源、依赖及宿主权限差异并校验新增授权。

#### Scenario: 更新中途失败
- **WHEN** 新依赖下载失败或服务在候选构建时中断
- **THEN** 重启仍使用完整旧版本，失败候选可清理或重试，不自动执行包。

### Requirement: 分享卸载与数据保留

系统 SHALL 导出可再安装的包及锁定信息，排除凭证、会话和默认私有状态；卸载 SHALL 在运行边界撤销全部注册和指导，保留独立历史与状态直至用户明确删除。

#### Scenario: 导出后在另一项目使用
- **WHEN** 用户导出审查包并在干净项目导入
- **THEN** 能够重新绑定规则作用域和凭证引用，安装结果可核验；包不含旧项目密钥且不会自动执行。
