## Purpose

定义 V1 与 V2 合并后的可交付产品门槛，使原始自定制需求有实际使用证据，并把兼容迁移、安装包、真实演练与公开发布状态清楚区分而不以规划完成代替交付。

## ADDED Requirements

### Requirement: 原始需求全覆盖

系统 SHALL 在干净安装中支持通过对话创建并实际使用命令、工具、Provider、工作流及 UI 定制，并组合 Skills、Rules 与 MCP；每类能力均须有确定性验收和可检查的运行证据。

#### Scenario: 完整审查能力包
- **WHEN** 用户要求创建审查命令、检查工具与 Skill，应用目录规则、MCP 内容、自定义模型和审查面板
- **THEN** 生成、修复、激活、实际使用、暂停恢复、更新回退、分享重装和停用均可验证，不需要修改产品源码。

### Requirement: 兼容与故障门槛

交付版本 SHALL 验证 V1 SDK、配置、状态与历史兼容及取消、崩溃、越权、未知副作用、依赖缺失和升级失败；未通过的必需场景 SHALL 阻止把 V2 标记完成。

#### Scenario: 旧项目升级
- **WHEN** 一个已有 V1 扩展、Skill、Rules、MCP 和历史的项目升级到候选版本
- **THEN** 旧能力仍能使用、历史仍可导出，配置迁移留备份；不兼容迁移有明确失败与回退说明。

### Requirement: 真实模型证据

系统交付验收 SHALL 单独记录真实模型对话生成、失败修复和实际使用结果，包含模型标识、耗时、attempt、限制及失败；模拟服务不能冒充真实调用，真实账户不成为 CI 前提。

#### Scenario: 模型生成候选失败
- **WHEN** 真实模型生成类型或注册错误并进入修复流程
- **THEN** 保留失败与修复证据，成功使用必须实际运行；若只有预置故障则明确标识，不伪造首次生成失败或统计成功率。

### Requirement: 可安装版本候选

交付 SHALL 提供一致版本的类型、SDK 文档、示例、构建产物、迁移/发布说明和 tarball，验证 Node.js 22.19.0/24.15.0 的 macOS/Linux 运行及 Windows 原生安装、扩展进程/MCP 清理和 Web 冒烟；不得用平台推测替代必需验收。

#### Scenario: 离线账户独立安装验收
- **WHEN** 在干净环境安装最终候选 tarball，使用本地模型/MCP/OAuth fixture
- **THEN** 公共 SDK、能力包、模型回合、工作流恢复和 Web 可使用，验收不用真实账户，报告记录包完整性与平台。

### Requirement: 发布状态区分

系统交付记录 SHALL 区分候选已验证与 registry 已发布；公开发布按既有标签 CI 和正式 Release 流程执行，未经真实核验不得报告已发布。

#### Scenario: 候选完成但未上传
- **WHEN** 本地 tarball 验收完成且用户尚未要求公开发版
- **THEN** 交付候选与验证记录，保持未发布状态，不自动创建标签或正式 Release。
