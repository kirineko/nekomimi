## Purpose

使 MCP 除工具外还能为定制工作流提供有来源的资源和提示模板，并支持有界订阅和服务端授权，确保远端内容、身份和凭证不会模糊模型上下文与执行权限。

## ADDED Requirements

### Requirement: 资源与模板

系统 SHALL 在服务声明能力后支持资源、资源模板的分页发现和显式读取，保留 URI、MIME、内容摘要、服务器版本与原始响应；资源链接不自动读取，单次/累计内容与分页必须有界。

#### Scenario: 显式读取远端资源
- **WHEN** 用户或已授权工作流选择一个 MCP 资源模板并提供参数
- **THEN** 仅按服务器能力读取目标，保存原始内容和来源，缺失/过大/不支持内容明确报告。

### Requirement: 提示模板调用

系统 SHALL 支持 MCP prompts 的分页目录、参数校验和显式获取，保存模板、参数及返回消息角色；注入模型上下文时 SHALL 标明来源和实际适用级别，远端提示不能提升宿主权限。

#### Scenario: 远端提示请求越权
- **WHEN** 获取的 prompt 包含伪装系统权限的内容
- **THEN** 原始角色和内容保留，应用按既定上下文策略呈现，不因此允许额外文件、网络或工具操作。

### Requirement: 订阅与固定快照

系统 SHALL 在服务器支持时提供资源订阅、退订、断线诊断及有界通知合并；通知仅将资源标为待刷新，不能偷换已发请求或活动步骤的内容。

#### Scenario: 资源连续变更
- **WHEN** 订阅资源在模型请求期间多次更新或连接中断
- **THEN** 当前请求仍指向原内容；下一显式读取取得新版本，诊断显示断线，重连不重发原工具调用。

### Requirement: OAuth 生命周期

系统 SHALL 为支持的 HTTP MCP OAuth 流程提供服务端授权、PKCE、状态绑定、凭证持久化、刷新、断开及重新授权；授权资源/issuer/端点 SHALL 经验证，不支持流程明确报错且不回退明文凭证。

#### Scenario: 刷新与重启
- **WHEN** 已授权连接在服务重启后令牌过期
- **THEN** 宿主使用持久凭证按协议刷新或请求重新授权，令牌不进入浏览器业务数据或 Journal。

#### Scenario: 恶意回调或发现
- **WHEN** 授权回调状态不匹配，或发现信息把凭证导向不可信目标
- **THEN** 系统拒绝回调或目标，不转发凭证，不把连接标为已授权。
