## Context

动机与范围见 `proposal.md`。本变更涉及滚动状态、异步布局和渲染性能，需要设计文档统一处理其交互。

已检查的代码事实：

- `App.tsx` 在多个 layout effect 及 `ResizeObserver` 回调中写入 `scrollTop`；历史锚点仅在已处于历史模式的滚动事件中更新，进入模式前没有同步捕获，也没有明确的会话失效标记。
- `onScroll` 将距底部小于 48px 判为跟随，`useSession.reachBottom` 随后退出历史模式，触发滚到底；现有用户意图只通过输入后的 600ms 时间窗判断。
- `.history-return` 是纵向 flex 布局中动态插入的实体，占用高度；显隐会改变 `.conversation` 可用高度。
- 历史滚动每次查询全部行并逐个读取几何位置；`Timeline` 使用 Context 和 memo，但内联 `onContinue` 与流式 `liveRows` 更新可能扩大重渲染。180 行窗口限制并不等于 DOM 节点数限制。
- 现有测试验证跟随、分页及阅读位置的最终结果，未记录连续往返过程中的每帧位置。

以上是静态证据，不是浏览器性能结论。用户已确认上下翻动会跳；具体触发比例、浏览器惯性表现及帧耗时尚待基线复现。

## Goals / Non-Goals

**Goals:**

- 一个滚动协调入口决定是否写入位置，区分用户移动、内容高度变化和显式导航。
- 保持现有 `useSession` 的有界窗口、请求代次与失败恢复语义，滚动状态不成为第二份会话历史。
- 通过位置轨迹和可见记录偏移验证稳定性，并把性能采样与功能断言分开。

**Non-Goals:**

- 不改变 Journal、快照/SSE 数据格式，不持久化阅读锚点，不回放执行副作用。
- 不将所有滚动改成 smooth，不新增滚动库或虚拟列表，不承诺跨设备固定 FPS。

## Decisions

### 1. 统一滚动写入与模式转换

将 `App.tsx` 分散的滚动逻辑收敛到专用 hook 或同等职责明确的协调模块；`useSession` 继续负责历史窗口及待查看状态，通过明确的 browse / reachBottom / latest 事件与其协作，不新增独立且可分叉的历史模式布尔值。

滚动写入限定为：初次选中会话定位最新、显式返回最新成功、仍处于跟随模式时内容增长、历史模式下真实布局变化或分页的必要补偿。模式切换本身不恢复旧位置。位置差在舍入容差内不写入，记录程序写入的目标及代次，避免自身事件触发新一轮模式转换。

手动离开底部时立即取消跟随并建立当前锚点；只在最新窗口距真实底部不超过 2 CSS px 时恢复跟随，废除 48px 提前吸附。程序补偿不能被当作手动到达底部。显式返回最新复用现有请求去重和代次检查，成功后一次定位，失败保留浏览位置；等待期间再次手动浏览应使旧滚动意图失效，不让迟到成功抢占视口。

不采用延长固定 600ms 意图窗的方案：长拖动和触控惯性可能超过任意固定窗口。跟踪输入类型、手势生命周期和实际位置变化，滚动停止信号及兼容性回退只用于收尾；上翻时退出跟随不等待停稳。覆盖滚轮、触摸移动、滚动条拖动及键盘，忽略横向滚动和嵌套滚动区未导致会话移动的输入。

### 2. 阅读锚点按当前交互和导航代次维护

锚点包含会话标识、导航代次、稳定行 ID 与相对视口偏移。进入历史模式前捕获；手动滚动后刷新；会话切换、卸载或成功返回最新时清理，并取消旧测量任务。分页触发前同步刷新位置缓存，避免观察器尚未投递时使用过期几何信息；分页前保留当前锚点，响应到达时若用户已继续浏览，使用最新有效锚点而非发请求时的过期位置。

观察器在容器生命周期内保持稳定，收到高度变化时先区分用户位移与内容布局位移，仅读取最新有效锚点并补偿必要差值。不因每次 `rows` 引用变化重建观察器并无条件恢复。可见锚点被裁剪时优先使用仍保留的可见邻接记录；内容变短导致浏览器提前限制 scrollTop 时使用限制前的位置寻找仍保留的可见锚点；不存在有效记录时保留并限制当前位置到合法范围，不恢复其他会话或旧窗口锚点。

由应用负责会话容器内的锚点补偿，并对该容器禁用原生 `overflow-anchor`，避免两套补偿叠加；禁用范围不扩散到代码或其他面板滚动区。必须验证分页、延迟 diff/扩展面板加载与手势交错时的可见记录偏移，不简单在用户滚动时丢弃所有布局补偿。

### 3. 返回入口使用不占布局高度的浮层

在会话区域的定位容器中、输入框上方放置返回入口，聊天视口不因显隐或错误文案改变高度。浮层外壳不拦截指针，只有按钮和必要交互区域接收输入；保留键盘焦点、当前主题和错误重试。

限制窄屏/放大后的提示宽高，确保消息控件可滚动到无遮挡位置；入口隐藏不留占位。选用浮层是为了同时满足现有“最新底部无留白”和新增“显隐不改变视口”的约束。固定预留按钮高度会违反前者，不采用。旧窗口底部的“查看较新”分页区域提供局部滚动余量，避免其按钮被浮层覆盖；余量随旧窗口分页区域存在，不随返回入口显隐变化，最新窗口不保留该区域。

### 4. 合并测量，依据实测缩小渲染范围

高频滚动处理先更新轻量引用，再按动画帧合并锚点测量；同帧布局读取集中在位置写入之前。保留有效锚点节点引用，窗口变化时更新候选集合，避免每个原始 scroll 事件都从头查询全部 DOM；进入模式所需的首次捕获不能被延迟到使用旧锚点之后。

实际实现缓存布局变化时的行节点及内容坐标，手动滚动只更新当前位置，布局变化时据此选择当前可见锚点；无需每帧重新查询行几何信息。分页前显式刷新缓存，底部判定按帧合并。会话生命周期隔离节点缓存，`useSession` 的导航代次拒绝迟到响应；新的输入同时清除旧程序写入的待确认标记，避免快速换向合并事件时漏掉手动到达底部。

先记录静态历史和流式更新下的渲染/布局耗时。若证实非变化消息被重复渲染，稳定 `onContinue` 等属性并缩小 `liveRows` Context 的通知范围；保留面板实时/回放边界。单靠 memo 或 CSS 平滑滚动不能解决程序回拉，不把它们作为主修复。未发现显著渲染开销时记录证据而不扩大优化范围。

### 5. 验证位置轨迹及性能证据

使用无需真实模型与凭证的浏览器 fixture，覆盖普通消息、长 Markdown、代码块、diff 和延迟面板；分别测试 60 行与 180 行、静态会话与持续更新。使用真实 wheel/键盘输入并按帧采集位置；触控惯性和滚动条拖动在可用真实浏览器中补充人工验收，不能用直接设置 `scrollTop` 代替全部交互验证。

- 在内容稳定、无显式导航时，持续同方向输入不得出现超过 2 CSS px 的反向位置变化；上下换向轨迹与输入一致，无回到旧锚点或未到底先吸附。
- 返回入口显隐及提示变化前后，视口高度差不超过 1 CSS px；静止阅读时可见锚点偏移差不超过 2 CSS px。
- 对布局补偿使用可见行相对位置断言，而不是要求 `scrollTop` 不变；分页裁剪和显式返回最新单独断言。
- 固定同一机器、浏览器、视口和 fixture 比较修改前后帧间隔 p95、超过 50ms 的主线程长任务及脚本/布局耗时；记录环境与采样时长。功能位置断言作为自动门禁，绝对 FPS 不作为跨机器 CI 门禁。
- 若仍可见跳动或性能明显回退，定位后再完成任务；浏览器能力不足时明确记录未验证项，不将代码审查作为实测通过。

## Risks / Trade-offs

- [手动输入与异步布局在同帧交错] → 使用最新交互代次和锚点，只补偿内容位移，并增加受控延迟 fixture。
- [禁用原生锚定后遗漏补偿场景] → 覆盖 Markdown、diff、扩展面板、分页和容器尺寸变化，确认后再交付。
- [浮层局部遮挡或拦截内容] → 有界尺寸、透明区域穿透及窄屏/缩放交互验收。
- [2px 边界在缩放时误判] → 按 CSS 像素测试舍入；任何调整仍限于舍入容差，不能回到数十像素吸附。
- [帧统计受环境噪声影响] → 同机前后对照，保留轨迹和采样条件，不用单次 FPS 宣称解决。

## Migration Plan

无需数据迁移。实现后运行类型检查、相关单元及浏览器测试、全量 OpenSpec 严格验证，并记录真实浏览器结果；本变更不自行触发发版。回滚前端滚动及布局改动即可，不修改已记录 Journal、快照或会话内容。

## 自然滚动交互修订

新消息到达时直接合并最新窗口的行，浏览模式只控制位置跟随，不再冻结最新内容。达到 180 行上限时保留当前阅读侧的窗口，用 after 游标承接剩余内容；手动向下到底调用 newer，逐页接续并保持可见锚点，不直接跳过中间记录。回到底部后恢复跟随。“返回最新”保留为可选快捷操作，不显示“有新消息”。历史浏览中的扩展行继续遵循回放交互边界，不因追加内容自动执行历史副作用。
