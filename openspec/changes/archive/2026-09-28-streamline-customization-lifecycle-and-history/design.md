## Context

动机见 proposal.md。现有 Customization 将 result 和最近三条 receipts 放在分类外；资源 enabled 不能表达新增能力尚未获准。Themes.catalog 过滤未获 themes 权限的资源，resource_list 又读取本轮 activation，无法解释新文件与当前宿主的差异。SDK 目录未标识运行中的构建，导致用户会话中混用了全局旧 CLI 与开发宿主。

useSession.older 将前页拼接后 slice(0,180)，丢弃新端；Timeline 把返回最新与 hasOlder 绑定；App 仅在 cursor.seq 改变时执行跟随滚动。并发 older 没有互斥、去重或独立窗口请求序列。

Candidates.snapshotFiles 将每个文件按 UTF-8 读取，prepare 又写为文本；对示例 WOFF/PNG 的只读字节往返检查均不一致。普通扩展的二进制扫描已存在，需与候选路径整合，不能以普通目录测试替代候选验收。主题颜色目前仅接受六位十六进制且强制对比度，文档未覆盖该阻断。

本设计跨服务、持久化和 UI，并改变既有导航契约，因此需要独立设计。前序两项未归档 change 作为实现基线；归档时先同步基线再同步本变更，保留历史验收结果。

## Goals / Non-Goals

**Goals:** 同一资源版本可由用户和 Agent 看到一致的状态；历史浏览不依赖 DOM 无限增长；用户颜色不由平台审美校验否决；含素材的候选保持内容寻址可靠。

**Non-Goals:** 不通过暴露 HTTP 令牌或公开内部类补足诊断，不取消权限确认，不用文件路径推断作者，不对私人会话做修改或作为测试夹具。

## Decisions

### 1. 用统一生命周期投影支撑目录、诊断和交付卡

引入能力目录投影，资源 ID + 贡献类型 + 局部 ID 为能力身份，资源 revision 单独保存；未执行工厂的草稿仅展示可确认的清单信息，不为了列卡片执行代码。目录保留候选、发现版本、活动版本与受阻更新，避免未授权贡献完全消失。

校验、权限、加载、应用、宿主验收是独立维度，不压成一个 success；根据阻碍派生当前主操作。静态/模拟/预览/宿主证据携带内容摘要与宿主构建标识。更新后旧证据仍可查但不为新版本背书。全局错误与资源操作失败分别呈现；反馈按 operationId、resourceId、revision 归属，成功提示可关闭，关闭不删除服务端事实。

原始执行事实仍来自 Journal；权限及活动指针来自对应权威存储；主题选择来自配置 CAS。新增生命周期记录采用版本化持久事件，目录为可重建投影，不另建与运行事实冲突的状态源。轮询只更新投影，不增加配置 revision 或启动工厂。

### 2. 开发来源记录区分受控创建与观察到的变化

受控候选、包和资源写入记录 sessionId/runId、创建或更新、目标资源/版本与时间；来源链接不包含提示词正文或凭证。开发任务中通过普通文件工具修改的资源，可依据工具路径及前后资源摘要关联“本次运行更新”；不能确认创建行为则不标记为创建。通过 shell/外部编辑仅能观察差异时标记“发现更新，创建者未知”。

历史资源惰性补充可验证来源，不回写旧 Journal、不修改资源 ID。来源为管理元数据，不应因补充来源改变代码内容哈希。过滤分别按关联会话、项目作用域和全部可管理资源实现。删除会话后能力仍保留，只将来源链接标记为不可访问。

### 3. 把开发诊断放在当前宿主内

扩展 SDK 查询返回包版本、构建/契约指纹、实际宿主入口和运行环境标识；开发文档推荐内置工具，CLI 指令显式指向该入口并带工作区，不默认调用 PATH 的同名命令。构建指纹由发布/构建产物生成，不能只靠相同 package.json 版本识别开发构建。

提供受控只读 customization 状态查询，复用同一目录投影，区分当前运行的固定 activation 与宿主最新发现状态。返回所需/已获/缺少权限、活动版本、回执及主题选择，使用有界输出与资源过滤，不暴露凭证。查询不创建临时空 host，也不请求浏览器 API 令牌。

新增权限确认呈现差异，绑定所检查的资源 revision 和授权设置 revision；文件或授权变化时拒绝过期确认。沿用版本切换失败保留旧活动版本的机制。任务运行中的切换仍遵守原安全边界；交付卡显示排队状态，任务结束后刷新实际结果，不把 pending 当 activated。

### 4. 管理 UX 围绕用户能力，而非开发文件

顶层采用“我的定制 / 模型 / 管理”。我的定制默认展示本项目可用与待处理能力，提供本会话/当前项目/全部筛选和类型筛选；同资源贡献可分项查看、按资源统一授权，不能把停用一个贡献误说成独立权限隔离。优先复用主题预览、工作流入口和现有模型编辑组件，不复制两套状态。

管理内提供资源、能力包、权限、工作流高级操作与开发记录；未分类功能逐项映射并回归。缩小品牌头部和上下留白，卡片包含名称、类型、阶段摘要及一个主要下一步操作；路径、哈希、JSON 和校验日志折叠。异常采用分类标记加直达目标，避免全局回执流水账。面板草稿、焦点、滚动与轮询刷新隔离，保留 360px、200%、键盘和 reduced-motion 验证。

交付卡通过结构化贡献关联目录项目和 revision。历史卡只读，点击执行前重新核验，不自动加载代码。主题预览/确认应用复用当前宿主界面；完成的定义是确认该宿主选中并加载指定版本，而非仅运行了 registerTheme。

### 5. 分离历史窗口和实时水位

浏览状态包含 history/latest 模式、窗口边界、是否存在更新内容、请求 generation 与阅读锚点；SSE 水位独立推进。latest 模式有界保留末尾窗口；history 模式冻结阅读窗口，SSE 更新实时摘要及新内容标记，不把尾部片段拼成缺口列表。

沿用或兼容扩展现有 before 分页协议，支持通过稳定边界向新端取页；裁剪窗口后仍可向两个方向导航。older 串行、相同请求去重，行按稳定 ID 合并；latest 与切会话提升窗口请求 generation，迟到请求作废。页面更新前记录首个可见行与偏移，布局后恢复锚点；字体、图片、面板高度变化通过布局观察保持合理位置，避免与用户主动滚动竞争。

返回最新是独立操作，获取末页并在渲染完成后滚动，而不是等待 cursor.seq 改变。底部检测、浏览模式和新消息标记决定浮动入口可见性；到达最早处只移除加载更早按钮。失败保留窗口和锚点，提供显式重试。

### 6. 二进制候选与颜色共享契约

候选快照升级为版本化文件清单：路径、类型、字节大小、摘要及文本/二进制内容引用。摘要基于原始字节；仅文本源进入 TypeScript 检查。prepare、load、回滚、导出复用字节存储及路径/MIME/大小检查。旧纯文本快照继续按原摘要算法验证，不静默重算或迁移不可变版本；新格式标记独立版本，元数据不计入代码内容。

统一浏览器安全颜色解析器，接受明确字面值集合（#RGB/#RGBA/#RRGGBB/#RRGGBBAA、rgb/rgba、hsl/hsla、transparent），归一化至宿主及 iframe 均接受的格式。拒绝 CSS 变量、函数组合、URL、脚本和非有限数值。删除对比度拒绝，不改写用户颜色、不增加确认负担；按钮前景色可按现有语义派生，但不替换用户显式配色。保持宿主焦点和恢复路径，不要求低对比主题达到平台指定观感。

不只删 validateTheme 的阈值：theme-build、panel-build、panel-document、主题变量和类型文档须同步，否则合法透明色仍会在后续链路被拒绝。

## Risks / Trade-offs

- [来源不完整] → 区分确认创建、关联更新及未知；不承诺识别任意 shell 操作的作者。
- [权限状态与当前运行版本不同] → 同时标识发现、活动和固定运行版本，所有写操作做版本校验。
- [生命周期元数据增长] → 目录有界分页/过滤，原始事件可查，不能用全量私有历史填充响应。
- [历史连续滚动复杂] → 用固定时序、迟到请求、更新中分页、字体变化与长会话夹具验证，不靠扩大到无限 DOM。
- [旧候选迁移破坏摘要] → 双格式只读兼容，旧版本不重写，新候选使用新格式。
- [用户配色难以阅读] → 尊重选择，保留独立键盘恢复；不重新引入对比度硬门槛。

## Migration Plan

1. 补足并验证二进制清单、统一颜色和生命周期投影，再接入状态查询与来源记录。
2. 接入新增权限确认及交付卡，保持原入口兼容；逐项映射到新的管理导航。
3. 独立修复历史窗口协议与前端锚点，覆盖旧分页客户端兼容。
4. 更新任务式文档与完整示例，在安装 tarball 中验证；旧文件记录与来源元数据采用兼容读取。
5. 通过相关单元、浏览器及打包验证后再同步/归档。回退 UI 可恢复旧入口；不得删除新增原始证据或自动执行回滚后的扩展。
