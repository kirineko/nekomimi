## Why

定制能力的校验、授权、加载、应用和实际效果缺少统一状态：反馈串到所有分类，新增权限导致能力隐身，Agent 又可能调用与宿主不一致的 CLI；用户难以管理会话中创建的能力。长历史分页还会裁掉新记录并隐藏返回最新入口，候选文件快照则会破坏字体/图片，影响完整定制交付。

## What Changes

- 将校验与操作反馈绑定资源、版本及操作，成功提示仅在所属卡片显示，可关闭；全局保留服务异常和跨分类待处理摘要，历史回执折叠。
- 修复历史导航：分离浏览历史与跟随最新，保留阅读锚点，控制并发并去重；独立提供回到最新入口与新消息提示，加载到最早处也可返回。
- 增加默认“我的定制”视图，按主题、命令、面板、工作流等用户能力展示；支持本会话、当前项目、全部筛选，持久关联开发来源及生命周期，旧数据来源不明时诚实展示。
- 重整定制面板 UX：模型独立入口，资源/能力包/权限和高级开发入口集中管理，精简头部及留白；每项能力突出当前下一步操作，技术证据渐进展开，控件跟随主题。
- 取消主题配色的对比度硬门槛和自动改色，支持规范化的常用颜色字面值；保留颜色语法和资源边界校验，不开放任意 CSS 注入。
- 补齐自定义能力交付链路：同宿主 SDK/构建身份、受控只读诊断、新增权限确认、版本绑定的验证阶段、交付卡与预览/应用入口。重载不再被当作授权或主题应用成功。
- 修复候选快照的二进制素材保真，覆盖校验、激活、加载、回滚与安装包验收；重写“修改已有能力并新增权限”的端到端文档。

非目标：自动扩权、绕过本地 API 认证、重新执行历史插件、读取浏览器令牌、插件市场、任意宿主 CSS、重写已有 Journal、发版或更改 128K/64 轮设置。对应 spec.md 第 3 节证据、第 8 节 Web、第 9 节定制生态及第 12–13 节交付验证。

## Capabilities

### New Capabilities
- `customization-lifecycle`: 用户能力目录、开发来源、权限差异、版本化阶段状态与交付操作。
- `history-navigation`: 有界历史窗口、阅读锚点、并发隔离与独立返回最新。
- `theme-color-values`: 无配色审美硬门槛的颜色契约及一致规范化。

### Modified Capabilities
- `web-customization`: 默认“我的定制”、管理入口重组、主题一致控件及按资源隔离的反馈。
- `customization-development`: 同宿主开发/诊断入口、阶段与权限诊断、候选二进制完整性及全流程文档验收。

## Impact

涉及 customization 的资源/候选/授权/加载/主题/SDK/工具描述、管理 API、会话投影与历史分页、Web Customization/useSession/Timeline/App、颜色构建与 iframe 协议、extension-docs 和测试。开发来源与验证记录增加可演进元数据；客户端字段采用兼容扩展，旧候选和既有资源 ID/版本需明确兼容处理。

本变更承接尚未归档的 `unify-platform-sdk-and-runtime-ui` 与 `improve-response-recovery-and-header` 实现，保持其有效能力；明确替换旧的模型默认分类和代码中的对比度阻断。前序变更的验收记录保留历史属性，本变更不自动归档或改写它们。用户会话仅作只读调查依据，使用合成夹具建立回归。
