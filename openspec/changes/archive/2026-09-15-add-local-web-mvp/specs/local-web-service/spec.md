## Purpose

提供固定工作区的本地浏览器服务，使单用户能够管理多个会话并控制任务执行，同时保持凭证仅在服务端、文件访问受会话约束以及命令确认与实际执行之间可检查的边界。

## ADDED Requirements

### Requirement: 本地启动与会话范围

系统 SHALL 支持启动时指定一个工作区并仅监听本机回环地址，提供该服务管理的会话创建、列表和重新打开能力。

#### Scenario: 重新启动服务

- **WHEN** 用户重新启动指向相同工作区和管理目录的服务
- **THEN** 已有会话仍可打开，其他工作区会话及任意路径不能通过会话接口读取。

### Requirement: 连接和资源授权

系统 SHALL 校验本地连接凭据、Host 和浏览器写请求的同源 Origin；模型密钥不得进入客户端、事件或下载地址。附件访问 SHALL 限于已授权会话引用的证据。

#### Scenario: 跨来源与越界请求

- **WHEN** 请求使用错误凭据、非法 Host、跨站 Origin，或请求不属于当前会话的附件
- **THEN** 服务拒绝请求且不执行工具、不返回越界内容，不通过允许任意 CORS 绕过检查。

### Requirement: 提交去重与持久化确认

系统 SHALL 在确认接受提交之前持久化 commandId、负载摘要和运行关联；同一会话相同 ID 和负载不得重复执行，不同负载复用 ID SHALL 返回冲突。

#### Scenario: 确认响应丢失后重发

- **WHEN** 服务已接受任务但客户端未收到确认，随后以同一 ID 和内容再次提交
- **THEN** 返回原有任务状态且模型/工具执行次数不因重发增加。

### Requirement: 单活动任务和取消隔离

系统 SHALL 允许查看多个会话但同一服务工作区最多一个活动任务；繁忙时拒绝新增运行。取消 SHALL 指向具体运行且幂等。

#### Scenario: 旧取消与新运行

- **WHEN** 旧运行已结束，新运行已开始，此时收到旧运行的重复取消
- **THEN** 新运行不被取消；另一个并发提交明确返回 busy。

### Requirement: 缺失配置

系统 SHALL 允许无模型凭证时查看已有会话，但不得接受需要模型调用的任务。

#### Scenario: 没有 API key

- **WHEN** 用户在未配置模型凭证的服务中提交任务
- **THEN** 界面得到明确配置错误，不显示任务已被接受。
