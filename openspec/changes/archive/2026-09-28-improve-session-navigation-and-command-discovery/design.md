## Context

动机与范围见 proposal.md。当前 `SessionManager.list` 对目录 ID 排序后分页，`App` 新建时插到数组头部；投影 `updatedAt` 是最后一条 Journal 事件时间，不能直接代表用户关心的对话活动。Sidebar 仅展示标题与状态，操作菜单是原生 details；删除确认没有遮罩、Esc、焦点管理。Composer 已处理 IME 与重复提交，但没有命令目录。

`CustomizationRun.command` 已实现 `/reload`、`/skill:…`、扩展和工作流命令，扩展注册包含 description。宿主 `describe()` 有激活版本和资源，但没有统一命令目录。现有浏览器删除测试覆盖取消按钮与确认删除，未覆盖外部点击和键盘退出。

## Goals / Non-Goals

**Goals:** 从权威 Journal 派生列表元数据；从实际激活资源派生命令目录；保持 UI 提示与服务端执行同源。让两行会话列表、菜单、确认框及补全菜单具有一致的键盘和触摸行为。

**Non-Goals:** 不新增数据库或运行时依赖；不将浏览器状态作为权限或执行依据；不改变既有 Journal 格式、删除语义、命令 handler 签名和工作流参数格式。具体产品范围见 proposal.md。

## Decisions

### 1. 活动时间单独派生

保留 `updatedAt` 原语义，新增可空 `activityAt`，取有效 `session.created`、`command.accepted`、`run.started`、`run.finished` 时间最大值。`run.started` 兼容没有 Web command 记录的旧会话；不含标题生成、工具和流式中间事件。缺失值置末尾，时间相同按 ID 升序。两行元信息以该时间为准。

不直接改变 updatedAt，也不取目录 mtime，避免后台事件或文件复制导致排序变化。Journal 是唯一权威；索引或缓存均可重建。启动首次扫描可读会话元数据，后续沿用现有 reader 缓存并更新受影响条目，不加载附件正文。

### 2. 排序先于分页，版本不一致时重载

服务端先获得全体可读条目的排序键，再分页。列表响应增加 `listRevision`（排序后的 ID 与活动时间摘要）；后续 offset 请求携带该版本，不匹配返回明确的列表已变化响应。既有不传版本的调用仍可读取，但 Web 必须使用版本检查，不能仅在前端对当前页排序。

`App` 在创建、删除、任务接受/开始/终态、重连和页面重新获得焦点时刷新列表；活动时间纳入 snapshot 更新判断。刷新已加载范围时从第一页重新获取并合并同版本页面，分页失效则重试最新第一页；保留选中 ID、草稿，按 ID 去重，丢弃过期响应。标题更新只更新展示，不改变顺序。

### 3. 紧凑布局与时间信息

第一行标题与省略号，第二行时间与状态。视觉复核后采用 52px 行高、统一左右边距和第二行基线；分组使用小圆点与淡紫细线，选中行使用浅紫渐变及左侧强调线，完成/运行/取消/失败状态使用低饱和绿/紫/琥珀/玫瑰色标签。不加摘要、模型名或额外第三行。分组按本地日历日差：0 为今天、1 为昨天、2–6 为近 7 天、其余为更早；未知时间单独置末尾。相对时间按分钟刷新，跨日重新分组。时间使用语义化 time，完整时间由可聚焦、可点按的小提示提供，不仅依赖原生 title。沿用现有淡紫色设计语言并保证状态文字与焦点对比度；避免 hover 才能找到操作。

### 4. 受控菜单与删除弹窗

用一个受控 session ID 管理菜单，点外部、Esc、切换会话时关闭。复用现有定制面板的关闭/焦点约束，抽取必要的小型公共逻辑，避免替换所有弹层。确认框默认聚焦取消、锁定背景交互、循环焦点，关闭恢复触发入口，入口消失则回到新建会话入口。只在遮罩本身被点中时关闭。

删除进行中禁用关闭与重复确认并标记 aria-busy；失败使用局部错误状态，恢复关闭能力。服务端继续决定运行中是否可删除，停止运行成功不自动删除；再次确认前更新目标状态。保留成功后当前会话/其他会话的既有导航语义。

### 5. 命令发现与执行共用解析元数据

新增经过既有认证边界的只读 `GET /api/v1/commands`，返回目录 revision、ready 状态与安全条目（稳定 ID、kind、name、description、source、insertText）。从当前 activation 获取启用扩展、工作流触发器和技能；补充内置 `/reload`。同名技能使用已有资源 ID 形式消歧。

抽出无副作用的目录构建与匹配逻辑供命令执行及目录共用，保留内置命令优先级和既有错误行为；扩展与工作流交叉重名时使用限定名，限定名仍冲突则不暴露可选条目。description 无值时使用类型级简短说明，不凭空生成参数签名。工作流仍接受既有 JSON 参数，补全不构造或执行参数。

服务启动时通过现有重载队列初始化已授权资源，使首次执行前和重启后可以发现命令；初始化与只读目录请求分离。目录读取只投影已激活状态，不能调用 acquire 或触发 reload；未就绪返回明确状态。进入页面、候选首次打开、定制资源操作生效、重连/窗口重新聚焦时刷新，并在候选打开期间低频检查 revision。请求序号防止旧结果覆盖。目录失效立即撤销候选；提交仍由最新服务端解析兜底，不能承诺资源变更与用户提交之间没有竞态。

### 6. 补全与发送分开

候选使用关联 textarea 的 combobox/listbox 语义与 aria-activedescendant，DOM 焦点留在 textarea；输入首字符为 `/`、光标在首词内、非组合输入时匹配。按名称前缀优先，其次名称/说明包含匹配，稳定排序；不做模糊推荐或使用频次持久化。

方向键移动、Tab/Enter 与点击选择只替换首词，保留后面的参数；无参数时补一个空格。补全后收起并记录抑制状态，第二次 Enter 才发送。Esc/外部点击后的未变文本不立即重新弹出，编辑命令词或主动重新进入命令词可再次打开。无候选时不拦截 Tab；Shift+Enter、IME 确认、keyCode 229、组合结束保护和重复按键保护保留。下拉有最大高度，根据可用视口在输入框附近定位并滚动选中项。

## Risks / Trade-offs

- 全体元数据排序增加首次扫描成本 → 利用 reader 缓存，测试多页规模与坏目录；不读取附件，不承诺未经测量的性能指标。
- 活动频繁导致分页版本失效 → 明确刷新状态，保留选择和草稿，禁止混拼版本；只在任务边界更新时间，避免每个 token 重排。
- 命令目录与提交存在时间差 → revision 防止过期覆盖，执行端始终重新判定；失败保留草稿并刷新候选。
- 焦点和 IME 处理与既有 Enter 行为相交 → 对修改的任务输入契约单独做浏览器回归，覆盖点击、键盘、触摸与移动视口。
- 当前未实际验证新设计性能、真实软键盘与辅助技术 → apply 阶段记录实测与模拟验证的边界，不将方案当作交付证据。

## Migration Plan

先增加可重建活动投影、兼容字段与命令目录，再接入列表和输入 UI；不修改历史文件。旧客户端可继续使用 offset 读取列表，新客户端使用 listRevision。回滚代码即可回到旧 UI 与排序，不需要数据回滚。完成相关检查及严格 OpenSpec 校验后再勾选 tasks，用户要求归档时同步主规格。
