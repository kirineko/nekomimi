## Why

会话列表目前按 ID 排序后分页，新会话又被前端临时置顶，缺少稳定的最近活动顺序与时间信息；删除菜单和确认框缺少自然退出方式。用户注册的 `/moe` 等命令已经能够执行，但输入框没有发现与补全入口，必须记住命令名称。

## What Changes

- 采用用户确认的紧凑两行会话布局：标题，以及时间与状态；不增加消息摘要。按最近对话活动倒序排列，并按今天、昨天、近 7 天、更早分组。
- 明确活动时间语义、稳定排序和分页一致性；后台命名与纯查看不改变会话顺序。
- 补齐会话操作菜单及删除确认框的外部点击、Esc、焦点恢复和请求中反馈。
- 输入开头的 `/` 时提供命令候选，展示名称、描述、来源，支持筛选和键盘补全；候选覆盖启用的扩展命令、工作流触发命令、技能入口与内置命令。
- 使用真实激活资源生成命令目录，与执行端共享名称解析规则；重名使用限定名，资源重载后更新目录。
- 延续现有淡紫色与圆角风格，保证紧凑布局、窄屏和键盘可用性。

非目标：置顶、搜索、批量删除、消息摘要、重做扩展面板渲染、改变命令执行权限或自动执行命令。对应 `spec.md` §8.1 稳定产品协议、§8.2 浏览器首要功能及 §9 Skills 扩展入口。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `web-task-workbench`：增加紧凑会话导航、自然关闭的删除交互及斜杠命令发现要求；调整 Enter 规则，使候选选中优先补全而非发送。

## Impact

- 会话投影、`SessionInfo`、会话列表 API 与 `Sidebar`：新增有明确语义的活动时间及一致分页契约。
- `App` 的列表刷新与删除确认、`Composer` 的输入状态和键盘处理、对应样式。
- 定制宿主与命令解析：增加只读命令目录及共享解析元数据，不向浏览器传输 handler 或凭证。
- 增加排序/分页、命令目录单元及集成测试和浏览器交互验收；不计划引入运行时依赖，不修改既有 Journal。
