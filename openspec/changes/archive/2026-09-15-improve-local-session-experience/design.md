## Context

当前 `cli.ts` 默认写 `~/.deepy-harness/sessions`，Web `server/sessions.ts` 写工作区 `.harness/sessions`；API key 来自 CLI 环境变量并传给运行时。Web 创建时使用时间戳标题，尚无删除或设置接口。`Composer` 仅响应 Ctrl/Cmd+Enter；`export.ts` 将事件和附件直接转成折叠 JSON。

本地参考依据：pi `packages/coding-agent/src/config.ts` 的 auth/settings 分离及 `core/export-html/template.js` 的消息与工具结果排版；dsh `packages/util/home-paths/src/index.ts` 的单根目录、`credentials-local/README.zh.md` 的保存/清除/只返回配置状态，以及 `session-title-first-prompt-llm`、`session-title-llm` 的首消息命名和辅助请求记录。参考实现允许环境变量覆盖，本项目按用户要求不采用该行为。此为已检查的本地参考快照，不宣称上游最新版本。

## Goals / Non-Goals

Goals：配置与日志统一，生命周期可恢复，新增 UI 和导出通过共享展示语义保持一致，业务代码在 src 中按配置、存储、生命周期和渲染划分。

Non-Goals：不引入第二份任务权威历史，不让标题生成影响工具上下文，不让浏览器选择任意服务端路径；本轮不增加回收站产品界面、持续改名或账户系统。

## Decisions

### 0. Nekomimi 命名与兼容边界

产品名 Nekomimi，仓库目标名、npm 目标包名和 bin 为 `nekomimi`，默认用户目录 `~/.nekomimi/`。实现时更新 package.json/lockfile、CLI 帮助、Web、HTML、当前 README/AGENTS/项目上下文、脚本和测试；显式保留迁移使用的旧 `.deepy-harness` 与 `.harness` 路径。首次正式发布前核实 npm 名称可用性，包名被占用时另行决定命名空间，bin 不必随包名改变。本轮不发布、不操作远端仓库或移动当前工作目录。

不重写历史 Journal、bundle 格式标识、来源标识、已归档提案与研究证据；这些不是展示品牌。旧 bundle 保持可导入，品牌变更不能破坏 hash 或来源关联。旧 `harness` 命令不再作为默认安装入口，README 提供命令更名提示。后续代码中的内部标识按兼容需求分类替换，不进行全仓盲替换。

### 1. 用户根目录和配置入口

默认 `homedir()/.nekomimi`。可用显式 `--home` 参数/库选项指定隔离目录用于测试和便携运行，不增加环境变量覆盖。现有显式非敏感 CLI 参数保留，优先级为命令行 > 文件 > 产品默认值。操作系统 HOME/PATH 等基础环境及 shell 子进程环境不属于产品配置，不要求清空。

```text
~/.nekomimi/
  settings.json
  auth.json
  workspaces/
    <canonical-path-hash>/
      workspace.json
      sessions/<session-id>/
        journal.jsonl
        artifacts/
      deleting/<session-id>/
      migrations.json
```

实际 Journal 文件名沿用现有格式，不为目录搬迁更改事件或 hash。工作区 ID 来自规范化真实路径的完整摘要，workspace.json 保留映射以校验碰撞和范围。文件工具继续使用原始工作区。目录搬迁不自动猜测项目新地址。

配置使用版本与修订号；非敏感设置与凭证各自独立保存动作，原子写入并锁定，修订不匹配拒绝覆盖，避免两个设置窗口静默丢失修改。POSIX 目录 0700、凭证 0600；不将文件权限描述为对同用户 shell 的隔离。配置解析失败保留原文并明确报错。

Web 设置入口位于侧栏底部，展示模型、base URL、API key 配置状态；密码输入仅用于新值，保存后清空，不用星号占位值覆盖真实 key。不增加自动测试连接；本次配置保存不消耗模型请求。CLI 增加 `nekomimi config` 交互式入口，密钥不通过命令行参数或日志回显。读取设置返回 revision/configured，不返回凭证。

接受每个运行时冻结配置快照，沿用现有运行时依赖注入入口；API key 只在服务端解析、传入统一 provider 和脱敏器。修改配置后下一运行生效。用户自选 base URL 必须是合法无内嵌凭证 URL，远程只允许 HTTPS，本机测试允许 HTTP；更新与 key 保存分开，服务地址明确展示。

### 2. 共享会话存储与迁移

提取 `src/storage/` 路径、会话目录与迁移模块，让 CLI/Web 使用同一发现及写锁规则；保留同工作区服务租约和会话 Journal 锁。旧 `~/.deepy-harness/sessions` 按 session.created.workspace 分类，不把未知工作区会话强行放入当前分区。

Web 设置提供迁移预览与显式执行，CLI 提供同等迁移入口。仅允许当前工作区旧根及已知用户旧根，不暴露任意文件读取 API。复制到临时目标、校验日志与所有引用附件后原子发布，写迁移来源/摘要记录；不重新生成事件 ID。尾行异常或损坏会话报告并跳过，保留旧版诊断入口，不静默修复。活动源必须获得锁后才可复制；无法获得则跳过并说明。

迁移保留原件，重试跳过已完成副本，内容冲突不覆盖。删除已迁移的会话后迁移记录继续保留，避免重复迁移无意恢复已删除数据。旧版回滚只读取保留原件，新版本新增会话需通过现有 bundle 导出转移，不自动反向同步。

### 3. 自动命名与 Journal 语义

新会话先显示“新会话”，第一条接受消息生成去换行、限长的本地临时标题并追加标题事件。首轮成功后安排一次辅助命名作业，仅输入首条用户消息，不传工具执行结果；默认目标 16 个中文字符或 8 个英文词，输入上限 4KiB、输出 64 tokens、超时 10 秒。辅助 Responses 请求设置 `reasoning.effort=none`，让输出预算用于标题；中英混排分别限制中文字符数和空白分词数，整体不超过 100 字符。输出去除包裹引号和多余行，校验非空及长度；非法结果保留临时标题。

复用现有 provider 的记录入口，不另写 fetch。辅助请求标记 `purpose=session-title`，保留 context/request/attempt/response 链，但其输出不追加为任务 context.add，也不更新任务终态。标题事件是名称权威来源，列表投影读取最新事件；旧 web.session 标题继续作为兼容回退。界面将辅助调用标为“会话命名”，避免伪装成用户任务或累计混淆用量。

命名由会话写入调度管理；持久化开始标记后才 dispatch，重启不自动重跑。与任务共用单活动执行约束：用户继续优先，取消命名、等待结束及日志刷盘再交接写锁。命名失败不改变已完成任务，删除必须等所有写入停止。不采用首消息截断作为唯一正式标题，也不采用随每轮重新命名，以减少请求和名称抖动。

### 4. 删除协议

侧栏会话菜单显示删除，确认文案标明“删除会话记录与附件，保留工作区文件”。活动任务或命名时给出停止入口，不将删除请求解释为取消授权。API 拒绝 busy，待停止后用户可确认删除。

删除与提交、命名、导出在相同生命周期门禁下串行化。拿到会话锁后先移入同文件系统 deleting 区域，使列表与读取立刻失效，再清理目录；目标不跟随外部 symlink。失败返回明确清理未完成，重启仅继续清理已隔离目录，不恢复列表。管理记录只描述删除/迁移状态，不能替代 Journal 重建运行历史。

向会话订阅者发送 deleted 控制状态并关闭流；客户端清除选中状态、查询缓存并刷新侧栏。重新打开旧 URL 返回不存在，不自动创建同 ID，会话提交只能作用于已存在会话。并发下载需持有读取租约直到流完成再允许删除，避免返回半个下载；重复删除幂等。

### 5. 输入和离线展示

Enter 事件统一走现有 submit 流程；Shift+Enter 换行，保留 Ctrl/Cmd+Enter 的兼容发送。显式处理 compositionstart/end、isComposing 及浏览器选词事件差异，组合结束的同一次 Enter 不发送，避免中文误提交。保持空白、busy、pending 去重和错误时草稿保留。

提取 `src/presentation/` 的纯内容分型/工具结果配对规则，供 Web 和离线导出使用；不能让 Node 核心导入 Web 状态或以展示文本构造模型历史。`src/export/` 独立组织阅读模型、HTML 模板和样式，`export.ts` 保留公开入口及 bundle 兼容。

离线 HTML 使用安全服务端渲染的 Markdown、原生 details 和锚点导航，无需 JavaScript、外部字体或 CDN；优先验证现有 react-markdown/remark-gfm 的静态渲染并固定依赖。页面显示标题、轮次目录、任务和回答，工具按 call ID 配对并显示结果/diff；长输出有明确展开入口，原始事件及附件在证据区关联。脱敏先于任何可见摘要/HTML 生成，HTML 仍非可继续会话。保留既有 CSP 和损坏/未完成证据提示。

## Risks / Trade-offs

- [用户目录下明文凭证可被同用户工具进程读取] → 限制权限及回显，继续跨块脱敏；不宣称其等价于密钥链隔离。
- [统一目录造成锁或工作区混淆] → CLI/Web 共用路径、租约和工作区校验，测试符号链接、重复路径与并发操作。
- [标题辅助请求与任务争用 Journal] → 所有写入串行化，用户任务优先；辅助用途隔离，取消与故障独立记账。
- [迁移或删除中断] → 临时复制校验后发布、删除隔离后清理，明确操作结果，不破坏原件或复活删除会话。
- [静态 Markdown 与 Web 展示漂移] → 共享纯展示规则，测试相同记录的消息/工具顺序、XSS、脱敏和 diff；截图只保存到忽略目录。
- [Windows 权限及目录原子性未实机验证] → 按平台报告实际覆盖，验证失败明确拒绝，不能以 POSIX mode 声称 Windows ACL 已收紧。

## Migration Plan

1. 发布统一存储和配置入口，首次启动缺凭证时引导设置，不读取旧环境变量。
2. 用户在设置中预览并执行旧会话复制迁移，校验通过的会话进入新列表；未迁移数据保持原位。
3. 验证新会话执行、标题生成、继续、删除和离线导出；同步 README、脚本和安装包验收入口。
4. 回滚使用保留的源会话和旧配置方式；不清理用户旧目录、不覆盖 `.deepy`，不将配置文件纳入 Git。

### 交付前 UI 调整

按用户反馈，Web 设置只保留模型与凭证卡片，移除旧会话迁移入口。已有 CLI 迁移工具保留用于显式维护。侧栏采用省略号操作菜单和删除确认；品牌与回复署名共享猫耳图形、小写 nekomimi 字标与淡紫配色。

当前版本设置面板仅支持 API key 保存、替换与清除；模型名称和服务地址的用户编辑入口按最新反馈推迟到后续版本。底层配置存储保留用于内部运行配置。

### Review 修复约束

HTML 在输出内容处脱敏，不对展示对象序列化后替换字段名；附件引用保持稳定。迁移读取登记、复制发布和保存登记持有工作区根目录事务锁；CLI 迁移额外持有与 Web 服务相同的 sessions 租约，避免绕过生命周期门禁。
