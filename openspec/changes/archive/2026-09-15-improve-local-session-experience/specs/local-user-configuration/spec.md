## Purpose

为同一操作系统用户提供统一、可持久化的本地配置与会话存储，使 CLI 和浏览器共享设置及工作区内历史，在不依赖环境变量提供凭证的前提下完成首次配置、后续修改和旧数据迁移。

## ADDED Requirements

### Requirement: 统一用户数据目录

系统 SHALL 默认在用户目录的 `.nekomimi` 下保存产品配置、凭证及按工作区隔离的 JSONL 和附件，CLI 与 Web SHALL 使用一致的定位规则；新会话不得默认写入项目目录。工作区路径仍决定工具执行范围，不因日志搬迁扩大。

#### Scenario: CLI 与 Web 共享历史

- **WHEN** CLI 在某工作区创建会话后，用户以 Web 打开同一工作区
- **THEN** 会话可被枚举与继续，其他工作区历史不混入当前列表；规范化后相同的工作区路径使用相同数据分区。

### Requirement: 文件配置与显式凭证

系统 SHALL 从版本化配置文件加载模型设置，从独立凭证文件加载用户显式保存的 API key，不从环境变量或 dotenv 读取或迁移模型凭证及产品配置。无凭证时允许查看历史，提交模型任务 SHALL 返回配置引导。显式测试依赖注入不访问用户真实配置。

#### Scenario: 仅环境变量中存在凭证

- **WHEN** 凭证文件为空而环境变量包含 API key
- **THEN** 产品仍报告未配置，既不发送请求也不把该值自动写入文件。

#### Scenario: 配置损坏

- **WHEN** 配置文件无法解析或版本不受支持
- **THEN** 显示明确错误，不静默覆盖原文件，不回退环境变量或隐式执行任务。

### Requirement: 配置入口与凭证隔离

系统 SHALL 提供 Web 设置面板及 CLI 交互配置入口，支持 API key 保存、替换和清除。当前 Web 设置面板 SHALL 不提供模型名称与服务地址的编辑入口，该界面能力推迟至后续版本。读取接口仅提供是否已配置及非敏感设置，不回显已保存凭证；凭证不得写入日志、浏览器持久存储或导出。写入 SHALL 遵守已有连接授权及同源限制。

#### Scenario: 保存并重启

- **WHEN** 用户在 Web 保存有效配置并重启服务
- **THEN** CLI 与 Web 均可使用该配置；页面不显示原密钥，保存失败不得显示成功或破坏旧配置。

#### Scenario: 运行中替换或清除凭证

- **WHEN** 用户在任务运行时更新配置
- **THEN** 已接受运行沿用捕获的配置，新任务使用新配置；清除后新模型任务被拒绝，旧凭证仍从该运行产生的证据中排除。

### Requirement: 显式迁移旧会话

系统 SHALL 支持显式迁移当前工作区 `.harness/sessions` 和旧用户目录 `~/.deepy-harness/sessions` 中可验证且匹配工作区的会话；迁移保留原件及 Journal 字节与引用附件，禁止覆盖冲突、跟随越界符号链接或迁移活动会话。迁移 SHALL 不调用模型或工具。

#### Scenario: 迁移重试与冲突

- **WHEN** 用户重复迁移相同源，或目标已有相同 ID 但内容不同的会话
- **THEN** 相同已完成副本跳过，不同内容明确报冲突；部分失败可重试，源会话保持不变。

#### Scenario: 损坏与未完成记录

- **WHEN** 源会话有损坏附件、尾部异常或未完成操作
- **THEN** 损坏会话报告问题且不发布为成功副本；可验证的未完成历史保留 interrupted/unknown 语义，不自动重跑。
