## MODIFIED Requirements

### Requirement: 匿名公开网络边界
系统 SHALL 仅接受无内嵌凭证的 HTTP(S) URL；直连时拒绝非公开地址及混合公开/私有 DNS 结果，连接目标 SHALL 与校验地址一致。采用用户已配置的可信代理时 SHALL 由代理解析域名，客户端仍拒绝非公开 IP 字面量、localhost 和本地域名；代理最终 DNS 与访问控制由可信代理负责。每次重定向 SHALL 重新判断路由与边界，最多自动跟随五次同源跳转；跨源跳转返回目标供显式新调用。目标请求 MUST 不附带模型密钥、浏览器 Cookie 或目标认证，代理认证仅发送给代理且不进入 Journal、模型结果或客户端。

#### Scenario: 目标与重定向
- **WHEN** URL 指向回环、内网、特殊用途地址，直连 DNS 返回混合公开和私有地址，或重定向跨源
- **THEN** 禁止向被拒绝目标发送请求；跨源结果提供目标地址及阻止原因。

#### Scenario: 代理与 Fake-IP
- **WHEN** 用户配置了可信 HTTP(S) 代理且请求公开域名
- **THEN** 不因本机 Fake-IP 解析结果拒绝请求，代理负责域名解析；不放行直接输入的保留网段地址。

## ADDED Requirements

### Requirement: 自动代理路由
系统 SHALL 优先遵循 web_fetch 专用的显式直连或代理覆盖，然后使用环境代理，再检测 macOS/Windows 已启用的系统静态 HTTP(S) 代理；无配置保持直连，Linux 使用环境配置；仅开启自动发现但无具体代理或 PAC 配置不视为已启用代理。系统 SHALL 支持 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY 的 HTTP(S) 地址及 NO_PROXY；大小写变量同时存在时小写优先。命中绕过列表 SHALL 使用完整直连校验。代理设置不改变模型工具参数或其他模型/API 请求。

#### Scenario: 无代理与覆盖
- **WHEN** 没有启用代理，或用户显式选择直连
- **THEN** 使用原有直连路径，显式直连忽略环境和系统代理。

#### Scenario: 启用与绕过
- **WHEN** 存在有效环境代理或启用的系统代理，且 URL 未被绕过
- **THEN** 通过该代理请求；环境配置优先且不被系统设置覆盖，NO_PROXY 域名、后缀、端口和通配全绕过按文档匹配。

#### Scenario: 不支持或不可用
- **WHEN** 用户配置的代理不可连接、类型不支持，或仅配置 PAC/SOCKS
- **THEN** 返回准确错误并停止，不静默直连、不执行 PAC 或尝试其他代理；未取得响应不伪造 HTTP 状态。

### Requirement: 通用 HTTP 兼容与验证页
系统 SHALL 使用统一浏览器式请求头，保持已有压缩、编码和摘要回退行为，不针对单一网站改写 URL 或调用专用接口。响应明确带网站验证标志时 SHALL 分类为需要浏览器验证，即使 HTTP 为成功也不把验证页当正文；普通 403 SHALL 保留为 HTTP 拒绝，不猜测为验证码。

#### Scenario: 验证与普通拒绝
- **WHEN** 响应包含 cf-mitigated: challenge 或只是普通 HTTP 403
- **THEN** 前者提示网站需要浏览器验证，后者保留 HTTP 403；两者均保存可安全脱敏的响应证据，不自动重试。

### Requirement: 路由证据与取消
系统 SHALL 在 Journal 记录每跳的直连/代理模式与配置来源，不保存代理 URL、账号或认证材料；失败记录可理解的分类。DNS、系统检测、代理连接及读取 SHALL 受统一超时和取消控制，回放不重新检测代理或联网。

#### Scenario: 取消与重放
- **WHEN** 检测代理或代理请求时取消，随后导出并重开会话
- **THEN** 不继续请求，已有路由和终态可回放且不再执行网络操作。
