## Context

动机见 proposal.md。当前 src/context.ts 将身份、工具 snippet、去重 guidance 和外部指令拼接；src/tools.ts 和 CustomRun.add 默认 snippet=description。runtime 在 custom.initialize 后过滤工具，但保留此前生成的 resources 指令。技能读取既返回正文又加入系统指令；压缩继承主提示但删除 schemas，命名单独维护字符串。extension-docs/README.md 已有目标导航，本次扩展和连通已有入口，不另造平行 SDK。

参考依据：
- reference/dsh/packages/core/system-prompt/src/index.ts：有序章节、动态上下文、作用域和确定性工具排序。
- reference/dsh/packages/context/agent-instructions/src/render.ts：预算、正文边界、指令变更来源。
- reference/pi/packages/coding-agent/src/core/system-prompt.ts：按实际工具贡献指导和文档导航。
- reference/pi/packages/coding-agent/src/core/tools/read.ts、edit.ts：摘要/描述/参数分工。

仅借鉴本地实现思想，不导入 reference 代码或内部 API。项目公开依赖仍固定 pi-agent-core/pi-ai 0.85.1。

## Goals / Non-Goals

**Goals:** 最终可用能力与指导一致；减少重复但保留必要契约；保持规则作用域及请求来源；让自定制形成可验证的效果交付；用可复现证据评价改变。

**Non-Goals:** 不引入完整提示词覆盖 UI、不搬入 dsh 注册宿主、不增加工具种类、不改变权限与回放规则、不调整压缩触发阈值及 64 轮/128K 输出配置。

## Decisions

### 1. 在最终能力确定后组装

在内部提示贡献模型增加稳定 id、章节、版本、来源集合、作用域和所需工具；纯组装器输入最终工具集合、有效指令、运行环境及任务用途。先进行启停与调用方限制，再决定资源入口和指导，刷新路径使用同一规则。只过滤宿主管理的贡献，不靠字符串搜索删除历史中的工具名称。

同章节按明确顺序和 code-unit id 排序，工具按规范名排序，规范化后去重并保留共享指导的所有有效来源。任意插件加载顺序不能改变最终结果。拒绝重复身份冲突并给出诊断，不静默覆盖不同来源。相比只修补 resources 文案，这能覆盖后续新增指导。

### 2. 明确层次与动态数据的角色

固定层包含身份、精简工作原则、指令/数据边界和启用工具的策略；指令层保留已授权项目/目录规则和按需 Skill，并显式标注来源与作用域。环境事实以带来源、版本和数据边界的上下文节点进入请求；无变化不追加，取消请求不提交迟到更新。授权状态以执行层为准，提示不提升权限。

重要兼容决策：本次不改变 Skill 正文进入有效指令的现有语义。spec.md 7.2 提到 Skill 正文仅进入历史，是研究建议；当前实现与已交付来源契约需要保留加载/撤销行为。将重复工具返回改为加载回执及正文证据引用，正文只在有效指令层出现一次，旧历史保持原样。更新相关研究说明以区分现行设计。规则不得为预算静默截断；可枚举目录采用稳定预算并返回省略数量及可用 resource_list 入口，缺失该入口时不得宣传不存在的查询路径。

不采用 dsh 的 in-history system 覆盖技巧。内置 Responses 和自定义 Provider 保持既有角色协议，所有投影变化写入 Journal 来源链，ContextView 与 WireRequest 保存实际输入。

### 3. 工具三层契约与结果恢复

核心工具显式填写简短 snippet；description 描述用途、选择条件、前置条件、结果和失败恢复；参数 description 解释单位及相互关系。运行配置中的默认值/上限与描述共享来源，避免手写常数漂移。

覆盖 read/edit/write/bash 或 powershell/web_search，以及 resource、SDK、candidate、package、reload、status、validate 和 MCP 内容管理工具。逐项建立动作契约表。保留现有工具名和合法参数；多 action 工具使用兼容 Provider 的对象 schema，加 action 说明及执行前动作级校验，缺参/互斥错误在写入前返回具体诊断，不以顶层 union 破坏 Provider 兼容。

read 保持字节偏移与 UTF-8 边界；edit 不增加模糊回退；shell 明确 cwd、毫秒超时、exit/reason 和索引/通道 artifact 读取顺序。错误恢复不能推荐绕过版本保护或重跑结果未知的操作。

### 4. 按需自定制导航

扩展已有 SDK 索引，形成目标到指南/示例的映射；常驻目录保留简短发现入口，完整过程仅经显式工具读取进入上下文，不通过猜测用户关键词自动加载全部资料。

选择规则：简单技能/规则及直接资源修订走 resource；隔离项目开发和检查走 candidate；分发、跨项目能力及版本管理走 package 或受支持的用户级 resource_write。主题覆盖字体、颜色、间距、气泡与动效；涉及运行区域时引用 runtime-ui，而非只创建结构化面板。

指导完成安装版契约读取、创建、静态检查、必要预览/模拟、显式授权与激活、实际状态核验。运行期间 reload 排队时报告 pending；当前运行不能等待自己的结束来声称激活成功。缺少可见效果证据时说明下一步，用现有 delivery card 呈现状态，不新建 Web 界面。

### 5. 第三方兼容

扩展可选 promptSnippet/promptGuidelines 维持兼容；无摘要默认省略系统摘要，schema 中仍保留完整描述。MCP 不擅自重写远端 schema 和参数；宿主只增加明确分隔的来源/数据边界。SDK 文档提供摘要、参数、恢复示例及禁用指导撤销规则。框架文本转义资源名、路径、正文分隔符，原始内容保存在证据中；不把转义描述为能完全防止模型提示注入。

### 6. 任务指令统一组织、分别渲染

主对话、compaction、session-title 共用版本与证据格式，但不共用全部操作指令。主对话强调相关上下文、专用工具、聚焦修改、验证、准确报告和跟随用户语言；压缩只接收必要摘要约束与历史数据；命名保留当前格式校验及失败回退。

压缩保留现有无 schemas、无执行器和拒绝 toolCall 的边界，不继承要求编码/激活的主提示。spec.md 7.4 曾建议复用主前缀，本次明确选择辅助任务隔离，接受可能损失前缀缓存，记录前后开销；不宣称缓存收益。保留压缩闭合边界、revision 校验、原子检查点、取消和迟到结果保护。辅助调用统一经过 createProvider 和现有记录入口。

### 7. 验收先测行为，再看成本

在变更前固定普通编码、限制工具、自定制、MCP、规则/Skill、压缩和命名的请求夹具。对照记录系统文本/schema/总输入 token 估计及来源；普通编码夹具的常驻自定制指南应减少，禁止同一完整 description 默认重复。完整 schema 可能因参数说明增加而变大，不以总 token 单一阈值牺牲契约。

确定性测试覆盖每项规格行为，浏览器和 tarball 验证资料可发现、效果及状态展示。真实模型评测另记录固定模型/参数、重复次数、完成率、无效调用、总轮数、usage 和耗时；默认不发送付费请求，凭证未配置时标未运行，不能将模拟测试结论替代模型表现。

## Risks / Trade-offs

- 描述更详细增加 schema 开销 → 删除系统重复、指南按需加载，并分别记录成本。
- 辅助任务隔离影响摘要质量及缓存 → 保留来源/未知结果场景并记录对照，不预先承诺收益。
- 动态节点改变上下文预算 → 使用最终投影重新计量，回归压缩和自定义 Provider。
- 按需资料不被模型主动阅读 → 短目录给出清晰触发条件和可用入口，真实模型演练单独验证。
- schema 动作校验暴露旧调用问题 → 仅拒绝原本无效调用，合法旧调用回归；不收紧远端 MCP 未声明条件。
- 参考代码可能不同于安装依赖 → 不使用 reference 内部类型，类型检查和安装包验证固定公开接口。

## Migration Plan

1. 保存旧请求夹具与成本基线；实现兼容组装和证据字段，旧 Journal 缺失新字段时保持可读。
2. 切换核心/定制契约、按需资源导航、辅助任务模板，更新随包 SDK 和研究说明。
3. 执行来源、工具、恢复、定制、压缩、Provider 回归及安装包/浏览器验收，记录未测真实模型项。
4. 通过后统一启用新模板版本；需回滚时恢复旧组装及模板，已保存记录不重写，新证据的附加字段保持兼容。
