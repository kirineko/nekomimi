## Why

当前提示词重复工具描述、缺少参数契约和明确章节，且定制指令在工具过滤前生成，可能继续引导模型调用不可用工具。参考本地 dsh 的分层、作用域和证据设计及 pi 的工具摘要/指导分离，统一优化普通编码、自定制、压缩和命名任务的模型输入，使调用更准确、交付更面向用户，并能验证优化收益。

## What Changes

- 建立带版本、来源、作用域和工具依赖的分层提示组装；以最终启用工具集合生成 schema、摘要、指导和资源入口，统一撤销失效贡献。
- 区分稳定行为规则、工具策略、项目/目录指令与动态环境和历史数据；精简重复内容，保留请求证据和明确的数据边界。
- 系统修订全部内置、定制管理工具的摘要、描述和参数说明，明确路径、单位、默认值、动作参数、前置条件、截断续读、失败及取消后的处理；扩展与 MCP 接入保留兼容和原始来源。
- 将定制开发长指引改为可发现、按需读取的任务指南，覆盖技能、规则、工具、命令、主题、面板、运行时 UI、工作流及 MCP 接入；统一项目/用户作用域、开发途径选择、验证/激活/交付证据。
- 统一主对话、压缩、自动命名提示的组织及版本追踪；辅助任务保留各自约束，无工具执行，并明确历史、远端内容和当前指令的边界。
- 增加组装、调用恢复、自定制及辅助任务回归场景和提示词成本对照记录，区分确定性测试与真实模型评测。

范围对应 spec.md 第 3.1、4、5、7、9、13 节。非目标：新增搜索/抓取或后台执行工具、迁移 dsh 宿主、升级 pi、修改既有授权模型、重做 Web UI、保证服务端缓存命中；不改变文件工具的字节偏移和精确编辑语义。

## Capabilities

### New Capabilities
- `prompt-task-profiles`: 主对话、压缩和命名的版本化任务指令、数据边界及可复现对照验收。

### Modified Capabilities
- `prompt-context-provenance`: 分层贡献、工具依赖过滤、动态上下文和精确来源追踪。
- `core-tools`: 与执行行为一致的模型可见工具契约和恢复指导。
- `self-customization-workflow`: 按需任务导航、定制工具动作契约、第三方贡献兼容及面向效果的交付指导。

## Impact

涉及 src/context.ts、src/runtime.ts、src/tools.ts、src/customization 的资源/工具/SDK 接入、src/compaction.ts、src/session/title.ts、extension-docs、相关测试及验证文档。沿用公开 pi 接口及当前固定版本，不增加外部依赖；扩展 promptSnippet/promptGuidelines 保持可选，旧 Journal 不迁移或重写。仅在 change 中建立规划，实施后再同步主规格。
