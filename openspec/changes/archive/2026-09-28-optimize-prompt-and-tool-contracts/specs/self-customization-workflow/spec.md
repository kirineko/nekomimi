## ADDED Requirements

### Requirement: 按需开发导航和动作契约
系统 SHALL 向模型提供匹配安装版本、实际可读的定制资料入口及简短任务目录，在需要开发定制能力时按需读取完整指南。指南 SHALL 覆盖技能、规则、工具、命令、主题、面板、运行时 UI、工作流和 MCP，说明 resource、candidate、package 的选择边界、作用域、权限及验证交付步骤。管理工具 SHALL 明确每个 action 必需及互斥参数、默认值、返回阶段和失败恢复条件；缺参或冲突 MUST 在副作用前返回可定位诊断。

#### Scenario: 普通编码任务
- **WHEN** 用户请求修复普通项目代码且尚未读取开发指南
- **THEN** 常驻提示仅包含简短可用入口和必要边界，不注入全部定制开发流程。

#### Scenario: 项目及用户级风格开发
- **WHEN** 用户要求定制字体、配色、间距、气泡和动效，或明确要求跨项目使用
- **THEN** 可从目录读取匹配版本的主题及运行时 UI 示例；默认项目级，跨项目请求使用用户级并保持独立写入和代码执行授权，不能把项目 candidate 当作用户级已交付能力。

#### Scenario: 无效动作与缺失资料
- **WHEN** 管理工具 action 缺少必要参数，或引用资料不可用
- **THEN** 无效动作不执行变更，返回具体缺失项或可用资料入口；不能通过要求读取任意安装路径绕过边界。

### Requirement: 第三方提示贡献兼容
系统 SHALL 保持已有扩展可选 promptSnippet/promptGuidelines 和 MCP 原始工具 schema 的兼容；缺失摘要时使用确定性的简短回退或省略摘要，完整描述仍可在 schema 中读取。宿主包装 SHALL 保留原始描述、有效描述和来源映射，不将第三方描述或工具结果提升为宿主权限策略。

#### Scenario: 旧扩展和远端工具
- **WHEN** 加载未提供提示摘要的旧扩展或含特殊标记的 MCP 描述
- **THEN** 工具仍可用，参数语义不被宿主擅自改写，内容边界不会被标记破坏，授权仍由执行层判断。

### Requirement: 面向效果的开发交付指引
系统 SHALL 引导模型以当前资源版本的验证和应用证据报告定制结果，区分静态通过、加载、预览、实际应用与待授权；常规交付优先说明用户可见效果、入口及必要下一步，技术标识和原始 JSON 保留在证据详情。

#### Scenario: 排队重载和取消
- **WHEN** 开发后重载仍 pending、权限不足或验证取消
- **THEN** 交付说明真实阶段及下一步，不宣称主题已应用或面板已显示；恢复查看历史不再次执行激活。
