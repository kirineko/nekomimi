## MODIFIED Requirements

### Requirement: 资源与模板

系统 SHALL 在服务声明能力后支持资源、资源模板的分页发现和显式读取，保留 URI、MIME、内容摘要、服务器版本与原始响应；资源链接不自动读取，单次/累计内容与分页必须有界。

发现或读取 SHALL 绑定模式和目标，读取事实与上下文注入是独立状态；跨模式使用必须经交接选择和目标权限校验，不自动复制已读取资源。

#### Scenario: 显式读取远端资源
- **WHEN** 用户或已授权工作流选择一个 MCP 资源模板并提供参数
- **THEN** 仅按服务器能力读取目标，保存原始内容和来源，缺失/过大/不支持内容明确报告。

#### Scenario: 创造读取后返回工作
- **WHEN** 创造会话读过 MCP 开发资料，随后用户回到工作会话
- **THEN** 工作输入不自动含该正文；只有经选择且目标允许的引用才注入并记录来源。

### Requirement: OAuth 生命周期

系统 SHALL 为支持的 HTTP MCP OAuth 流程提供服务端授权、PKCE、状态绑定、凭证持久化、刷新、断开及重新授权；授权资源/issuer/端点 SHALL 经验证，不支持流程明确报错且不回退明文凭证。

凭证 SHALL 绑定明确服务器/账户及目标端点，不因两个模式切换或同 URL 的不同服务而混用账号；已开始的轮换刷新须安全保存返回凭证，业务取消不将失效旧刷新令牌重新持久化。认证成功不授予工具执行权限。

#### Scenario: 刷新与重启
- **WHEN** 已授权连接在服务重启后令牌过期
- **THEN** 宿主使用持久凭证按协议刷新或请求重新授权，令牌不进入浏览器业务数据或 Journal。

#### Scenario: 恶意回调或发现
- **WHEN** 授权回调状态不匹配，或发现信息把凭证导向不可信目标
- **THEN** 系统拒绝回调或目标，不转发凭证，不把连接标为已授权。

#### Scenario: 同 URL 不同账户
- **WHEN** 用户配置同 URL 的两个服务器名称并分别登录
- **THEN** 凭证身份明确隔离，跨模式调用仍按服务器和授权选取，不发送另一个账户的令牌。

#### Scenario: 取消时令牌轮换
- **WHEN** 业务请求取消而远端已经轮换刷新令牌
- **THEN** 不继续业务调度，安全完成凭证状态更新或要求重新授权，令牌不出现在日志和客户端。
