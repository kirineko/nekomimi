## Purpose

为工作任务与产品创造之间提供可检查、最小化且可恢复的信息交接，使用户能够在两个独立会话间传递目标和交付成果，而不复制无关历史、授予新权限或重复触发开发工作。

## ADDED Requirements

### Requirement: 显式且最小化交接
系统 SHALL 在交接前展示目的、目标会话或新建目标、选定输入引用及作用域；仅在用户确认后持久化交接，默认只带目标、约束、选定引用和必要摘要，不复制全部历史或凭证。

#### Scenario: 取消交接
- **WHEN** 用户查看交接预览后取消
- **THEN** 不创建目标任务、不发送模型请求，源会话及草稿保持不变。

#### Scenario: 显式摘要准备
- **WHEN** 用户在预览后明确请求对选定数据生成摘要
- **THEN** 使用独立受记录准备任务和无工具请求，保留用途、输入 hash 与来源；成功摘要仍需用户确认，不能自动创建或运行目标任务。

#### Scenario: 摘要取消或源变化
- **WHEN** 摘要请求取消、返回工具调用、泄露凭证或源 revision 在完成前变化
- **THEN** 不接受迟到或无效摘要，不完成交接，保留脱敏失败／取消证据；未完成的准备任务不会因重复命令自动重跑模型。

#### Scenario: 引用无权限
- **WHEN** 选定引用属于目标不可访问的工作区
- **THEN** 拒绝该交接并定位引用，不通过复制正文绕过授权。

### Requirement: 交接幂等与恢复
交接 SHALL 有独立身份、源 revision、内容 hash、源/目标会话和命令 ID；同一命令同一内容返回原收据，不同内容复用 ID SHALL 冲突。恢复读取仅补齐已接受的元数据，不自动执行模型或工具。

#### Scenario: 接受后确认丢失
- **WHEN** 交接接受后浏览器断开并重复请求
- **THEN** 至多产生一个目标会话和一份交接记录，不重复提交任务。

#### Scenario: 跨会话记录中断
- **WHEN** 源侧已记录交接意图而目标侧尚未关联时进程终止
- **THEN** 显示待完成交接并按同一 ID 恢复元数据；不把单侧记录视作任务完成或自动运行目标。

#### Scenario: 源后续变化
- **WHEN** 已可靠记录交接意图后源历史又变化，随后恢复目标接收
- **THEN** 使用意图中的固定快照，不重新生成摘要或从变化中的源上下文复制正文；不同内容复用原命令仍冲突。

#### Scenario: 意图未可靠提交
- **WHEN** 意图 I/O 失败且可靠水位不包含该意图，修复又改变源 cursor
- **THEN** 不将未提交尾部当已接受交接，不绕过旧预览过期检查；重新预览并确认后才能接受。

#### Scenario: 活动运行中重取收据
- **WHEN** 已完成交接的源或目标后来运行普通任务，调用方重提原确认
- **THEN** 只读返回原收据，不抢占 writer、不重复写入交接、不改变当前运行。

### Requirement: 交付结果独立应用
返回工作会话的交付 SHALL 包含候选/活动版本、范围、使用入口、真实验证阶段、阻碍及证据引用；交付通知不等于激活、授权或再次执行能力。

#### Scenario: 只有预览通过
- **WHEN** 创造会话回传一个仅预览通过的主题
- **THEN** 工作会话显示待应用而非已生效，不自动改主题。

#### Scenario: 目标已删除或候选过期
- **WHEN** 交付时工作会话已删除或候选已更新
- **THEN** 保留创造证据并报告不可交付或版本变化，不重建已删会话或应用旧候选。

#### Scenario: 交付阶段不能伪造
- **WHEN** 客户端提交候选版本并声称它已应用、获准或通过宿主验收
- **THEN** 拒绝客户端阶段及权限字段，只从匹配版本的 Journal 和当前宿主计算交付事实；预览、加载与工作应用不能互相替代。

#### Scenario: 工作显式引用交付
- **WHEN** 用户提交带已接收交付引用的新工作请求
- **THEN** 在派发前核对引用属于当前工作会话，记录请求、运行和交付版本的关联；引用不自动执行命令或扩大授权，同一命令改变引用仍冲突。

#### Scenario: 历史交付与当前版本
- **WHEN** 已确认交付的候选后来更新、停用或源会话删除
- **THEN** 历史阶段及快照保持不变，当前差异和来源不可回溯分别显示，工作宿主仍可检查自己的已活动版本，不恢复来源或旧候选。

### Requirement: 独立取消与上下文
两会话 SHALL 分别维护草稿、历史、预算和运行；取消一个会话不隐式取消另一个已明确启动的运行。交接摘要 SHALL 作为有来源数据而非新权限指令。

#### Scenario: 返回工作会话
- **WHEN** 用户离开仍在验证的创造会话
- **THEN** 工作草稿恢复且验证状态可查，不把导航当取消，不将创造的 SDK 和构建日志全量注入工作上下文。

#### Scenario: 不同目标独立运行与取消
- **WHEN** 工作与独立开发目标的创造会话均由用户明确启动，随后停止其中一个运行
- **THEN** 仅匹配的会话及运行 ID 收到取消，另一运行继续；同一物理目标仍串行，导航、观察和重提已接受命令不取消任务。

#### Scenario: 辅助命名隔离
- **WHEN** 一个会话正在无工具命名，用户在另一个独立目标启动任务或提交过期取消 ID
- **THEN** 原命名不被隐式取消；只有同一目标的新任务优先，命名不能改写另一会话标题或主预算。
