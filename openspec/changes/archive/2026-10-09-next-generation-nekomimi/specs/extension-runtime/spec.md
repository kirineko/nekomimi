## MODIFIED Requirements

### Requirement: SDK 版本和命名
系统 SHALL 提供版本化的统一公开 SDK 类型与能力目录，覆盖工具、命令、运行及工具前后钩子、清理、Provider、工作流、状态、面板及运行时 UI，并声明支持的协议与模式。旧清单和公开类型不再保证兼容；系统 SHALL 在执行工厂前拒绝不受支持版本、能力、重复注册和内置名称覆盖，诊断定位来源，不自动扩权或生成兼容代码。

#### Scenario: 请求未来能力
- **WHEN** 扩展声明当前宿主不提供的能力或不兼容协议
- **THEN** 系统拒绝激活并列出不支持项，不注册半套工具或伪装成功。

#### Scenario: 新旧扩展共存
- **WHEN** 安装使用不受支持旧 SDK 的命令或主题扩展
- **THEN** 返回明确版本错误和新 SDK 资料入口，不执行扩展工厂、不改写其文件、不赋予新增权限。

#### Scenario: 查询真实能力
- **WHEN** 开发者或 Agent 查询安装版本的 SDK
- **THEN** 公开类型、版本、模式范围和能力目录一致，区分支持、所需、获准及实际可执行能力。

### Requirement: 统一受记录执行
宿主管理的内置、扩展和 MCP 工具 SHALL 在副作用前记录意图及实际参数，记录终态、原始结果和资源版本；模型投影与 UI 数据 SHALL 独立于原始证据，输出 SHALL 有界且能定位完整证据或明确缺口。

从脚本或其他工具触发的嵌套调用 SHALL 使用相同门禁，记录独立 ID、父调用及模式/目标。辅助模型服务 SHALL 经统一模型证据入口；能力过滤不能只发生在前端。

#### Scenario: 扩展工具输出超限
- **WHEN** 自定义工具返回大量结构化输出
- **THEN** 模型得到有界结果和截断指引，历史可查看已保留完整 artifact；若证据本身超过限制则明确报告缺口，不能宣告完整捕获。

#### Scenario: 绕过 UI 调用
- **WHEN** 工作模式扩展尝试嵌套调用产品激活工具
- **THEN** 服务端在副作用前拒绝，保留被拒绝调用证据，不运行激活逻辑。

#### Scenario: 取消时排空已准入宿主服务
- **WHEN** 扩展回调因取消或进程退出终止，但该回调发起的宿主工具服务仍在收尾
- **THEN** 宿主拒绝新的回调服务，等待已准入服务完成结果或失败记录后再释放调用方 Journal；进程退出不视为宿主服务已完成，未知外部效果不自动重跑。
