## Goals / Non-Goals

**Goals:**

- 将上游变化限制在集中适配层，业务规则、证据格式与 UI 不追随 Pi 内部类型变动。
- 在新能力中只有一条模型记录入口、一条工具执行管线和一份权威事实历史。
- 从数据身份上分开 work/create，不靠提示词或前端路由完成权限隔离。
- 将能力创造与工作消费连接起来，同时控制上下文量和副作用。
- Web 状态按权威数据、读取缓存、草稿、布局分别管理；复用组件而非重写两套工作台。
- 先建立可执行规格与验收映射，再按批次切换，内部过渡代码不形成长期兼容 API。

**Non-Goals:**

- 不替 Pi 维护 fork，不依赖未导出的模块，不复制其 CLI 会话系统。
- 不构建分布式运行时，不在本次提供完整多代理调度和远程 SSH 环境。
- 不将可信代码执行承诺为强沙箱，不用模式切换偷偷扩大权限。
- 不兼容旧持久化/SDK 格式，但不主动修改或删除旧数据。
- 不把组件框架选型、所有模型可用性或实际性能收益写成已经验证。

## Decisions

### D1. 稳定产品边界与 Pi 集成层

推荐目标模块边界（名称为设计建议，不是必须保持的公共路径）：

```text
web/work + web/create
          |
application commands + queries
          |
mode / sessions / creation / capabilities
          |
context preparation + recorded model/tool services
          |
pi adapter: durable / ai / codemode / mcp
          |
journal + artifacts + derived projections
```

依赖方向：Web 只导入纯协议与展示类型；应用服务依赖产品接口；Pi 类型仅进入 adapter 和必要的类型映射。Journal 物理写入不依赖 React 或 Pi 私有 session 实现；Durable Storage adapter 使用公开序列化写入契约，context 不从 UI timeline 重建模型历史。

Pi 版本与支持清单作为构建 manifest 输出，含包精确版本、adapter revision、支持的模型操作、实验功能标识及安装资产检查结果。不允许从 `reference/pi` 的绝对路径加载运行代码。升级契约套件为每项上游能力绑定 fixture 与产物测试。

备选“整个嵌入 pi-coding-agent”会带来第二套会话、压缩和扩展加载假设，因此不作为默认方案；备选“完全自研模型循环”则使跟进成本更高，也不采用。

### D2. Durable 目标底座与唯一提交适配

**唯一生产目标路线：Pi Durable 1.0.4 + Nekomimi Journal Storage adapter。** Durable 负责公开的 conversation/task/submission/document 生命周期，产品负责模式、目标、授权、上下文、模型传输与证据。低层 Agent 的已完成探针仍是行为基线，不是可自动切回的生产路线。

Journal 继续使用追加 JSONL、hash 链、可靠水位及完整性附件。每次 Durable `Storage.commit(writes)` 对应一个 `durable.commit`，保存 adapter/format 版本、框架 seq 及 detached writes；多项写入不能拆成若干分别生效的事件。MemoryStorage 通过公开 `prepareCommit` 预校验批次，并作为只读查询投影；禁止另建 Durable 原生 JSONL/SQLite 或持久化内存快照作为权威恢复来源。

提交顺序：序列化/校验并固定批次 -> Journal 附件（需要时） -> Journal 事件及可靠水位 -> apply 内存投影 -> 返回 Storage seq -> Session 提交观察。Journal seq 与框架 seq 分别保存、显式关联，不以数量相等推断；模型/工具证据也写同一 Journal。投影更新或水位提交失败时 poison 当前 adapter，禁止继续派发/发布成功，重开只恢复可靠提交。mintId 采用公开投影分配，已持久化 ID 从批次恢复；未提交 ID 不构成已接受身份。

以下七项是 Durable 的准入门槛，1.4 必须逐项提供实际证据：

1. 意图、工具/模型结果、任务状态与 UI 水位由同一权威提交决定，提交前不能对外发布可靠成功。
2. 统一 Provider transport 在最终序列化后记录每个网络 attempt；关闭或逐次捕获框架及 SDK 隐藏重试。
3. 通过公开 generation hooks 输入产品固定 ContextSnapshot，禁止框架随后偷偷添加历史或声明；最终 body 与来源清单对照。
4. 原始流及不完整响应通过受记录入口按背压持久化，Parsed events 只作投影，不能替代原始字节。
5. kill、unknown、取消迟到、磁盘/fsync/水位故障保留实际事实；提交失败 fail-closed，重开不会派发副作用。
6. 只用发布包公开接口；工具桥强制采用不重放策略。只读打开、导出、导入、导航不启动 scheduler，显式恢复也不得重新执行 unknown 工具。
7. 仅一份 Journal 和一个写入租约；删除全部内存投影后仍能重建 Durable 任务、条目、文档和关联。

恢复分为只读观察与用户显式接受的新任务。未完成工具从可靠批次导出 unknown；框架的 interrupted 或 replay 标记不能伪造其外部终态。恢复启动前核对待运行任务与授权，通过公开取消/提交接口阻止旧业务自动续跑，不能简单调用 `waitForIdle` 充当安全恢复。

七项未全通过时不宣称 Durable 生产可用；记录具体阻碍并补公开适配，不自动回退 Agent，也不放宽唯一权威或 unknown 政策。双工作台视觉评审保留独立门槛。

### D3. 权威记录、身份与命令状态

新产品数据格式固定formatVersion=2，新SDK契约sdkVersion=3；默认独立分区为~/.nekomimi/v2，显式目录选择保持原路径。根标记nekomimi-format.json必须声明product=nekomimi及formatVersion=2；无标记的非空目录在任何写入前拒绝。内部Durable批次adapter/format版本仍为1，它不是产品根目录或SDK契约版本。新格式使用显式版本；不复用旧格式写入目录。建议身份与关联：

| 对象 | 必需身份/版本 | 权威归属 |
| --- | --- | --- |
| Session | sessionId、mode、targetId、formatVersion | 会话 Journal |
| Target | targetId、kind、规范化根目录、目标宿主身份、范围 | 版本化配置与创建快照 |
| Run / Task | runId/taskId、sessionId、commandId、输入摘要、状态 | 所属会话/创造操作 Journal |
| Call / Attempt | callId、attemptId、parentToolCallId、parentModelCallId、parentAttemptId、purpose、operation | 同一记录入口 |
| Candidate | candidateId、内容 hash、基线、目标宿主、契约版本 | 创造操作记录 + 不可变产物 |
| ContextSnapshot | revision、mode、target、model、capabilityRevision、节点清单 | request 准备证据 |
| Handoff | handoffId、commandId、源/目标、sourceRevision、payloadHash | 源会话协调记录及目标引用 |

同一 commandId 的内容 hash 必须相同，否则冲突；回执已丢失不等于命令未接受。运行状态至少区别 accepted/running/cancelling/completed/failed/cancelled/interrupted/unknown，显示映射可以简化但不可改变事实。

创建协议保持现有HTTP envelope版本1，增加显式commandId/mode/target；新版工作台固定同一创建ID直到收到收据，创建本身不提交任务。服务生成的会话路径ID与Journal sessionId相同。工作区session-catalog Journal仅协调创建命令：先持久化固定身份的session.create.intent，再创建会话首条durable.session及session.created，最后记session.create.committed；重复命令补齐元数据，不命名或调模型。会话Journal保持模式/目标的权威，registry不保存模型和工具历史。删除收据保留在协调Journal，旧创建ID不得复活被删除会话。显式headless创建命令共用该命名空间并绑定规范会话位置。headless 显式任务命令重提先只读核对已接受 ID／内容 hash，返回原运行与可靠终态；无终态返回 interrupted 的观察结果，不调度旧业务。该路径不加载工厂、获取写入者或再次命名，writer 内仍复核并发准入。

Target快照包含规范绝对根目录与目录device/inode、范围，以及创造宿主id/build/SDK/数据契约版本。只读打开将丢失或被替换的目标标为unavailable；执行入口在工厂与任务派发前核对，不回退服务cwd。没有模式身份的旧观察仍可读，但不能继续运行；新分支有独立创建身份并继承原模式/目标。后续3.2/3.3落实有效能力及宿主资料/权限门禁，身份绑定本身不授予权限。

服务保留单写入者与跨进程工作区租约。每个副作用在 dispatch 前持久化意图，Journal 失败触发 fail-closed；在途结果可不完整但不得伪造回滚。UI 仅发布可靠提交后水位，流量诊断另走可丢弃 telemetry。

### D4. 模式、工作区和权限是三个独立维度

会话 mode 不可变。工作 target 是用户项目；创造 target 是独立开发目录，加目标宿主和能力/核心候选类别。改变目标或模式通过新建/关联会话，不在活动运行中修改 session.cwd。

请求准备计算 `effective capabilities = mode filter + target scope + enabled versions + granted permissions`。执行时再次校验当前授权：版本固定不冻结授权。撤权后下一次派发必须拒绝；对在途工作请求取消并诚实报告实际终态。

工作模式没有候选管理或核心切换入口；已应用 `/review` 等普通能力仍可用。创造模式可访问受限版本资料，但用户级写入、构建代码执行、外部端点及切换宿主仍独立授权。

SDK 3 工具、命令和工作流的 `modes` 声明参与同一过滤；省略表示两种模式适用。工作模式的 SDK 资料不可发现且已知 ID 读取也拒绝。`ctx.callTool`、`ctx.reload`、工作流创建／继续和 HTTP 管理入口依据持久身份校验，客户端 mode 字段不构成授权。拒绝写入 Journal，已知未派发的 RPC 拒绝与结果未知分开记录。有效能力事件记录模式、目标、固定激活 revision 和实际工具／命令目录。

物理独立目录不构成 OS 安全沙箱。基础文件工具校验路径、真实根目录与新鲜度；unrestricted shell/可信扩展的进程权限风险继续明确告知。不得在 UI 或文档宣称 work 模式能拦住任意受信 shell 的所有越界访问。若未来需要强隔离，另设执行环境能力；本次不隐式引入容器平台。

创造准入与每次派发检查目标目录身份及绑定宿主构建／SDK／数据版本，资料读取也核对同一绑定。目标不能包含原工作项目或覆盖当前安装。核心目标先只读检查匹配版本源码、lock 和构建入口，不执行脚本；完整内容基线、独立源码复制及可信构建由 D9 核心候选阶段记录，不把文件存在当作构建验收。

### D5. 跨模式交接使用两阶段元数据协议，不假装跨文件事务

两个会话历史独立，源 Journal 协调交接：

```text
preview (no mutation)
   --> source: handoff.intent + selected immutable payload
   --> target: handoff.received (dedupe by handoffId)
   --> source: handoff.committed + target receipt
```

目标新会话 ID 在 intent 中先确定，重试不再次分配；持久操作以相同 handoffId 幂等补齐。源/目标存在不同 Journal 时，不假设原子跨文件提交。崩溃后只恢复关联和读取状态，不自动运行模型或工具；用户仍需明确提交目标任务。目标首次接受任务时引用交接快照，不从变化中的源上下文重新取值。

确认请求要求 `confirmed:true`、固定命令 ID 与预览 hash；源 writer 内再次核对 cursor 后可靠提交 intent。目标创建沿用创建命令注册 Journal 并核对预览中的完整绑定，target.received 独立持久化同一选定快照，source.committed 包含两个事件 ID。已确认收据可在活动运行持有 writer 时只读返回。状态读取显示 pending／blocked／committed；`handoff-recover` 只从已接受 intent 恢复元数据，不接受替换 draft，不在 GET、导入或回放中隐式创建目标。

未可靠提交的 intent 不作为已接受命令。I/O 修复新增 Journal 恢复证据时，旧预览可过期，需要重新预览确认；已可靠接受的 intent 则始终使用原快照，源后续变化不偷换交接正文。目标的逻辑删除标记或已创建记录丢失阻止恢复，不复活原目标。

预览不发模型请求。需要模型生成摘要时作为用户发起的独立准备任务运行，成功后仍需确认实际内容；取消、失败或冲突不创建已完成交接。用户手写交接可直接确认，无需额外模型。

摘要准备使用独立操作 Journal 固定选定输入、源 cursor、目标身份、payload hash 和命令 ID，经统一受记录模型入口发送 handoff 用途的无工具请求。重复已完成命令返回同一收据，未完成／unknown 命令不重跑。准备成功只产生待确认摘要；请求取消、凭证响应、工具调用或源 revision 冲突均不创建目标会话，不向源主上下文计入辅助 usage。准备 Journal 是该操作的权威证据，不是源／目标历史的副本。

交付方向 create -> work 使用相同协议，payload 为使用摘要、候选/活动版本、真实阶段、范围与证据，不含全部开发 transcript。接收不是应用，不自动执行能力。删除源会话不会删除目标已持久化交接快照；原证据引用显示不可回溯。两会话运行互相独立，导航不取消，取消不跨会话扩散。服务按会话追踪运行和命名，不同物理目标允许同时运行；同一目标的可变宿主保持串行。新请求只抢占同一目标的辅助命名，重提已有命令不抢占；取消必须匹配会话及当前运行／命名 ID。服务停止及租约丢失取消全部活动任务。删除预览提供双侧关系与证据影响，逻辑删除不级联；关系查询保留已接收快照并标记来源不可回溯。

刷新后的交接确认状态从源 Journal 的 handoff.intent/received/committed 关联读取，页面观察不补写记录；用户勾选原快照后按原 commandId/payloadHash 显式恢复元数据。已删目标保留阻碍且不可重建，已完整记录的交接不提供重复恢复操作。工作输入可单独选择最多 8 份已接收交付，将 handoffIds 随显式请求一并提交；选择本身不执行、应用或授权。普通输入和交付引用草稿分别持久化，收据只清除仍与原提交匹配的当前草稿；跨导航迟到回执读取按会话隔离的最新草稿，不能清空后来编辑的内容。

摘要准备在预览内单独授权模型调用，沿用原 payloadHash 与独立准备命令；结果先展示，采用后清除旧确认并要求重新预览。停止请求等待服务端终止，不将请求发出当作完成；取消/失败后重取原命令不能再次派发模型。修改或离开预览撤销 HTTP 观察并通过既有断开信号中止摘要，迟到结果不写入新草稿。无凭证和源 revision 改变分别显示局部诊断，不确认交接。

工作和创造共用会话输入控件；创造输入按绑定 targetId 独立保存草稿，命令目录按 session 查询。创造主区显示可靠快照/SSE 结果和显式停止入口，活动运行时允许编辑下一轮草稿但禁止重复发送。查看新收到交接或刷新仅观察，提交才执行绑定目标的创造任务。

交付卡的候选链接包含工作会话、handoffId 和确切 revision。目标页面先从该工作会话的已接收快照验证源会话/候选/版本关联；无匹配快照时拒绝展示候选。开发内容变化或源候选不可读时只保留交付快照与诊断，不把新版差异和验证当作旧交付；另行查看当前候选需要明确导航。返回工作时以交付卡为阅读锚点恢复相对滚动偏移和证据展开状态，支持显式返回与浏览器后退；异步数据到达期间恢复锚点，用户主动滚动/触摸/按键后停止自动定位。该交付锚点不替代第 10.7 的完整虚拟列表与动态媒体门槛。

交接表单与普通任务草稿分开，按模式、会话和候选保存输入。预览只读取来源记录与目标事实，取消或编辑使迟到预览失效；确认提交固定快照 hash 和命令 ID，同一页面的网络失败重提沿用原命令。来源引用使用只读选择列表，最多选择 16 项；当前列表显式显示最近 100 项及省略数量，长列表分页按后续 UI 门槛处理。交付卡将历史快照、开发版本变更、当前工作状态和来源可回溯性分别呈现；查看、刷新和跳转不启动模型或扩展工厂，不授权或应用候选。交接关系与交付事实分别查询，任一失败只影响自己的区域。

交付选择只接受资源／候选身份、确切 revision、贡献选择和用户使用说明，阶段、活动版本、权限和证据由只读宿主事实解析。开发与工作版本独立；跨物理资源 ID 用文件摘要比较相同内容，不将开发加载视作工作可用。静态／模拟／预览／加载／应用选择／宿主验收分别保留，只有相同内容的工作活动版本才列出其有效模式入口。原快照与当前过期、撤权、缺失、源删除诊断分离。

工作提交可显式选择已接收交付的 handoffIds，引用参与命令 hash，在资源工厂／派发前验证，再在 writer 下写 delivery.referenced 与 run／command／版本关联。引用不执行说明中的命令、不授予权限、不自动加载旧版本。来源删除后可继续只读检查工作宿主活动事实；实际模型输入仍由 D6 上下文选择及任务4.7接入。

### D6. 请求上下文是确定性产品投影

Durable的原生自动压缩和隐藏重试在接入阶段关闭；所有摘要由产品上下文服务经统一模型入口产生，公开压缩钩子只能提交通过源校验的产品检查点，不再维护独立有效摘要。

请求前服务输出不可变 ContextSnapshot：

4.2 使用 `context.snapshot` 的持久附件固定持久 mode／target、模型端点及版本、活动／有效声明 revision、来源 cursor 和有序选择清单；深复制并递归冻结，不冻结调用方对象。只规范化 revision envelope 的 JSON key 排序，不先规范化 Journal 身份和原节点 bytes；原 targetId／节点 hash 保持原序列化语义。纯元数据增长改变 cursor，不改变所选请求 revision。Durable 公开 beforeRequest 在可靠投影完成后准备快照，受记录 stream 只消费该 Provider 准备的一次性对象，框架历史不成为第二输入来源。

最终传输先可靠写 `request.transform`，再写带 snapshot 引用的 `request.dispatched`。内置 Responses 逐项核对 model／instructions／input／tools／输出预算与捕获值，并保存字段映射；注册 Provider 保留传给 serialize 的完整输入附件、注册版本和精确输出 bytes，作为显式 whole-envelope 转换，不通过重跑 serializer 重建旧请求。辅助选择保留原节点 hash 与数据 framing，压缩替换节点和未满足工具依赖的指令有排除理由；没有持久身份的旧辅助夹具标 unbound，明确的来源 links 只提供已知 mode／target ID，不虚构完整目标。


1. 读取持久模式、目标、当前模型、有效能力 revision 和任务输入。
2. 解析必要指令及目录作用域；按固定顺序产生分层 fragments。
3. 读取目录摘要和明确选择的 Skill/SDK/MCP 内容，记录引用、内容 hash、角色、范围及状态。
4. 选择历史节点和有效压缩检查点，保持工具 call/result 及 provider reasoning 等必要组合。
5. 应用大结果有界投影、预算与可安全压缩策略。
6. 保存选择和排除理由，并交给 adapter；adapter 输出 WireRequest 及转换映射。
7. 在发送前验证授权未撤销，保存最终序列化证据后 dispatch。

Mode profile -> task purpose 分为 work、create、compaction、session-title、handoff；分类/图片操作有独立请求类型，不复用聊天提示模板。正式运行从持久 mode 选择 work／create v3，压缩及交接各 v3，命名保持独立 v2；旧 main 组装别名只映射 work，不作为新的模式选择来源。每个 profile 有独立 source／版本／内容 hash，与 context.view 和实际 attempt 一并记录。所有辅助 profile 丢弃工具及主任务附加指令，不继承创造流程；旧请求按持久 bytes 展示，不用新 profile 改写。Rules 是指导，不是授权；交接、工具和历史数据进行安全编码和角色约束。

4.3 初始策略由 `context-policy.ts` 版本化：目录／分页／描述各有独立预算，分页同时受完整工具结果投影边界约束；目录状态事件和请求快照分开保存可发现、已读取、当前有效、本次注入与历史事实。技能加载收据不代替正文注入，实际资料数据按 Journal 原生工具身份关联；规则正文超限在主请求和任何压缩前失败，保存原文附件，不通过摘要修补必要指导。详见 resource-context 验证记录。

4.4 在请求准备撤下失效指令／声明并记排除来源；派发意图前及其可靠提交后重查来源、根身份、当前授权与凭证，不改已捕获正文。工具 prepare／hooks 保持一次，意图前及其提交后另行执行无 hooks 的再校验；意图后拒绝明确记录未派发，不能仅凭意图事件推断 HTTP 或外部效果。固定工作流区分执行副本和原逻辑授权位置，副本仍校验完整性、旧版本仍受当前 grant 和绑定范围约束；显式授权的候选模拟保留 mock 服务准入，生产不使用该模拟规则。验收见 context-revalidation 目录：最终 79 文件 544 项、类型／构建／严格规格通过，4.4 已完成。

4.5 使用版本 2 的预算／投影策略：输出、安全及可能工具结果预留分别报告，层级来源／排除与三类总量可对照；校准锚点包含模式、目标、有效声明和实际图片编码，辅助 usage 与主占用分离。大结果保留完整受控附件，再以 UTF-8／编码预算选择文本和独立图片；tool.projection 与请求选择保留双附件及 framing，省略图片按原 content 索引显式续读。实现经相关测试及最终 550 项单元回归验证；完整证据与历史失败见 context-projection 验证目录，工作台分层详情由 10.5 接入。

预算策略版本化，初始可沿用已存在的 80% 压力触发及约 16% 近期目标作为**待校准默认值**，但硬边界始终是容量减去输出和安全预留；数值放配置与测试，不在新规格中固化为不可更改体验。Model/schema/图片编码或上下文变更使旧 usage 校准失效。容量未知显示未知，不能沿用另一模型值。

压缩仅对安全闭合区间发生，保留创造状态、未知结果与权限待办。摘要提交校验 sourceRevision、model、target 与能力快照；失败不改投影。交接摘要不作为源会话的压缩检查点。禁止将辅助调用的输入/usage 累计到主上下文占用。

4.6 的来源身份及保留事实各有独立 hash。生成前后、附件后及 Journal 写入队列内用只读检查校验目标、Provider 配置、有效指令／工具授权和当前创造状态；异步检查后另有同步源／取消门禁。授权拒绝返回不提交并保存失败事实，不触发存储失败门禁。创造状态来自真实候选目录与生命周期 Journal 的当前版本各阶段记录，UNKNOWN、待授权交互和已确认交接约束按来源保留；宿主数据作为提交时快照独立附在摘要后，不靠模型 prose 代替验证事实。状态超过 64 KiB 或模型预算则安全拒绝，不裁去关键未完成事项。主题偏好读取无目录创建；递归与并发整理被拒绝，Durable 内置压缩保持关闭。实现经 130 项相关测试及类型／构建／严格规格验证，证据及历史失败见 compaction-source 验收目录；完整综合验收仍由第 11 组执行。

备选“同一历史切换 system prompt”实现短，但无法分离权限、摘要和输入量；备选“每轮重新生成完整摘要”会增加模型成本并损失来源，因此均不采用。

### D7. 统一工具执行与 Codemode

统一执行管线处理直接、扩展、MCP 和脚本子调用：

管线分为prepare与execute：prepare固定schema与参数快照、执行一次参数准备/真实schema校验及权限/前置hooks，返回只能消费一次的准入对象；execute在信号/Journal检查后记录意图并执行。Durable公开beforeTool桥接prepare，原生意图后消费同一准入对象，参数若变化则拒绝执行。框架ToolRegistration只声明通用object封套，避免其内部重复校验/强制转换真实产品参数；实际模型请求仍由受记录Provider发送完整真实schema。这里不会删除或放宽产品校验。后置hooks只观察副本，失败单独记录，不覆盖已持久的工具结果。

```text
resolve pinned identity
   --> validate input + current permission + target
   --> durable intent
   --> execute with cancellation / concurrency limits
   --> durable result or evidence gap
   --> model projection + UI projection
```

Durable 工具/任务 hooks 只作桥接，避免直接与嵌套两条路径重复触发 hooks 或重复写 tool.intent。子调用由宿主分配 ID，不信任模型自报 parent。脚本开始时固定可发现能力集合，但每次执行重新检查撤权。

使用独立 Pi Codemode 包的公开 sandbox 接口；注入的是管线方法而不是原工具 executor。VM 无直接 I/O；CPU/内存/输出/总时限由宿主预算控制，不允许脚本扩大上限或嵌套启动另一个脚本 VM。具体默认限制在批次 0 根据发布包验证后记录，不假设 Pi CLI 配置等同独立包默认值。任务 5.1 的正式适配器固定总时限 30 秒、QuickJS 内存 16 MiB、源码 256 KiB；调用者只能缩短时限。使用 1.0.4 公开输出上限 16 Mi 字符／100,000 项和小状态单值 256 Ki／总量 1 Mi 字符，并在调用前检查源代码和状态大小。公开 worker export 与 loadQuickJSWasm 从已安装依赖解析资产，独立 Nekomimi tarball 消费项目已实际启动验证。

资源级并发限制覆盖总调用数、同服务器、同文件修改；同文件串行不替代 stale-write 检查。MCP `isError` 在脚本中可作为结构化结果被处理，但记录依旧为远端错误。原始输出、可供脚本处理的有界结构、模型投影分别标明截断/缺口。

小状态按 session/branch 从成功的 store commit 重建，失败脚本不提交 storeWrites；这不回滚已执行子工具。未 await 调用在脚本结束时收到取消，远端终态不能确认则 unknown。正式实现每脚本 128 个子调用，同运行共享 4 个执行槽，同资源 2 个槽，取消收敛等待最多 1 秒。文件队列入队前固定已读版本；扩展/MCP 通过异步作用域使用子调用信号。成功 codemode.finished 引用状态附件作为唯一提交，队列内比较旧状态事件 ID；失败、取消或并发冲突不提交。分支以带 sourceEvents 的 state_seed 复制状态，不重放脚本。所有图片复制到持久附件后再对外给引用，不把临时文件路径当唯一证据。

### D8. MCP 和模型复用的适配范围

Pi MCP 优先负责 stdio/HTTP transport、初始化及可复用 OAuth；Nekomimi 负责作用域、授权、工具版本、记录和上下文选择。批次 0 对 tools、resources、prompts、订阅、OAuth 分别检测。Pi 缺少公开便利 API 时可保留当前官方 MCP SDK 的必要协议适配，不复制内部代码，且同一服务器只能由一个连接 owner 管理。

直接工具是请求必要连接，其他服务后台连接；显式搜索等待相关服务时有预算，失败不阻塞其他服务器。声明清单在请求边界固定；活跃运行不偷换 schema；移除工具不能转发到同名替代。目录发现与授权分开记录。

统一模型服务在 Pi Models 外包一层 evidence-aware 操作接口：聊天流、分类、图片和辅助调用都走相同 transport 捕获与取消门禁。无法公开截获实际网络 attempt 的实现不能直接登记为受记录能力；保留受控 adapter，关闭无法观察的自动重试。

受记录attempt只允许派发一次网络请求；重试必须创建新的attemptId。当前自动重试仅接受明确的429/502/503/504 HTTP响应，未知网络结果、解析开始后的失败及取消不自动重试。产品取消信号与原生任务信号合并后直接传入transport，不等待原生任务异步取消提交。网络完成事实可以保留，但完成记录落盘期间取消后不得再发布模型值、上下文或工具调用。

**本轮默认不开启自动虚拟路由。** 当前实现的 `routing` 契约仅允许省略或 `physical`，适用于模型定义、profile 和宿主请求；恢复配置中其它策略同样拒绝，保留原文件，并提供重新选择物理模型的诊断。目录明确报告物理模型，不提供 opt-in 路由入口。 完成目录、操作类型和物理模型分离记录，提供不支持路由的明确诊断。批次 0 可以验证 Pi 路由接口，但完整自动路由不是完成本变更的前提；若实现 opt-in 实验入口，则必须满足已有条件场景。辅助分类/生图默认需要明确模型配置，不自动跨 provider 回退。

模型登记身份固定为 provider/operation/id，operation 省略时为 chat；公开目录返回副本，执行登记独立捕获定义。模型资料按 work/create/compaction/session-title/handoff/classifier/image 选择，改变一个用途只更新其选择。新格式的 main/auxiliary/naming 默认项仍可明确使用：未单独选择的工作、创造、压缩、交接使用 main，命名使用 naming，扩展聊天使用 auxiliary。只读 model_catalog 同时供普通工具和 SDK callTool 使用，报告资料、凭证及操作接入状态，不因目录存在而声称可执行。

费用以唯一 model call/attempt 聚合，父工具仅展示子调用汇总引用，不能再次把它加到总费用中。未提供 usage/价格时保留未知。

### D9. 候选生命周期与核心版本切换

扩展候选复用现有内容寻址、检查、试运行和激活基础，重整 SDK 契约并拒绝旧版本；不新增另一套平行能力包系统。候选阶段独立存储：内容 revision、静态检查、可信执行试验、授权、加载、应用、宿主验收。不是把所有阶段挤成一个 enabled 布尔值。

核心候选另外包含 source baseline、源码快照、lock hash、Node/工具链、构建命令、产物 hash、协议/存储版本。源码来自用户明确选择的路径；复制到独立目录或从干净基线分配 worktree，未提交修改需显式快照，绝不重置原目录。

源码准备入口为 `core preview/prepare/inspect/list`：preview 只读实际文件并给出 source revision 与目标 build，prepare 必须确认二者，在不存在且独立的目标目录复制实际源码。基线保存文件字节摘要、可执行标记、空目录及 Journal 内容附件；源码差异从准备时附件读取前文，不从后续可能变化的原目录重建。已有候选缺少正文附件时明确诊断，仅展示摘要。附件落盘后再次核对原目录和副本，再提交 prepared；未提交/未跟踪源码保留。Git、依赖、构建输出、研究 reference、运行数据和环境凭证文件明确排除，排除项随预览返回；拒绝其余符号链接和超限输入。准备前后复核原目录与副本；失败保留诊断副本但不登记 prepared。Journal 的 core.candidate.prepared 是唯一登记，绑定所属项目、目标宿主和目录 device/inode；核心会话准入从登记事实固定 candidate id 与原始 source revision，不能使用仅含几个标志文件的任意目录。后续编辑只改变 current revision，不重写原始基线。此阶段 built/applied 仍为 false，后续构建与切换任务独立验证。

构建和包生命周期脚本是可信执行，不属于静态校验。独立启动使用隔离 home/存储、默认禁用真实凭证及外部副作用；真实服务验收另需授权，报告模拟范围。

可信构建以 build-plan 的 inputHash 显式确认当前源码、lock、目标宿主、Node 二进制、配套 npm 文件树、PATH、命令和预期契约。先写 Journal 意图，再在专属副本执行 npm ci 与 npm run build；HOME、临时目录、npm 配置和缓存独立，不继承凭证或 NODE_OPTIONS。输出附件分块落盘并跨块脱敏；默认 15 分钟、每命令 8 MiB 日志，超限明确终止。受管 POSIX 进程组取消采用 TERM/KILL 和 5 秒确认期限，不能确认时 unknown；已有意图无终态不自动重跑。产物全树包括依赖生成 manifest，拒绝外部/绝对符号链接及与产物目录外共享的硬链接；npm/esbuild 的完整内部硬链接组在固化前复制为独立文件，文件及目录同步落盘并只读固化后记录成功；检查当前输入、工具链或产物变化则使旧通过失效。构建成功不等于独立启动或宿主验收，始终保留 hostIntegration=not_run 和 applied=false，直到对应后续阶段获得独立事实。

独立启动入口 core validate 需要确认 buildId、artifactRevision、唯一 commandId 和可信执行授权。当前宿主在全新测试目录写入会话和 Durable commit；宿主自带子进程探针导入候选产物，检查实际 dist 身份、API/SDK/数据契约、Web 静态资源、无凭证配置、会话与 Durable 读写及重启，以及旧格式拒绝。父进程独立复核旧数据字节不变、当前宿主可读回和所有已观察端口关闭。只保留白名单环境，fetch 被探针拒绝，不调用模型或业务工具；可信候选仍有 OS 权限，不能称为恶意代码沙箱。60 秒总预算、1 MiB 输出及受管进程组清理记录真实终态；重复命令读原收据，无终态为 unknown、不自动重跑。源码/工具链/产物复核失败使检查失效。isolated-startup 与模拟、生产 hostIntegration 明确分开，不因本地启动成功报告已应用或真实外部服务验收。

切换空闲检查使用两层门禁：HTTP 写请求在读取 body 前登记，异步检查前同步关闭新写入入口；会话 gate 在既有元数据操作之后枚举所有工作/创造运行、命名、交接准备、下载、审批、已加载目标宿主和持久工作流等待。相同门禁命令在检查未结束时等待同一结果，不提前返回 ready；失败释放门禁，成功保留直到匹配命令释放或服务停止。工作流状态检查只读，不创建目录或加载工厂；不可读或宿主清理未知时阻止切换。跨进程构建/验证通过保留其原有 Journal writer 阻止新派发，检查全部已接受意图和终态；无终态、unknown、缺少已启动 PID 清理证据或残留端口均阻止切换，不自动重跑。只读状态是提示，真正切换仍须取得以上保留锁并再次核对候选。

支持的托管启动路径采用薄 supervisor 选择不可变构建目录，活动指针与切换记录由安装级单写入租约保护。切换步骤：检查所有相关运行空闲 -> 校验候选/hash/schema -> 独立健康检查 -> 记录意图 -> 切换选择 -> 启动与验证实际身份 -> 记录收据。若健康检查失败，恢复上次可启动构建；协议/状态不兼容时不得对原数据回退执行，进入只读恢复或要求独立目录。

受管启动入口为编译后 CLI 的 core launch，要求通过独立验证的 validationId、确切 artifactRevision 及明确授权。薄父进程以规范化 CLI 路径计算安装身份，在用户 HOME 的独立 installations 注册 Journal 中持有全生命周期 writer；工作区和 --home 不拆分租约，路径别名归一。先记录启动意图，再启动不可变候选、经 IPC 核对实际身份和本机 HTTP 健康后记录 selected。令牌仅通过 IPC 交付用户，不进入 Journal。父进程退出/租约失效停止所属进程组，子进程失去 IPC 时关闭服务，尚在模块加载阶段则不派发启动。源码或不受支持平台只返回明确手动启动步骤；core launch-info 只读且 currentMode=unmanaged、switchSupported=false。运行中切换与重启恢复仍由对应独立门槛实现。

运行时控制经认证 Web 路由及父子 IPC 传递；父进程持有 Journal 和稳定浏览器令牌，子进程重启沿用端口与令牌，令牌不进入命令参数或 Journal。preview 的 planHash 绑定当前实际子进程、目标产物、验证 ID、影响目录及契约；切换前须取得构建/验证 writer 和业务门禁，随后复核同一计划。独立启动探针验证初始 fence 下业务写入拒绝及控制接口可达，缺少此检查不能成为切换目标。新进程先带 fence 启动，通过真实身份和 HTTP 健康核验、记录 selected 后释放门禁。切换意图与终态持久化，连接断开后按同一 commandId 查询/重发返回原收据；已接受无终态则 unknown，不重派发。工作台显示只读实际身份，状态刷新失败隐藏旧缓存身份。失败回退与重启对账仍必须独立通过 8.6 门槛。

恢复将历史选择和实际运行分开：recovery-info 只读展示最后/前一个 confirmed selection、未完成切换及记录进程组的观察，不凭 PID 或旧 selected 宣称正在运行。进程意图有记录但缺少 PID 观察、组仍存在或观察不明确时保持只读恢复，不向历史 PID 发送停止信号。reconcile 在取得安装 writer 后按 planHash 记录元数据对账，未知收据仍未知。

recover-plan 显式选择 last/previous，检查保留产物全树摘要及实际 dist 身份，并读取当前数据格式、工作区身份和 Journal 完整性；recover 确认 commandId/planHash/selection/authorize，取得安装 writer 后复核，再以原端口和初始业务 fence 启动所选产物。候选自己的只读存储检查必须在可写服务初始化之前通过，缺少检查协议或格式/Journal 不兼容时拒绝启动，不迁移数据。只读检查不加载资源工厂，不自动重跑业务任务；成功恢复的新进程仍通过已有任务/审批门禁。历史恢复收据只表示那次启动已确认，当前运行身份仍须查询服务；重复已接受命令不再次启动。

当前切换的目标健康失败，仅在旧进程与失败候选清理均可确认、父进程仍有效时尝试保留构建。复核旧产物摘要并由旧版本自己的存储读者检查后，在原端口恢复旧服务；切换收据仍为 failed，actualBuild 为真实恢复身份。任一回退检查失败则保留日志、构建与业务数据，进入 recovery-required；不能用旧版本覆盖新格式或清空结果未知的历史。

启动模式不支持 supervisor 时仍可构建候选，但只报告已构建并给出显式启动命令，不修改 PATH 或全局 npm 安装。托管切换自身不自动触发 npm/GitHub 发布。

10.8 工作台对切换计划显示当前/目标 build、candidate、validation、产物 revision、工作区/数据目录和协议版本；确认默认焦点为取消，忙碌检查持续刷新且保留等待/会话导航入口。浏览器在请求前保存按宿主、会话、候选隔离的安装 ID 与确认命令；请求失败后只读轮询原回执，明确重试只能使用原命令，已接受 unknown 不重发。成功提示要求绑定回执与当前服务实际身份一致。原核心会话因切换后宿主变化不可读时，独立“版本恢复”入口仍读取保存命令，并从 supervisor 持有的正确安装读取最后/前一个选择、未终态意图和进程观察。恢复页面不运行对账或启动；这些操作需要启动终端按新 planHash 显式授权。源码入口不生成伪可执行恢复路径；普通手动模式的候选启动指引经当前会话归属和构建完整性校验后返回准确 argv。


### D10. Web 技术栈与状态架构

推荐验证并采用 React/Vite + shadcn/ui/Radix + Tailwind + TanStack Query/Router/Virtual。继续使用本地 Node 服务与静态资源包，不引入 Next.js/SSR。确切版本在批次 0 验证 React、Node、Vite、类型和打包兼容后固定；候选更换只影响 design，不改变交互 specs。

shadcn 纳入项目的组件归项目维护，不能把其当自动升级黑盒。Radix 负责交互原语，Nekomimi 负责样式与可访问名称；Tailwind 引用语义 tokens，不让扩展注入任意选择器。分栏候选也先通过键盘、窄屏与恢复测试再接入。

状态分层：

| 状态 | 所有者 | 策略 |
| --- | --- | --- |
| Journal、运行、候选、授权 | 服务端 | 唯一事实；命令 ID 去重；确认后公开 |
| 快照、目录、详情 | Query cache | key 包含 host/build、mode、target、session、revision；只读可重试 |
| SSE 当前投影 | 事件 reducer | 严格验证 session/cursor/hash，补读后更新 cache；不将查询缓存变为事实 |
| 会话草稿 | draft store | 以 mode/target/session 区分；页面导航不清空；接受收据后只清已提交文本 |
| 输入密钥 | 短生命周期组件状态 | 不写通用缓存或草稿存储，失败清除敏感字段 |
| 分栏、选项卡、滚动位置 | layout/view state | 按工作台持久化非敏感布局；不触发执行 |
| URL | Router | 仅路由和目标引用，不包含凭证、源码正文或确认操作 |

核心工作台先显式审阅当前 build-plan，再由用户确认依赖安装/构建脚本；独立验证另选通过构建及确切产物摘要、单独授权。Web 后台接受收据使用所属项目的 core-operations Journal，绑定 commandId、会话、候选、目标、宿主与输入 hash；在首次接受前复核计划/产物，重复命令先返回原收据，不因轮询或导航重新执行。原 core-builds/core-validations Journal 仍是进程执行和产物的权威事实，Web 收据只链接其结果 ID。请求取消先持久化再传递给已有有界进程组清理；异常或丢失终态为 unknown，不推断已停止。运行中的 Web 核心操作阻止切换，服务关闭或租约失效发送停止；任务状态读取和取消仅验证会话归属，不依赖已失效的候选目录，避免无法停止在途任务。

核心候选的工作台只读入口绑定核心创造会话，展示准备基线与当前源码差异、目标宿主和构建输入。构建/独立验证记录分别投影各自 Journal，输出只读取受校验附件，不在导航中执行 build-plan、构建或验证。历史 passed 不替代当前产物准入；无终态仅表示未确认（可能仍在其他进程运行或已中断），不由 UI 推断成功。任一验证历史不可读局部显示错误，源码视图仍可读取；正文/日志和任务列表的展示预算明确标出截断与省略数量。

候选差异使用独立只读视图接口，导航不调用编译器、不初始化工厂、不写生命周期事实。视图同时返回当前内容/宿主环境匹配的阶段证据与旧版本证据；绑定会话决定实际开发目录，面板文档也按同一会话定位实例。预览执行仍需明确授权及确切内容 hash，离开预览或迟到响应不能重新挂载实例。

可信扩展模拟与面板预览的取消覆盖工厂初始化，不只覆盖已注册回调。扩展进程启动前后检查信号，启动 RPC 在取消时触发受管进程停止；活动实例只有清理确认后才能记录 cancelled。模拟失败先关闭宿主，面板失败先撤销已附着帧并停止进程，再记录阶段终态。清理确认丢失时状态为 unknown，不用 failed/cancelled 冒充已确认停止；取消前已产生的外部效果不被视为回滚。

模拟与面板预览复用 validation-tasks Journal 接受收据，绑定 stage、commandId、内容/宿主 hash 及输入 requestHash；重复命令只返回原任务。实际 trial/panel 证据链接任务与创造会话，60 秒预算和取消信号覆盖工厂启动、执行与清理。目标目录失效后仍从所属项目读取/取消任务，写目标证据前复核目录身份，禁止为收尾记录重建已移动目录。预览 nonce 仅保留于内存实例，不进入任务日志；读取已完成实例不执行工厂，关闭或宿主重启后返回过期诊断。页面离开后后台任务继续，迟到回执不挂载面板；返回页面只有显式授权打开已完成实例或发起新任务才运行浏览器面板代码。

静态校验作为后台任务：每个 commandId 在所属项目的数据目录中拥有独立操作 Journal，先持久化意图，再以固定候选快照在线程中运行 Compiler API（不 emit、不加载候选工厂）；线程 512 MiB 堆和 60 秒预算。命令绑定会话、目标、候选 revision 与宿主构建，重复命令只返回原任务。运行阶段、诊断、取消请求与终态均来自 Journal；刷新和导航仅查询，不重启任务。取消先记录请求再终止线程，确认退出后才记录 cancelled；无可靠终态且当前进程未持有该任务则显示 unknown，不自动恢复执行。生命周期证据仍绑定被验证的快照，不把旧内容通过计入新版状态。静态验证中的目标阻止核心切换，服务退出/租约失效停止线程；编译通过不代表模拟、预览、应用或宿主验收通过。

Mutation 默认不自动重试。网络确认丢失先查询原 commandId，用户显式重提仍使用原 ID；不能由 Query retry 产生新的副作用。

### D11. 设计系统与扩展 UI

建立语义色（surface/text/border/accent/danger/status）、字体/行高、spacing、radius、shadow、density、motion tokens；保留猫系品牌，默认采用用户选择的清晰高对比、轻量猫系点缀；保留双工作台布局，新版tokens已获样稿评审批准：浅色surface #f8fafc/text #172033/muted #4b5563/accent #5a3ec8，深色surface #131b2b/text #f0f4ff/muted #b7c0d2/accent #beaaff；完整语义色值和状态样稿见docs/validation/next-generation-nekomimi/ui/styles.css及screenshots-high-contrast/。主题资源随包提供且校验，故障回退宿主默认。主题不影响模式或授权事实。

控件覆盖 Button/Input/Select/Dialog/Menu/Tabs/Tooltip/Toast/Badge/EmptyState/ErrorState/ResizablePanel，每项包含等待、失败、危险、禁用、焦点和触屏行为。共享组件不能自己执行业务 API，由应用动作传入。

扩展 slots 带 contractVersion、mode applicability、target scope、resourceRevision 和 instanceId；导航销毁旧实例及订阅。声明式 UI 和受隔离静态组件沿用各自信任边界，不合并为任意宿主脚本。Bridge 验证宿主会话、模式、目标和当前权限，禁止扩展替换停止、授权、恢复、模式和目标标签。

长列表虚拟化保留稳定 item key/锚点，动态测量代码块和图片高度。程序布局变化不关闭跟随；只有用户向上阅读关闭跟随。历史视图只展示保存数据，互动面板显式打开，不因虚拟行重新挂载而执行副作用。

10.7 实现使用共享的 SSE/分页控制器，最多保留 180 行数据，TanStack Virtual 只挂载可视区域和 overscan 内的行正文；轻量行容器保留稳定身份及最近测量高度，作为分页和动态布局的原生阅读锚点。焦点和选中文本涉及的行暂留挂载，选择期间暂停自动翻页。滚动补偿由单一协调器负责，虚拟器关闭二次尺寸补偿；交付定位结束或用户返回最新时交还控制。历史导航使用固定高度，不因失败提示改变阅读视口。工作/创造布局各持有当前会话唯一的 SSE/分页控制器，通过 Context 供时间线、证据侧栏和更多菜单共享；按会话 key 卸载旧订阅，组件不能各自重复建立长连接而占满同源连接额度。宽窄屏保持同一分栏组件树，仅改变布局与可见性；分栏比例按工作台保存并恢复。

### D12. 兼容退出与可验证交付

新格式显式命名，新 home 数据区域独立；旧格式检测在加载工厂/创建 Journal 前执行。安装文档解释不兼容，不提供自动迁移入口。用户可以主动保留旧安装查阅旧历史，但新宿主不调用旧代码。新格式内的重启、分支和恢复仍必须工作，“不兼容旧版”不是取消持久化保证。

旧格式的全局兼容承诺以当前支持格式范围解释；本次 delta 明确改变 SDK、候选和主要交互。归档前检查与剩余主规格的相互约束，保留未变能力如文件保护、headless 导出、本地服务鉴权、进程宿主和包完整性；如发现真实外部行为冲突，必须先扩充相应 delta，而非在实现中静默删能力。

## Risks / Trade-offs

- [Durable 的便利性与证据所有权冲突] -> 使用公开 Storage 到 Journal 的单提交映射；未证明的接入保持未交付，不自动回退或牺牲唯一权威。
- [Pi 包的源码能力与发布资产不一致] -> tarball exports/worker/WASM/install smoke 与版本 manifest；不读取 reference 补运行依赖。
- [广泛重构导致回归] -> 先冻结现有关键 fixture，按批次切换；保留保护行为，替换过时布局断言而不删除风险场景。
- [双会话交接非原子] -> 单源协调、稳定 ID、幂等目标接收及元数据恢复；不声称 exactly-once 外部工具执行。
- [普通 shell 可越出目录] -> 受控文件服务执行路径校验，可信 shell 授权说明；不将逻辑模式隔离包装成 OS 沙箱。
- [前端框架增加依赖与体积] -> 最小组件切片验证、精确版本、按需加载和包资产检查；不批量加入未使用组件。
- [虚拟列表损伤阅读体验] -> 图片/字体/面板延迟高度、焦点、选择文本、分页锚点的浏览器回归，不能只测节点数量。
- [核心自修改导致停机] -> 独立构建、安装级锁、空闲门禁、不可变产物、健康检查与旧可用版本；不兼容状态阻止回退执行。
- [模型操作可见但不完全可记录] -> 发布每种 operation 的支持矩阵，未通过证据门槛不启用。
- [清理旧兼容误删数据] -> 默认新目录，旧目录只诊断，hash 对照确保拒绝前后不变。
- [真实性能没有收益] -> 同条件基线记录 schema/input 体积、准备延迟、内存与交互指标；不由 token 估计推断成本和质量。

### 模型配置工作台实施补充

模型用途页面独立于能力管理，工作/创造/辅助/自动命名/压缩/交接/分类/图片分别显式确认，只提交所选 purpose 与审阅时的 profiles revision；冲突更新权威快照但不自动重试。默认物理模型按实际宿主设置报告配置状态，已知模型、已绑定 profile 与可用凭证分别显示。同一模型的多份配置各自返回不含凭证值的状态，不能因另一份 profile 有密钥而显示本配置可用。

### 能力与候选管理实施补充

能力目录按创造目标作用域读取，提供范围/类型筛选及来源、发现/活动版本、权限、遮蔽和诊断。导航不校验、不加载工厂；新授权、静态校验、重载和用户目录写入需绑定创造目标并显式确认。确认时冻结请求及展示版本；资源内容与授权修订冲突返回 409，拒绝后保留反馈、不自动重试。加载收据只读轮询，pending 不显示已生效。

候选管理分别显示已选择与已加载版本。启用确认包含内容摘要、目标、所需/新增权限及授权/活动修订；回退只读取得不可变旧内容的实际权限并核验旧 hash、活动修订和授权修订。操作仅作用于绑定的开发目标，不等于安装到工作项目。导出确认目标路径与内容摘要，已有文件拒绝覆盖；失败保留路径和错误，用户主动刷新后重新审阅。

MCP 管理页按目标读取授权状态、已加载连接与保存的诊断目录。OAuth 开始/断开确认携带资源 hash；配置变化在远端发现前拒绝。授权回调不隐式启用资源；pending 只读轮询，授权链接仅保留当前页内存，刷新后提示完成原回调或显式断开重新开始，不自动重发授权。

能力包管理导航仅读目录；候选与回退检查均显式执行静态预览，权限、范围、摘要和安装修订展示后再确认。安装/回退确认绑定内容及安装修订；卸载绑定已审阅安装版本，导出绑定内容且通过排他发布防止并发覆盖。缓存清理明确列出请求丢弃的候选，最终保留仍由安装/回退/历史/工作流引用决定并报告实际计数。

持久工作流管理按工作/创造模式及目标显示定义与记录，启动/迁移提交已显示的定义版本。等待记录出现不等于执行租约释放：workflowBusy 在收尾期间维持只读轮询及操作锁，取消保持可达；未知结果必须显式核对，不在导航时恢复。扩展进程终止与宿主服务排空分离，回调归属的在途 RPC 记录完成后才返回失败/释放 Journal，防止取消时迟到工具证据写入已关闭文件。

### 10.9 定制集成迁移补充

旧入口和无依赖管理模块、专用样式已删除，主题资料类型拆为独立模块。旧 Timeline 及其单元测试暂未移除：`web-readable-presentation` 主规格的按轮次组织、重复成功状态合并及辅助调用按需查看仍需在新时间线补齐并迁移验证，不能用旧组件测试证明新工作台满足这些保证。

### 10.9 轮次阅读契约收编

正式工作台通过 `readableTurns` 对当前历史窗口生成只读展示投影，只合并相邻且 runId 相同的记录；缺少身份、分页截断和非相邻同名运行不合并。第一条原始记录保留为稳定滚动锚点，回答到达后不替换锚点身份。正常调用摘要折叠、空成功结束记录合并，扩展结果及附件不因文本为空而丢弃。失败/取消/未知的结束记录直接显示；没有结束记录的末次异常调用仍显示，已恢复的尝试由调用证据访问。

每轮的证据入口携带原始 runId，打开后直接选择对应运行；全局证据入口仍默认最新运行。所有分组、展开及证据读取不发执行命令、不修改 Journal。旧 Timeline 展示测试迁入新投影，旧 Timeline、RuntimeViews、ToolCard、Artifact、Brand 和无人调用的 PanelManagement 移除，共享 CustomPanel 保留。

### 11.1 未变面板展示契约补齐

当前窗口已连接后收到的新结果保留一次实时展示资格；时间线进入前已经收到的记录不算新结果。首次展示前只读刷新面板目录，核对保存的 resourceId/revision/panelId、模式及当前授权，避免候选刚加载而客户端目录仍旧导致错过展示。一次资格由时间线持有，与具体虚拟行的挂载生命周期分离；目录迟到时再次检查是否仍在实时阅读，卸载或隐藏时取消展示回调。

刷新、断线后快照补读、历史分页、离开页面后返回以及虚拟行重挂均不自动执行保存面板；隐藏扩展期间到达的资格会被消费，重新显示时仍需用户打开。正常 UI 更新不销毁已有实例或输入，切换到历史快照时关闭实时实例。当前成功组件外不重复显示文本回退，加载失败仍由共享 CustomPanel 保留可读内容与恢复入口。以上恢复 `custom-web-panels/故障与历史回退` 的未变保证，不通过新增 delta 弱化原行为。

### 7.8 项目候选受控交付补齐

综合验收发现现有 candidate-activate 只作用于独立开发目录；交付卡仅记录版本说明，无法完成默认项目范围的工作使用。补齐该缺口，不以用户级包替代默认项目交付，也不扩大工作模型的管理工具权限。

项目交付从已确认的创造→工作 handoff 快照发起。只读审阅返回来源 candidate/hash、源与目标绑定、目标宿主、请求权限、目标授权修订及活动修订；未确认的导航不复制或加载代码。明确授权后，来源准备与类型验证通过的文本和二进制原始字节写入目标 Candidates 内容寻址区，重新绑定目标 resourceId，保留来源/目标/交付 ID/内容摘要的 Journal 事实，不修改开发文件或直接覆盖用户项目文件。目标处于 busy 时拒绝并要求空闲后重新审阅，旧调用不被热替换。

安装命令具有稳定 commandId 与计划摘要；在调用工厂之前持久化意图。重复命令只返回已记录状态；意图存在但没有可靠终态时为 unknown，重启、页面恢复和查询均不得重跑工厂。应用结果以真实目标加载收据和活动摘要为准，历史交付快照不改写。后续版本重复审阅流程，停用撤销命令、工具及其提示，原工作草稿和双会话历史独立保留。本补齐属于 7.8/11.4 的原有端到端门槛，完成存储切片不表示整个交付流程完成。
