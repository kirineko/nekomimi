## Context

见 proposal.md。当前 `App` 静态导入可选面板；`Customization` 同时导出常驻的 `ExtensionInteractions`，`WorkspacePanel` 导出共享上下文，因此只把组件改成 lazy 不一定切断静态依赖。现有主 JS 约 499 KiB（超过十进制 500 kB）；语法高亮已独立 Worker 和语言分块。

`Timeline` 无条件渲染返回最新，`App` 在 historyMode 再渲染一个。`useSession` 已有 180 行窗口、请求 generation、双向边界和 SSE 历史冻结；`App` 的底部检测只进入历史模式，未负责可靠退出。`Composer.send` 期间禁用 textarea，finally 仅恢复 pending，没有焦点恢复。

## Goals / Non-Goals

**Goals:** 降低聊天启动负担；集中导航状态与可见性；使连续输入和用户自主焦点迁移兼容。

**Non-Goals:** 不改变 Journal 权威性、分页协议或运行恢复语义；不延迟常驻扩展交互订阅；不将浏览状态持久化为会话事实；不引入自动发送队列。

## Decisions

### 1. 以功能边界拆分可选界面

将定制管理、文件与变更、检查器和导出组件作为异步入口。共享类型、上下文及常驻扩展交互移至轻量模块，避免反向导入管理组件使拆分失效。聊天 Markdown 与主题基础设施仍保持可用，语法高亮保留既有实现。

每个入口使用局部 Suspense/错误边界，加载占位保留关闭和焦点管理；重试需重新建立可重试的加载状态，不能仅重绘已经缓存失败的 lazy 实例。关闭或切换入口后，迟到完成只填充模块缓存，不改变打开状态。沿用原组件草稿生命周期，不因重试重新挂载整个 App。

先验证实际网络请求再决定是否需要 Rolldown 公共分组；不把所有依赖合为一个 vendor 包，不调整告警阈值。保持 Vite 8.3.0 公开配置接口，手动分组如有必要须回归模块副作用顺序。

### 2. 唯一的最新入口与两端分页

App 在滚动容器外、输入区上方管理唯一返回入口，避免其参与时间线高度和锚点计算。Timeline 顶端仅更早、底端仅较新，无操作时不留空容器。控件使用主题语义变量、小尺寸胶囊样式、明确焦点与禁用反馈；reduced-motion 下取消装饰动画。

以三个事实判断：窗口是否包含最新记录、是否处于底部容差内、是否有历史冻结期间的新内容。只有三者共同确认处于最新时退出浏览模式；旧窗口的物理底部不等于会话末尾。主动滚到底部但存在未同步更新时取最新窗口确认，防止把冻结的尾部误当最新。程序性锚点恢复不能被误认为用户主动恢复跟随。

点击返回最新沿用独立 scrollRevision 强制定位，即使 cursor 不变。分页串行；返回最新可取代旧分页但自身重复点击去重，失败继续提供同一入口重试。错误绑定当前会话和请求 generation。SSE 只在存在尚未展示的内容更新时标记新消息，不把单纯连接/状态通知视为新消息。

替代方案为自动无限滚动，但裁剪、布局变化和触底自动加载容易竞争；本轮保留两端显式分页，减少入口而不改变用户触发方式。

### 3. 提交拥有有限的焦点恢复权

记录提交来源、当前会话/提交身份及焦点迁移意图。请求结束且 DOM 已恢复可编辑后，在未主动转移目标的前提下执行 focus({preventScroll:true})；成功清空已提交草稿，失败保留文本和合理光标位置。区分禁用造成的浏览器失焦与用户 pointer/keyboard 主动转移，不能仅凭 activeElement 是 body 判断。

会话创建导致的内部选择更新属于本次提交；用户主动切换会话则撤销旧提交焦点恢复权。弹窗、其他控件或页面失焦也撤销自动恢复，防止异步响应抢焦点。运行完成不触发恢复逻辑，busy 期间保持可编辑而限制再次发送。

不采用每次渲染 autofocus，也不在 finally 内立即聚焦仍处于 disabled 的元素。

### 4. 验收口径与规格关系

以同一生产构建、冷缓存、固定空聊天夹具记录 minified 原始字节与 gzip 字节，首屏统计实际请求 JS（包括同步依赖与预加载），按需功能另行统计。保留 500 kB 告警阈值，要求最大 JS 分块不超限且首屏总量较基线下降。无预设未经验证的优化百分比。

新增工作台约束补充前置 history-navigation，不取代其锚点、只读回放与有界窗口要求。前置 change 未同步主规格，归档时先处理前置变更；本轮不修改它的已验收任务。

## Risks / Trade-offs

- [共享模块让拆分失效] → 同时检查静态依赖与冷启动网络，专用分块不得提前请求。
- [异步弹窗缺乏焦点容器] → 加载壳与完成界面使用统一关闭和焦点边界，覆盖取消与失败重试。
- [跟随恢复与锚点竞争] → 区分用户滚动及程序性定位，覆盖字体/图片高度变化和 SSE 竞态。
- [恢复输入意外唤起键盘或抢焦点] → 仅由有效提交恢复，验证触摸视口、页面失焦和主动切换。
- [打包路径和缓存失败] → 在安装 tarball 中逐一打开入口，模拟一次性分块失败并重试；持久缺失保留关闭与错误说明。

## Migration Plan

1. 记录构建基线，拆分可选功能并验证真实首屏请求。
2. 集中导航与焦点状态，更新针对旧重复按钮的浏览器断言。
3. 类型检查、相关单元/浏览器和安装包验收后记录结果，再标记任务完成。
4. 无数据迁移；如需回退可恢复同步导入和交互实现，不修改历史或运行事实。提交、归档与发布不在本次实施范围。

## 用户补充范围

自动跟随由用户滚动意图控制，消息和 ResizeObserver 布局变化负责在跟随模式下定位底部，程序性 scroll 事件不改变模式；历史模式继续恢复阅读锚点。覆盖新会话首条消息、持续 SSE、较晚素材、手动向上及返回后持续跟随。

资源层保留两级发现和项目同名优先，统一 resource_write 的 scope 默认 project；显式 user 沿用 userWrites 授权与 CAS 内容写入。候选属于工作区内开发暂存，不引入第三种用户能力作用域；用户级交付使用用户资源写入或已有 capability package 的 user 安装。SDK 报告实际 host home、资源路径和流程入口，UI 添加用户级筛选与卡片范围。测试使用两个临时工作区及一个临时 home，不写真实用户目录。

## Review 修复边界

自动挂载只接受当前实时 SSE 新行，不以曾提交过的 runId 推断历史为实时内容。读取历史窗口清除资格，浏览历史时的流更新不授予资格；历史面板由用户明确打开。渲染要求快照会话 ID 与当前选择一致；历史读取后以快照 cursor.seq 为回放边界，迟到 SSE 不重新授予已读行自动挂载资格。启动的一般加载错误允许修复后重载，degraded 仅保留清理失败导致的未知状态。loaded 证据来自 active.extensions 的实际版本，不来自发现目录。
