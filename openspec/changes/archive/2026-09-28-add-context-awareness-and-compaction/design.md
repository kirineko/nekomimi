## Context

见 proposal.md。当前 `context.ts` 从 Journal 的 context.add/tool.result 等事件生成有序节点，`provider.ts` 和 `customization/adapter-provider.ts` 都调用该投影并记录 context.view；尚无压缩检查点。`runtime.ts` 已有模型请求循环、工具终态门禁、取消和 64 轮预算。`RecordedCall` 是模型证据入口，辅助请求已有用途划分，须扩展而非另建隐藏摘要客户端。

Web 已有快照/SSE、命令补全及 Composer 底部控制区，历史窗口有界，不能用页面上可见行数计算上下文。`cli.ts` 在 startWeb 后仅输出 app.url；程序化 startWeb 被大量测试使用。`test/context.test.ts`、`test/customization-provider.test.ts`、`test/cli.test.ts` 可扩展为定向验收入口。

参考本地 `reference/dsh/packages/llm/token-meter` 的请求锚点与分类估算、`ui-conversation/.../ContextMeter.tsx` 的交互、`compaction-basic/src/config.ts` 的 0.8/0.16 默认策略；pi 的 `coding-agent/src/core/compaction/compaction.ts` 提供 usage 加增量及近期保留思路。参考 checkout 不等于本项目已固定依赖的公开 API，实施不导入其内部 session/compaction 模块。

## Goals / Non-Goals

**Goals:** 以同一源上下文支持统计、压缩规划和实际请求；压缩可取消、可追溯、原子生效；浏览器操作紧凑且沿用主题；启动行为可测试。

**Non-Goals:** 不以估算冒充计费 token 精度，不根据 base64 字符数计图片 token；不压缩系统指令和工具 schema，不实现独立工具输出剪枝、自动溢出重试或新 AgentHarness；不改动无参数 CLI 行为。

## Decisions

### 1. 共享测量与明确估算来源

新增宿主测量层，输入为有效 ContextView、当前模型身份/容量、提示片段、工具 schema 及可用的匹配 usage。输出包含 contextRevision、模型/容量、三类估算、总量、测量方式与锚点；协议字段可选，旧客户端不必立即消费。统计和压缩决策复用该层，服务端负责计算，客户端只格式化。

三类按互斥来源分类：有效系统提示及规则指导、工具 schema、对话节点（含摘要、工具结果及图片估算）。先实现确定性、对中文和 JSON 不明显低估的有界估算并用混合语料验证；图片使用已声明模型规则，缺少规则时标记近似与不确定性。usage 校准仅在模型、提示、schema、协议投影身份匹配时使用，并按当前内容变化估算增量；压缩后旧大上下文样本失效。Provider 自定义序列化增加无法精确解释的开销时保留近似状态，不能假装宿主统计等于服务端 tokenizer。

总量与三类值都带约数标识，浮层不显示底部说明文字，估算口径保留在用户文档中；分段条用分类占比划分总占用。容量未知时不显示假百分比，禁止容量驱动的自动决策。估算读取不激活资源、不调用扩展工厂。未运行或资源待加载时使用可确认的活动配置，尚不能确定的定义显示待估算。

替代方案是浏览器按文本长度计算：会遗漏隐藏历史、工具 schema、图片和 Provider 转换，故不采用。

### 2. 非破坏性检查点投影

新增版本化 compaction.started/completed/failed/cancelled（名称实施时保持一致）证据；只有完整持久化的 completed 提交改变 ContextView。检查点包含源语义 revision、被替换节点引用和摘要、保留边界、前置检查点、摘要 artifact、模型调用关联及前后测量。revision 比较针对有效上下文，不因摘要自己的 attempt 事件追加就误报冲突。

重放先解析有效检查点链，再投影摘要与未替换节点；新摘要可以涵盖旧摘要，但需保留递归来源，不能重复叠加。时间线继续读取完整事实，导出保留原记录；原始未配对调用和未知工具结果恢复必须独立读取事实，不能因压缩隐藏待恢复操作。摘要作为明确标识的历史数据加入普通上下文，不提升为系统权限或覆盖当前规则。

按完整用户/助手/工具交互及 Provider 协议依赖选择闭合前缀，保留最新用户请求和未解决调用；切点允许超出近期目标以保护完整性。未知协议不能证明安全切点时停止压缩并说明原因。模型切换继续遵守已有 historyCompatibility 校验，摘要不绕过协议不兼容门禁。

### 3. 请求前策略与有界执行

默认 auto=true，ConfigStore 增加向后兼容的配置；设置面板提供一个主题化开关，CLI 配置输出和 SDK 文档说明，旧配置缺字段取默认值。操作在原有活动任务锁内进行，自动检查覆盖首请求和每次工具循环后的主请求，摘要路径不递归检查。

设窗口 W、实际请求输出预留 O、安全余量 S=max(1024, ceil(0.02W))，可用输入预算 B=W-O-S；触发阈值 T=min(floor(0.8W),B)。保留近期目标 K=min(floor(0.16W),floor(0.5*max(0,B)))，它是目标而非强制切断界限。B 非正时直接报告模型/预算配置不可用，不偷偷降低输出上限。上下文达到 T 后规划压缩；成功必须严格缩小，自动继续请求还须低于 T，以避免连续立即压缩。固定提示、摘要和不可分尾部仍放不下时停止并给出可操作说明。

摘要默认使用当前主模型与相同协议路由，以独立 compaction 用途记录并显式绑定主配置，不误路由到命名或辅助配置。摘要输出预算上限为 min(8192, 模型输出能力, 本次显式输出限制)，输入须给摘要指令预留空间。超长待摘要范围按安全单元分块、逐步合并，每个子请求也必须适配容量；所有子结果仅在最终检查点提交时一起生效。取消随时传播；每次检查最多一次规划流程，不对无缩减结果反复调用。

摘要请求复用兼容且有用的稳定前缀，关闭工具执行；即使 Provider 返回工具调用，也不能执行或作为有效摘要。只有 completed 的非空文本通过预算、节点配对和版本检查才生效。网络重试最多沿用既有有界 transport 策略；输出耗尽、不完整和语义无效结果不自动扩大预算或重试。压缩额外成本单独展示在证据中，主任务轮数默认值不变。

### 4. 手动命令与用户反馈

`/compact [保留重点]` 为宿主保留命令，执行前于普通用户消息入模路径分派，避免把控制命令当作新任务。命令目录与冲突规则一起更新；Web/CLI 共用操作，commandId 去重、服务级互斥和取消沿用已有机制。空会话或无安全前缀不调用摘要；繁忙直接拒绝，不新增后台排队。

自动压缩在当前任务内显示“正在整理上下文”，成功后继续原任务；手动压缩独立结束并显示约数变化。失败简短说明保留原上下文，详情进入已有证据入口。压缩期间可保留和编辑下一条草稿，但不能并发发送；取消不得清空草稿。界面不展示整段摘要或原始检查点 JSON。

### 5. 占用浮层与状态投影

Composer 底部增加小型圆环和百分比，点击打开三类明细，保留约数标识及自动压缩状态；自动开关在现有设置中集中管理。颜色、字体、圆角和间距使用当前主题变量，避免默认表单及独立顶栏按钮。

Snapshot/Update 增加可选上下文统计与压缩状态，按 sessionId 和 revision 隔离，分页不覆盖当前统计。读取恢复不发起摘要；节流测量和复用相同 revision 结果，避免每个流式字符全量扫描历史。未提交草稿不计入持久上下文估算，界面说明为“已提交内容的下一请求估算”，实际发送前再测量包含新输入的请求。

### 6. CLI 浏览器启动

浏览器打开属于 `web` CLI 编排，不放进 startWeb。成功监听并注册退出处理后打印原有 URL，再用跨平台打开适配器传递 app.url：macOS open、Windows 系统 URL 打开机制、Linux xdg-open。使用参数数组和适当平台转义，不拼接不可信 shell 命令；不新增运行时依赖为优先选择。连接 token 继续在现有 URL fragment 中，错误提示不回显完整启动命令。

`--no-open` 完全绕过打开动作；打开进程失败或超时不影响服务，简短提示使用已输出地址。每次 CLI 启动仅一次，不声称已确认浏览器页面加载成功。适配器可注入测试桩，程序化服务不打开浏览器；现有启动测试与安装包脚本补 --no-open。

## Risks / Trade-offs

- [估算误差与自定义 Provider 开销] → 标记来源、匹配 usage 校准、安全预留，验证中文/JSON/图片及缺少 usage，不承诺精确计费。
- [摘要丢失细节或指令提升] → 保留近期完整交互、结构化摘要要求和原记录引用，将摘要标为历史数据；不是无损压缩。
- [摘要本身超限或无缩减] → 安全分块与有界合并、提交前测量，无法收敛保留原投影并终止，不循环重试。
- [压缩改变缓存前缀并有额外费用] → 接近阈值才触发，复用稳定前缀并分别记录摘要成本；不承诺一定节省每次运行费用。
- [崩溃/迟到请求误提交] → 语义 revision 检查、提交事件原子生效、取消检查、重启仅恢复完成的检查点。
- [浏览器自动打开影响测试和远程环境] → --no-open、注入适配器、失败不退出；跨平台原生命令需分别验证。

## Migration Plan

新增事件和协议字段为可选扩展；无检查点会话保持原行为。先落地确定性测量与检查点投影，再接入摘要策略、命令和 UI，最后补 CLI 启动及文档。用假模型和隔离目录完成故障、取消及安装包验收；不依赖真实凭证。

关闭自动压缩只停止后续自动操作，不撤销已提交检查点。回退旧程序不会删除 Journal，但旧版本忽略检查点可能重新发送完整历史并触及容量限制，须在文档说明，不能宣称语义无差别降级。
