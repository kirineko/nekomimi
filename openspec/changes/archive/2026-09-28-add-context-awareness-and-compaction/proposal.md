## Why

用户无法判断当前模型上下文的占用构成，长会话没有自动或手动压缩入口，容易在任务中途触及容量限制。`nekomimi web` 启动后还需手动复制 URL，增加了本地使用步骤。

## What Changes

- 输入框底部增加主题一致的上下文圆环、百分比和点击展开明细，区分系统提示词、工具定义、对话消息；显示下一请求估算及当前模型容量，不混入累计计费用量。
- 增加共享统计与非破坏性压缩机制：原始 Journal、聊天历史和完整工具证据保留，后续模型上下文使用版本绑定的摘要检查点及近期完整交互。
- 默认开启 autocompact，在每次主模型请求前检查压力，以 80% 容量与扣除输出预留后的安全边界中较低者触发，支持关闭；不改变已有 128K 输出上限与 64 轮默认值。
- 新增内置 `/compact` 与可选保留重点，接入现有补全和运行互斥、取消、证据机制。压缩成功仅报告结果，不自动发送新的任务。
- `nekomimi web` 在监听成功后自动打开实际连接 URL，支持 `--no-open`；失败保留服务及手动访问地址。
- 非目标：不删除或重写历史，不新增任意模型控制命令，不引入累计费用仪表盘，不迁移 dsh/pi 整套宿主，不新增大结果剪枝策略；本轮不做上下文溢出后的自动重试，不将 `Response incomplete` 解释为压缩触发依据。

## Capabilities

### New Capabilities
- `context-occupancy`: 共享上下文估算、来源与模型容量、主题化明细交互。
- `context-compaction`: 自动/手动压缩、闭合区间、摘要检查点、并发及失败恢复。

### Modified Capabilities
- `prompt-context-provenance`: 增加摘要与原始节点的来源链及投影一致性约束。
- `local-web-service`: Web 子命令自动打开浏览器和可关闭的启动行为。

## Impact

- 对应 `spec.md` §3.1、§7.3–7.4 和 §8 的上下文可观测性、非破坏性压缩和浏览器工作台方向；历史研究中的剪枝及溢出重试保留为后续范围。
- 涉及 `context.ts`、`runtime.ts`、Provider/RecordedCall 边界、配置与会话命令、服务端快照/SSE、Composer 和 CLI；增加 Journal 检查点事件及可选协议字段，旧历史保持可读。
- 默认摘要使用当前主模型，单独记录用途及有界预算，不混入主对话输出；内置和自定义 Provider 使用同一压缩投影。参考本地 dsh 的测量/交互与 pi 的近期保留，不依赖其私有 API 或引入新框架。
- 补齐 SDK/文档中的上下文统计口径、压缩边界及命令说明，测试不依赖真实模型密钥，不在自动化测试中打开真实浏览器应用。
