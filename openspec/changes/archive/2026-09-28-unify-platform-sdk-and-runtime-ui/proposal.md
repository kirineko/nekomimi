## Why

现有平台能力分散在 V1/V2 文档和公开类型中，已交付能力仍被标记为实施中，导致用户与 Agent 难以找到完整、可信的开发入口。用户要求改变整体 UI 风格时，扩展只能创建局部 iframe；面板又泄露原始 JSON、重复回退和内部标识，无法直接交付用户期望的视觉效果。

## What Changes

按以下顺序实施，统一作为一个 change 交付：

1. 扩展运行时 UI 边界：声明式全局主题覆盖字体、字号/字重/行高、配色、间距、圆角、阴影、气泡、背景素材、动效和紧凑度；增加会话头部、消息/工具结果、输入框工具栏、侧栏挂件及独立页面扩展区域，提供受控草稿、命令、导航和状态交互。
2. 系统整合现有开发平台：统一 SDK 公共类型、能力目录、脚手架、示例和安装包文档，以开发任务组织，不再按 V1/V2 划分；保留旧清单和类型的兼容适配以及底层协议版本。覆盖扩展、Skills/Rules/MCP、Provider、工作流、状态、能力包和 UI。
3. 修复面板展示链路：当前运行直接显示已授权组件；历史和导出提供可读摘要；JSON、哈希、内部 ID 等默认进入开发详情。完善加载、失败、重试、收起/重新打开、自适应高度和插件缺失回退。
4. 将真实宿主内主题切换及命令到面板的完整体验纳入验收，明确区分静态检查、模拟试验、独立预览和宿主集成验证。

非目标：任意注入宿主 DOM/CSS/脚本；替换整个聊天壳、会话列表或输入框本体；允许插件覆盖授权/停止/恢复入口；离线执行插件；新增市场、TUI 或发版操作。本轮不删除旧协议或改写历史 Journal。

对应 `spec.md` 第 3 节观测与证据、第 8 节 Web 与稳定产品协议、第 9 节定制生态、第 11 节工作流、第 12–13 节交付与验证；末尾历史交付记录保留历史属性，现行能力入口统一更新。

## Capabilities

### New Capabilities
- `runtime-ui-extensions`: 全局风格、受约束扩展区域、宿主交互桥接、多插件组合和恢复默认界面。

### Modified Capabilities
- `extension-runtime`: 统一公开 SDK 命名与能力发现，保留旧契约兼容并按真实能力校验。
- `customization-development`: 统一开发文档、任务式脚手架和完整能力目录，建立 UI 宿主验收证据。
- `custom-web-panels`: 用户内容优先、当前与历史展示区分、生命周期、自适应布局及可读离线回退。

## Impact

涉及 `src/extensions.ts`、`src/customization/{types,contracts,sdk,panels,panel-document}.ts`、扩展进程与能力包注册/构建/授权链路；Web 根布局、主题、Composer、Timeline、CustomPanel；session projection、HTML 导出与开发工具。更新 `extension-docs/`、README、相关现行说明和安装包验收。

新增 UI 能力必须单独声明与授权，现有插件不能静默获得。主题、素材和扩展配置需要持久化及版本关联；运行副作用继续经过现有记录入口。预期不引入强制外部 UI 框架或联网依赖；示例素材/字体随包交付并标注许可。兼容适配不承诺未经验证的历史包行为，须通过安装包回归验证。
