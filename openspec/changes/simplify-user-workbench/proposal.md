## Why

`next-generation-nekomimi` 交付的新工作台把内部实现信息直接摆在用户面前。顶栏显示构建 hash，常驻“版本恢复”入口；页面有 `WORK MODE`/`INSPECTOR` 英文眉标和 `idle` 原始状态；空会话就展示交接确认状态和若干“刷新/重新读取”按钮；导航里管理链接和会话列表混在一起；右侧详情栏常驻占据四分之一宽度。此外，样式层故意不引入 Tailwind preflight，链接显示为浏览器默认的蓝色下划线，页面看起来像资源没加载完。服务端 CSP `style-src 'self'` 还会拦截 Radix Dialog 动态插入的 `<style>`，每次打开对话框控制台都报错，滚动锁失效。现在旧页面已经全部删除，兼容理由不复存在，适合在归档后统一收敛为面向用户的界面。

## What Changes

- **样式与安全基线**：引入 Tailwind preflight 和全局排版基线，去掉浏览器默认的链接、按钮和分隔条样式。静态页面 CSP 改为每次响应生成 nonce，并通过 `get-nonce` 注入 Radix 的动态样式；不放宽为 `'unsafe-inline'`。缺少或已失效的连接授权时显示整页引导，取代多处零散报错。
- **信息分层与开发者视图（新能力）**：界面信息分为三层：常驻任务流（L0）、按需打开（L1）、开发者视图（L2）。新增本地、非权威的“开发者视图”开关，默认关闭。构建 hash、运行 ID、原始状态码、内容 hash、交接确认状态、手动刷新按钮和英文眉标只在开发者视图中显示。开关只影响展示，不改变请求、授权或证据。
- **顶栏精简**：**BREAKING（UI）** 顶栏只保留品牌、工作/创造切换、运行状态与停止、`设置` 菜单。“版本恢复”和运行版本移入设置菜单；只有服务版本无法确认、正在切换或处于开发者视图时，才在顶栏显示状态提示。“更多操作”更名为“设置”，并收纳外观、模型、基础设置、高级管理、导出、版本恢复和开发者视图开关。
- **布局简化**：**BREAKING（UI）** 工作台默认两栏：会话导航和主区。详情（变更、文件、证据、上下文、扩展 slot）改为可开合抽屉，由会话头部的“变更”“详情”按钮或文件定位打开。管理入口从会话导航移到设置菜单和设置总览页，导航只保留“新任务”和会话列表。
- **会话页面精简**：会话头部只保留标题、用户语言的状态、“变更”入口和 `…` 菜单，菜单内含调用证据、上下文、交接、导出、删除。交接表单从常驻按钮改为菜单触发；交接/交付卡只在存在记录时显示。手动刷新按钮由自动失效刷新取代，失败时才显示“重试”。
- **创造工作台精简**：创造导航默认只显示开发目标和候选；原始能力清单（`openspec-* · enabled`）、阶段码和目标宿主 build 移入开发者视图或候选详情。
- **文案与术语**：建立用户术语表，替换“投影、idle、可靠状态、宿主、unknown”等内部词，所有原始值保留在开发者视图或证据详情中。
- **测试迁移**：浏览器测试通过统一的 `enableDeveloperView` 夹具访问 L2 信息，按新的入口路径迁移选择器，不删除既有风险场景。

### 非目标

- 不删除或削弱任何证据、上下文、交接、核心切换、恢复能力及其服务端接口；只调整入口和默认可见性。
- 不新增模型调用、不改变 Journal、协议、SSE 或命令幂等语义；开发者视图不是权限边界，也不进入服务端。
- 不重做设计 tokens 色值（沿用已批准的高对比明暗样稿），不引入新组件库，不做 TUI。
- 不处理 Windows 平台验证，也不发版。

### 与 spec.md 的对应

- §8.2 浏览器的首要功能：以任务输入、结果和变更为主路径，证据检查按需可达。
- §8.3 本地服务边界：静态资源 CSP 与连接授权的用户引导。
- §3 可观测性：证据入口保持可达；L2 信息默认隐藏但仍可一键查看，不重建、不伪造。

## Capabilities

### New Capabilities
- `developer-view`：定义 L0/L1/L2 信息分层、开发者视图开关的持久化与非权威性，以及每类开发者信息的归属和可达性。

### Modified Capabilities
- `web-design-system`：修改“双工作台布局与导航”（默认两栏 + 详情抽屉）；新增样式基线（preflight、链接/按钮基础样式）和用户文案要求。
- `web-task-workbench`：修改“工作与创造双工作台”（详情按需、管理入口迁移）；新增会话头部精简菜单、交接按需展示、自动刷新取代手动刷新等要求。
- `compact-header`：修改“统一更多菜单”，改为“设置”菜单并收纳版本恢复、管理入口与开发者视图开关；运行版本仅在异常或开发者视图中显示。
- `context-occupancy`：修改“主题化明细入口”，入口位于输入区状态行或会话菜单，分层明细属于开发者视图。
- `web-evidence-inspector`：新增“证据入口默认收起且可达”，规定调用证据和原始字段的入口位置，并规定开发者视图不改变证据内容。
- `web-customization`：修改“分类导航与渐进展开”，创造导航默认只显示目标与候选，管理入口移到设置总览。
- `local-web-service`：新增“静态页面内容安全策略”（nonce 化样式）与“连接授权失效引导”。

## Impact

- **前端**：`src/web/styles/tokens.css`、`src/web/main.tsx`、`src/web/v2/shell.tsx`、`more-menu.tsx`（重命名为 `settings-menu.tsx`）、`core-status.tsx`、`router.tsx`、`routes/work-nav.tsx`、`routes/create.tsx`、`routes/work-session.tsx`、`routes/details.tsx`、`routes/session-catalog.tsx`、`routes/handoff-*.tsx`、`routes/settings.tsx`，以及新增的 `src/web/v2/state/developer-view.ts`、`src/web/v2/dev-only.tsx`、`src/web/v2/routes/session-menu.tsx`、`src/web/v2/routes/settings-hub.tsx` 和 `src/web/glossary.ts`。
- **服务端**：`src/server/app.ts` 静态响应 CSP 与 index.html nonce 注入，`src/web/index.html` 增加 nonce 占位 meta。
- **依赖**：将 `get-nonce@1.0.1` 从传递依赖提升为固定版本的直接依赖，不新增其它运行时依赖。
- **测试**：约 54 个浏览器测试文件中涉及“更多操作”（16 个文件）、“调用证据”（6 个）、“版本恢复”（4 个）、“导航与详情”（5 个）、管理链接等选择器的场景需要迁移；新增 CSP 零违规、preflight 视觉、开发者视图开关和默认隐藏场景。
- **前置条件**：`next-generation-nekomimi`（89/89）须先归档。本变更的 delta 以归档后的主规格为基线书写。
