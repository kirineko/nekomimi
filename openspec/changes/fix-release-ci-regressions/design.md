## Context

最新 CI 两组 Linux 通过。Windows 安装包、原生进程和 MCP 检查已通过，失败停在浏览器测试。macOS 22 trace 显示在启动后约 4.5 秒的 GET 中才读取到 unknown，响应及下一次页面绘制接近默认 5 秒断言边界。Windows trace 显示第二个命令已返回独立 runId，但断言看到的仍只有第一轮 Ready，现有完成断言可直接匹配上一轮。

## Goals / Non-Goals

**Goals:** 用准确完成条件和有限预算验证完整轮次，保留历史、回退与未知副作用断言。

**Non-Goals:** 不改产品超时、取消/恢复语义、依赖版本或 CI 触发范围；不跳过失败用例。

## Decisions

- 激活/回退从 POST 获得 receipt id，并轮询 management 中该回执的最终状态；目录指针和历史已生效回执不能代表本次运行时切换完成。
- 命令提交等待 HTTP 接受并验证新增用户轮次及新增完成结果，随后验证对应结果内容。允许 20 秒覆盖进程启动与 Web 投影；不使用 sleep 或自动重试整个测试。
- 未知结果的浏览器等待单独设 20 秒，覆盖 pinned activation、释放重载及 1.5 秒轮询；不会自动重跑未知步骤。
- 长行正则分词与分页断言分开，长行测试使用单独 30 秒预算，普通测试维持现有预算。Journal 仍是唯一权威历史，测试不通过绕过 UI 来伪造完成。

- 新标签 CI 35882756788 的 macOS 22 仅失败于显式重试/迁移综合用例的 15 秒上限；该用例包含多次 pinned 进程启动、释放重载及迁移。限定该用例总预算为 60 秒，保留所有未知结果、attempt 唯一性、迁移失败不改变旧状态与最终内容断言，产品内启动和退出预算保持不变。

## Risks / Trade-offs

- 本机 macOS 无法证明 Windows 修复通过 → 明确记录需要新提交的远端 CI 复验。
- 更长预算可能延后真实错误报告 → 保留强断言、限定到具体场景并验证新增轮次，避免只匹配旧文本。
