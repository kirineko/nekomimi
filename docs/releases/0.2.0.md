候选 CI 暴露并修复了 Windows 短路径与真实路径不一致、嵌套扩展快照路径分隔符问题；进程树退出确认区分已退出的僵尸进程与仍运行的成员。取消测试改为等待真实传输事件，多窗口浏览器测试显式切换操作窗口，失败保留追踪供审查。上述修复继续由完整标签 CI 验证。

后续标签 CI 再暴露两处问题并修复：Windows 上扩展子进程的 fd 3 双向 RPC 通道原以同步命名管道打开，子进程在延迟后写入（延迟返回结果、迟到的 SDK 调用）会被内核与其阻塞读取串行化而死锁，现改为 `overlapped` 打开；macOS 对处于退出中间态的进程组 `kill(-pgid, 0)` 会返回 `EPERM`，进程树退出确认不再将其视为致命错误，而是继续用 `ps` 状态确认直至超时。

2026-09-23 再次准备发布：修复候选激活/回退的回执与新轮次同步、未知工作流的清理等待，以及语法高亮长行测试预算。本地 Node 24.15.0 浏览器 22/22、单 worker 单元 221/221、类型、发布检查、安装包验收和严格规格校验通过；默认并发单元有两次不同旧用例的超时，详细记录保留在 `fix-release-ci-regressions` change。官方 npm 确认 0.2.0 尚不存在，GitHub 无对应 Release，继续等待新标签提交的全部 CI。

重新发布检查中，macOS Node 22 的显式重试/迁移综合测试超过默认 15 秒，已为该多次进程切换场景设置独立 60 秒总预算；Node 22.19.0 的完整 durable-workflows 测试 14/14 通过。产品内部超时及取消、未知结果、迁移断言保持不变。

Windows 后续验证中候选激活/回退已通过，面板工作流的进程启动等待超过默认 5 秒；定制浏览器场景统一使用有限的 20 秒断言、90 秒总预算，无用例重试。Node 22.19.0 定制浏览器测试 9/9 通过，继续进行完整标签门禁。

2026-09-24，标签提交 `b531e08` 的 Linux/macOS 四组 CI 均通过，但 Windows 浏览器追踪确认两个失败均包含 `EPERM · watermark.rename`，运行实际被中断。新增 Windows 原子替换的有界退避，仅对同一已同步临时文件的 rename 重试，保持旧水位可读，不删除目标或重复业务副作用；持续失败仍按原有诊断关闭写入。Windows CI 加入原子替换与 Journal 测试，重新验证完整标签。
