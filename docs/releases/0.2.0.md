## 归档

已同步八份新增、三份修改主规格，并归档 `2026-09-22-deliver-customization-v2`。归档时保留 52/55 的真实验收状态：用户先延期 Linux/Windows，再明确授权归档和发布。跨平台与发布结果在本文件接续，不能把归档当作 CI 已通过。

## 发布门禁

本地 macOS：Node 22.19.0/24.15.0 各 219 项测试；浏览器 22 项；类型、发布检查、包安装、完整审查能力包、严格规格校验通过。真实模型 22 attempts 的五类定制生成/修复/实际使用已记录。

本次发布将等待 `v0.2.0` 的 Linux/macOS 四组 CI 和 Windows 原生安装检查全部通过，再创建正式 Release，使用 Trusted Publishing 上传工作流验收的同一 tarball。当前尚未记录 registry 发布成功；最终提交、CI、integrity 和安装核验将在成功后补充。

候选 CI 暴露并修复了 Windows 短路径与真实路径不一致、嵌套扩展快照路径分隔符问题；进程树退出确认区分已退出的僵尸进程与仍运行的成员。取消测试改为等待真实传输事件，多窗口浏览器测试显式切换操作窗口，失败保留追踪供审查。上述修复继续由完整标签 CI 验证。

后续标签 CI 再暴露两处问题并修复：Windows 上扩展子进程的 fd 3 双向 RPC 通道原以同步命名管道打开，子进程在延迟后写入（延迟返回结果、迟到的 SDK 调用）会被内核与其阻塞读取串行化而死锁，现改为 `overlapped` 打开；macOS 对处于退出中间态的进程组 `kill(-pgid, 0)` 会返回 `EPERM`，进程树退出确认不再将其视为致命错误，而是继续用 `ps` 状态确认直至超时。
