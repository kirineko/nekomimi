# 切换恢复基础阶段记录

本文件保留最初恢复观察和元数据对账的阶段证据。当时总进度 69/89；后续已完成恢复启动、回退与故障验证，最终结果见 `recovery.md`。

`src/core/recovery.ts` 从安装 Journal 投影最后/前一个已确认选择和无终态切换；历史选择不冒充实际运行，running 明确为 not-observed。对记录进程组仅发送信号 0 进行观察，不以旧 PID 为授权杀进程；观察不明确或组仍存在则阻止元数据对账。历史 PID 被复用可能造成保守阻挡，不能自行按 PID 终止。

CLI `core recovery-info` 不创建注册或加载候选。`core reconcile` 明确授权并确认 planHash，取得安装 writer 后复核 Journal 头和进程观察，单条事实记录元数据收据；重复命令原样返回，改变输入拒绝。未知切换仍未知，不写 applied=true，不打开业务存储、不执行候选代码或任务。没有进程记录不证明 OS 中没有进程，本接口不据此宣布可安全启动。

验证：`recovery-unit.log` 3 文件 17 项通过，其中 5 项恢复测试覆盖空安装无写入、不同中断记录投影、明确授权与重复命令、业务数据字节不变、活跃 writer 拒绝，以及实际受控子进程组存在时拒绝、退出后允许元数据对账。阶段投影使用构造 Journal，不冒充真实 supervisor kill 故障注入。另以编译后 CLI 和全新隔离 HOME 执行 recovery-info，验证目录仍为空。
