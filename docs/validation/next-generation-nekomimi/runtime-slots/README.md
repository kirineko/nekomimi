# 10.9 插槽与桥接阶段验收

本记录只覆盖 10.9 的扩展接入阶段，**不代表 10.9 已完成**。默认入口仍为旧 UI，`/v2` 为新工作台；旧页面/样式清理、剩余功能迁移及完整浏览器回归继续保留在任务中。

## 实现

- 面板 SDK 要求 `contractVersion:3`、显式非空 modes、`targetScope:current`、title 和六个正式区域。`registerPanel` 使用 tool-result/sidebar-widget；旧 result/sidebar 明确拒绝。iframe 消息协议仍为 uiVersion 1。模板、分发示例、规格和开发文档已同步。
- 注册 API 对应的 panels/views 权限由宿主写入构建产物，不从 slot 推断，也不信任扩展传入字段。挂载再次检查模式；面板事件携带范围与资源版本。
- 文档读取、宿主桥接、工作流操作及卸载均校验挂载会话，拒绝发生在消息序号/限流计数变更之前。候选预览的无操作权限生命周期保持独立。
- 运行时目录按会话查询及缓存。新工作台接入头部、工具栏、侧栏、消息/工具 renderer 和独立页面；历史读取及刷新均不自动挂载。顺序稳定，替代 renderer 单选且可恢复宿主展示。
- 草稿桥接只填写不发送，已有内容提供保留/追加/替换；导航只允许绑定会话，页面只允许同资源 page。卸载或故障中止尚未处理的草稿请求，两个模式使用各自目标和草稿。
- iframe 故障显示保存的文本回退；React 局部边界防止单个贡献破坏工作台。管理页共享同一桥接。修复命令补全定位到不存在 textarea ID 的问题。

## 验证范围

环境为 macOS arm64 / Node 24.15.0 / 本机 Chrome；使用临时目录、真实扩展子进程与本地 HTTP/iframe。没有真实模型调用，也不以此宣称 Linux 或完整安装包验收通过。

- 完整类型检查与构建退出码 0。
- 6 个单元测试文件、24 项通过：跨会话 HTTP 读/操作/卸载拒绝及原会话继续操作，SDK 模式/区域校验、候选预览、工作流集成与前端契约。
- 最终浏览器结果见 manifest 与 `browser-final.log`；包含新增插槽场景以及候选、面板管理、历史和工作台回归。
- 严格规格校验 43 项通过。

## 首次失败与修复

新增 HTTP 夹具最初错误假设示例名称为 sakura，而实际为 sakura-studio；随后直接改授权再 acquire，没有重新加载启动时已初始化的宿主。改用准确资源身份及 requestReload/reload 收据后通过。这些失败属于测试夹具，未放宽隔离断言。

首次浏览器运行 11 项通过、2 项失败：测试扩展缺少公开 SDK 类型注解和 const tuple，被生产静态检查拒绝。补上 ExtensionFactory/PanelModule 与 tuple 类型后，两条场景通过；首次日志完整保留。随后补充离开待处理草稿冲突的回归，并对最终构建复验。

旧契约有意拒绝，不增加静默适配；旧 UI 测试中尚需迁移的布局选择器保留为后续任务，不能用本阶段定向回归替代完整浏览器验收。
