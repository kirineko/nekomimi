# 10.9 失败恢复、诊断与搜索证据迁移

本阶段从旧浏览器场景定位并补齐实际缺口；10.9 仍未完成，总进度保持 77/89，默认入口未切换。

## 已实现

- 工作/创造失败状态显示中文诊断说明与“继续任务”。继续仅填写当前模式、目标、会话草稿，不提交、不恢复运行；已有草稿时默认保留，显式选择追加或替换。提示明确要求先核对未知结果而不自动重跑。完整原始调用仍可通过证据查看。
- 双模式恢复非权威运行诊断入口；即使 durable cursor 和状态未变，新的诊断元数据也能显示。诊断下载为只读请求，有同步去重、取消与显式错误重试。
- 鼠标/键盘点击发送后立即将焦点放回当前编辑器，不依靠晚到响应恢复焦点；提交期间新草稿和已打开弹层不受旧响应影响。
- 恢复保存的搜索来源与历史 web_fetch 摘要，不重新读取远端网页。来源最多呈现前 10 项，拒绝非 HTTP(S) 或带凭证网址，文本经 React 转义。历史网页读取仍只作证据展示，没有重新注册已移除工具。
- 新顶栏使用与 favicon 相同的现有猫耳 SVG，维持轻量点缀与独立文字品牌。
- `search-brand.spec.ts` 已迁至新工作台，保留实际图标解码、搜索调用次数、web_fetch 未注册、刷新不重放、窄屏与浏览器异常断言。

## 默认入口切换前新增审计记录

未更改下列仍有效的主规格来迎合现实现；它们仍是 10.9/11.1 所需工作：

1. `compact-header` 要求统一更多菜单、外观内的显示扩展内容开关、宿主独立恢复、取消主题预览与焦点恢复。当前 TopBar 仍直接列出恢复/明暗按钮；需要迁移实际控件并验证，不能简单删掉 header-recovery 旧场景。
2. `web-feature-loading` 要求低频界面专用代码按使用加载、局部失败/显式重试和取消迟到加载。新 router 仍静态导入管理页，SessionExport/Inspection 部分也同步进入工作入口；details 只有 React.lazy/Suspense，尚无可靠重试边界。需要恢复按需分块/局部错误处理并测量冷启动 JS。
3. 其余旧场景仍涉及聊天加载/滚动、上下文预算、工作区与定制管理。既有 v2 专项通过不能直接替代逐项等价迁移；旧入口/页面/样式只能在对应行为可用后删除。
