# 11.6 上下文与长会话性能对照

2026-10-09，同一 macOS arm64 / Node 24.15.0 / Chrome 154.0.8037.98。旧版为基线 be50c5a8a1557ef160056b964cd29e65b395685d 的独立构建，新版为当前未提交工作树。仅使用本地 SSE 响应，无真实模型调用或成本/质量结论。

## 方法

`scripts/measure-runtime-performance.mjs` 两版均使用 deepseek-flash、maxOutputTokens=2048、read/write/edit/bash 四工具、相同任务和 0/400 条历史，每组 3 次。每次使用独立工作区与数据目录；`--expose-gc` 在运行前收集，但进程和模块跨样本复用，首样本与后续样本并非独立冷进程。准备延迟从 run 入口到 fetch 接收最终请求，包含准入、上下文和持久化，不等于模型延迟。RSS 是 5ms 定时采样峰值，包含 Node、模块及之前样本残留，不能视为会话专属内存。原始 memoryUsage 各字段保留在 JSON。

## 浏览器阅读

`scripts/measure-history-browser.mjs` 对相同 450 条历史各执行 3 次：读取最新、连续 6 次前翻、固定阅读位置、前方内容增加 240px、返回最新、刷新。两版均保留最多 180 个锚点，收敛后位置误差为 **0px**，读取不改 Journal。中位数如下：

| 指标 | 原版 | 当前 |
| --- | ---: | ---: |
| 首屏就绪 ms | 81.88 | 125.44 |
| 锚点收敛 ms | 116.50 | 115.54 |
| 返回最新 ms | 64.13 | 68.39 |
| 刷新恢复 ms | 57.02 | 103.75 |

分页每一步的耗时保留在 JSON；锚点检查含 Playwright 轮询，约 115ms 不是渲染器内部精确耗时。所有阈值保持 2px，不通过放宽断言消除回归。

## 回归与限制

当前准备延迟、RSS、浏览器首屏与刷新中位数均有回归；请求 schema 减少 4 bytes，但输入增加 155 bytes，总请求增加 137 bytes。该夹具只衡量相同四工具的普通工作请求，不将结果外推为 Codemode 或所有任务类型普遍节约 token。机器后台负载、文件系统同步、JIT 和缓存会影响短时采样；浏览器采样期间 Linux 镜像后台下载仍在进行，两版采用相同机器和配置，不能据此给出精密微秒或跨机器排序。

冷启动分块与三类入口体积另见 [loading-performance](../loading-performance/README.md)：首页原始字节仅下降 0.07%，gzip 估算和直接会话 JS 均有回归。未宣称整体性能提升。此前逐消息延迟渲染导致的滚动错误已撤回；完整回归及安装产物仍须在最终代码上验收。
