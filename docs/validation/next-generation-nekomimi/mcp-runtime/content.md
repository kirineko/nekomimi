# 6.4 MCP 内容、prompt、订阅与模式上下文验收

资源/模板/prompts 继续通过单一 Pi MCP 连接和宿主有界分页/协议适配。内容目录现有固定 contentRevision，包含服务器、配置和完整发现列表；catalog 返回独立副本，外部修改不影响捕获定义。每次读取保留原响应 digest、URI/模板参数、服务器与目录版本。prompt 原始角色保留为证据，模型只接收工具数据；资源链接不自动下载。

mcp_content 的结果新增独立 mcp.content.observed 事实，引用模式、目标、服务器、操作及原始结果附件，明确不授予权限；之后工具结果/上下文投影沿现有记录链处理。订阅通知只合并为待刷新，旧结果及固定目录版本不变；显式重读取得新内容 digest，退订清除状态。

跨模式实际运行采用独立创造开发目录与工作目标：创造读取的专用标记出现在创造工具结果、没有进入 system 指令；同一服务器配置放到工作目标后仍是 untrusted，工作请求没有 mcp_content 声明，也不包含该正文，工作 Journal 无读取事实。已有交接来源/目标权限与显式选择回归继续通过。

18 项相关测试通过（customization-mcp-content、mcp-demand、mcp-version-runtime、handoff-context）。随后增加模板和 prompts 各两页夹具，内容测试 6 项再次通过。覆盖三种分页、参数检查、原始角色/引用、通知合并、固定版本/新 digest、目录副本、超限/撤销及模式目标隔离。类型、构建、43 项严格规格及 diff 检查通过。

首次跨模式测试错误地共用项目与开发目录，被既有独立目标约束拒绝。仅修正测试为真实独立目录，未放宽约束；失败日志保留。没有真实模型或外部服务调用。OAuth 生命周期的新门槛仍由 6.5 实施。
