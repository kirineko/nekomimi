# 请求与执行边界的撤权及作用域再校验（任务 4.4）

2026-10-07，macOS arm64 / Node 24.15.0。假 Provider、本地 HTTP、SDK 子进程及真实 Journal I/O 边界；未进行真实模型质量验收。验收状态以实际日志和任务勾选为准。

`ResourceAccess` 保存捕获的身份、作用域与根目录身份，在派发前只读检查当前目录、来源是否存在、真实路径是否越界、授权及声明能力是否撤销。发现不加载新工厂，不用更新后的内容替换原请求。每次准备重新撤下失效技能／规则／扩展贡献及工具指导，保留 `instruction.withdrawn` 的旧内容 hash 和原因；后续快照记录明确的排除来源、当前资源状态及历史读取证据。新权限不在运行中自动恢复已经撤下的正文，显式读取仍验证当前授权。

固定工作流的执行副本与逻辑授权来源分开：非包快照保存 `authorityLocation`，已有 SDK 3 快照可从持久原始 manifest source 定位该来源；副本完整性仍由工作流的内容校验保护。包工作流按原逻辑资源和绑定范围校验当前安装及授权，不把不可变版本目录的更换当成授权目标变化。停用、卸载、范围变化或减少授权继续阻止旧版本执行。候选模拟可在显式授权但尚未激活时调用原有 mock 服务，仍验证当前 grant；生产请求没有该模拟准入。

主请求及独立辅助 Provider 都在序列化证据后、可靠派发意图后再次验证来源、配置及凭证。前置 hooks 仍只运行一次；统一工具管线分别在产品意图前、可靠意图后进行无 hooks 的执行再校验。执行前被阻止记录 `tool.blocked`，意图后的拒绝另记录 `unknown:false / effect:not-dispatched`。已有意图附件仍保留，不能用存在 `request.dispatched` 意图事件推断已发送 HTTP；后续 `request.blocked`、HTTP headers 与实际假 Provider 接收数共同证明事实。

新增验证覆盖：停用已加载技能后的实际续轮、准备后仅内容更新／撤权／意图落盘期间撤权、已准备工具及工具意图落盘期间撤权、来源删除与越界符号链接。内容更新保持旧捕获正文；撤权均零新增网络或外部效果；旧请求 bytes/hash 和原文附件逐项不变。路径越界撤下已加载正文并让请求失败，不在目录发现失败后继续发送。
