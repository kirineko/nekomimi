## 冷启动实际请求

可复现脚本：`node scripts/measure-web-loading.mjs <构建根目录> baseline|current <结果.json>`。三个 fixture 各采样 3 次：未选会话首页、空会话、包含相同消息/Markdown 表格的历史会话。每次新建浏览器上下文，1440×1000，监听实际 JS 响应，界面可见后保留 1.5 秒观察窗口。不打开可选界面、不调用模型。JSON 保存请求文件、字节数及 SHA-256。

| 入口 | 原版 JS 字节 | 当前 JS 字节 | 原版 gzip 估算 | 当前 gzip 估算 |
| --- | ---: | ---: | ---: | ---: |
| 首页 | 480150 | 479824 | 148421 | 159674 |
| 空会话 | 480150 | 786278 | 148421 | 255244 |
| 历史会话 | 480150 | 786278 | 148421 | 255244 |

服务以 identity 传输，JS 字节按响应解码后的实际内容统计；gzip 是同一 Node gzipSync 默认选项的离线估算，不冒充网络传输量。各入口 3 次字节数一致。当前最大原始分块 **361261 bytes**，gzipSync **114513 bytes**；全部分块低于 500 kB，Vite 构建不再超限。原版最大分块 471249 bytes / gzipSync 145039 bytes。

首页原始字节仅下降 326（约 0.07%），gzip 估算反而增加约 7.6%；直接会话 JS 增加约 63.8%。因此不能宣称整体加载更快。JSON 保留就绪时间，但短时本机采样受缓存、后台负载和并行类型检查影响，尚未作为稳定延迟结论。此前两个基线夹具失败因遗漏 assistant attempt 身份，最终两版使用相同来源身份；失败日志不删除。
