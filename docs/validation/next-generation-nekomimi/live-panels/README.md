# 11.1 实时面板未变契约修复

兼容审核发现 `custom-web-panels/故障与历史回退` 从未撤销当前运行新产生面板直接展示的要求；新 SavedRow 一律要求手动打开，旧 runtime-ui 测试迁移时也跟随了这一偏差。本批恢复原行为，未修改该主规格以迎合实现。

## 实现

时间线为新鲜 SSE 面板记录保留一次展示资格，先只读刷新目录并核对保存资源版本/模式，再挂载有效面板。资格在父时间线中有界保存，虚拟行卸载不会重新获得；进入页面前已收到的记录不自动展示。隐藏状态消费资格，重新显示不执行旧结果；异步目录返回时核对实时阅读状态，卸载后不能迟到打开。

快照/刷新、断线补读、历史分页和虚拟重挂保持显式打开，已有正常 UI 更新不销毁面板输入。成功组件外不再重复输出回退文本；历史及错误仍可读。面板 factory/桥接继续沿用原授权、版本和目标验证。

## 已完成验证

- 双模式新测试使用真实扩展进程/SDK 命令、保存结果和 iframe；当前结果自动展示一次，虚拟卸载重挂、刷新及离线补读不自动挂载；手动打开有效，原草稿保留，隐藏期间新结果在重新显示后也不挂载。命令效果文件恰好三次，模型 transport 禁止调用。
- 原工作主题/草稿冲突/历史重开场景恢复实时展示断言；原创造候选场景也恢复当前命令面板直接展示，历史刷新仍无 iframe。
- 首轮 2/3，创造模式暴露执行前目录缓存；改为首次实时展示前重新读取目录后，四项关键场景 **4/4 通过**，见 focused.log。
