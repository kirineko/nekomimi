# 定制开发 SDK 2（实施中）

本文件描述当前 V2 开发实现。发布候选、跨平台验收和完整组合演练尚未完成；以项目 change 和验证记录为准。SDK 1 保持兼容，新增注册使用 `ExtensionFactory2`，清单 `sdkVersion: 2`，逐项声明 `requiredCapabilities`。通过 `customization_sdk` 查询实际声明，不猜测接口。生成文件放在候选或工作区，不能修改安装目录。

## 开发与能力包

`customization_candidate` 提供脚手架、写文件、完整 TypeScript 校验、独立模拟试验和请求激活。校验绑定内容 hash；授权后通过活动指针事务切换。工具不能替用户授予新权限。重载收据为 pending 时应结束当前任务，下一轮使用新版本。

`customization_package` / `nekomimi packages` 支持 prepare、inspect、activate、list、rollback、export、uninstall。源为 `{kind:"local",path}`、`{kind:"npm",name,version,registry}` 或 `{kind:"git",url,commit}`。npm tag 与 Git branch 解析后写入精确锁，依赖独立于宿主，不运行安装脚本或用户构建配置。导入导出使用本地 tgz；Rules 需重新绑定目标，凭证与状态不打包。

包的 `nekomimi.json` 声明 `manifestVersion:1`、name、version、`sdkVersion:2`、requiredCapabilities、dependencies、resources，以及额外公开 files。资源 kind 可为 extension、skill、rule、mcp、provider、workflow、panel；可执行入口均为 SDK 工厂，面板静态入口另由 registerPanel 声明。每个资源具有独立身份，同一包 revision 共享子进程。Rule 的 ruleScope 与安装时 bindings 共同决定目标。

`packages collect '{"scope":"project","discardCandidates":["候选 UUID"]}'` 只显式回收未引用缓存。安装历史、回退、剩余候选和工作流 Journal 引用均保留；不会删除用户会话、工作流或私有状态。

## Provider 与模型配置

`http-providers.ts` 演示 Responses / Chat Completions 的 JSON/SSE adapter。序列化与解析在扩展进程，实际 HTTP、密钥与 RecordedCall 在宿主。声明 model 的协议、historyCompatibility、上下文/输出预算及 tools/images/reasoning 能力；不要把不支持的能力静默降级。原始请求和响应是证据，canonical projection 只是投影。通用协议的工具调用必须用 toolEvidence 指向原始字段。

Web「模型提供商」或 `providers save/select/credential` 配置 profile。main、auxiliary、naming 分开选择；辅助调用上下文独立，内置搜索仍遵循搜索配置。凭证仅保存服务端引用；CLI 用 `--credential-file`，不要写入命令参数、扩展源码或面板 props。旧 DeepSeek settings/auth 可继续使用，显式迁移保留私有备份。

不兼容历史拒绝直接续跑；`branch <session> --output <new-directory> [--omit-reasoning]` 或 Web 分支入口明确转换，并保留原事件与 artifacts；未知工具结果不能被伪造成成功。

## MCP 内容与 OAuth

`mcp_content` 显式发现、读取资源/模板、获取 prompt、订阅和退订。返回值是带源 URI/参数/版本的非可信工具数据，不是 Skill，也不会提升为 system 指令。通知只标记需要刷新，不修改已发出的模型请求，不自动执行工具或下载资源链接。

HTTP MCP 的 OAuth 配置为 `{issuer,clientId,scope?,redirectPort?}`，或者 `{issuer,dynamicRegistration:true,scope?,redirectPort?}`。只支持公开客户端、authorization code、S256；动态注册需要发现元数据中的同 issuer 注册端点。固定回调路径 `/oauth/callback`；注册过的静态客户端如限制端口可显式配置 redirectPort。服务/issuer/resource/client 绑定必须一致，不回退 implicit 或 client-secret。CLI `mcp-auth authorize <id>` 和 Web 打开授权 URL；tokens 私有存储，刷新串行，失败要求重新授权，断开不会自动重试工具。

## 持久工作流与工作区状态

`durable-review.ts` 演示 registerWorkflow、显式步骤与持久表单。每一步返回 next、wait 或 complete，只能转移到声明的步骤。wait 返回稳定交互身份，重启后仍可回答。SDK 1 的 ctx.ui(form) 仍是当前运行的临时表单，不具有持久等待语义。

每个工作流有独立 Journal，原会话只记录 workflow.reference。步骤意图先落盘；已有完成记录不重跑，意图后没有结果则为 unknown。必须核对外部效果，提交真实结果或明确授权新 attempt；不会自动重试或补偿。

`nekomimi workflows list|inspect|start|resume|answer|resolve|cancel|migrate|evidence|artifact` 使用 JSON 参数。Web 提供状态、证据、回答、恢复及 unknown 核对入口。恢复执行需显式操作；`recover` 只补投待办元数据。命令、工具完成和运行完成可触发工作流，队列最多 64 个未结束流程，因果链最多 8 层，同一链中不能再次触发同一定义；启动服务不会自动执行遗留待办。

ctx.workspaceState 使用 resourceId 命名空间和 schemaVersion、expectedRevision CAS。跨 Journal outbox 只补投状态，不重跑外部操作。`workflows state-get` 读取；`state-migrate` 显式提供 resourceId/key/fromSchemaVersion/schemaVersion/expectedRevision/value。迁移保留旧值证据，不兼容状态不会被自动清空。

## 面板、renderer 与主题

`panel-extension.ts` 与 `review-panel.ts` 演示 registerPanel 和浏览器 `PanelModule`。复制两份文件到同一资源目录，清单能力需 panels、commands、ui；panel.entry 是静态模块，默认导出 `{mount(root,context)}`。可以使用 DOM API，或在包内显式锁定 React 与其类型依赖后使用 TSX；构建不读取用户 tsconfig/插件/生命周期脚本。

propsSchema 校验结构化数据；slot 为 sidebar/result，fallback 必填。renderer 可绑定工具名，接收 `{tool,args,result}`。使用 `ctx.ui({kind:"panel",title,panelId,props})` 记录独立结果面板；历史保存原始 props artifact、资源 revision、bundle hash 和文本回退，不依赖重新运行脚本。

面板运行于无同源身份的 sandbox iframe，独立 CSP 禁止直接连接、外部脚本、表单提交与子框架；父窗口验证消息 source、nonce、版本和实例，再使用 MessageChannel。允许的桥接动作仅为声明的 workflow.state/answer/cancel；服务端重新检查授权、活动版本及绑定工作流，answer 使用稳定 waitId、CAS 和幂等命令。回答不会隐式继续执行，使用宿主“继续”入口。

theme 只接受 background/foreground/accent/border 的十六进制颜色，作用于面板内部。宿主授权、关闭和取消控件不由扩展 CSS 控制。组件失败或缺失时显示 fallback 与结构化数据；历史页面需显式打开仍被授权的同 revision 面板，导入和离线 HTML 不执行包脚本。

浏览器 sandbox 阻止顶层导航，组件 CSP 拒绝网络 API；宿主 frame-src 将 iframe 自身导航限制在面板响应路径。Chromium 已验证越权自身导航不会请求目标 API，其他支持平台仍需原生验收。Node 扩展也是可信代码，进程隔离不限制其直接文件/网络权限。
