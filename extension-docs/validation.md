# 验证与调试

| 阶段 | 证据 | 不代表什么 |
| --- | --- | --- |
| static | 清单/完整 TypeScript 校验、内容摘要与诊断 | 工厂已经执行 |
| simulation | 独立运行记录，模拟工具/模型/表单 | 外部操作或真实 UI 已通过 |
| preview | 指定资源版本的独立面板预览 | 宿主授权、命令与布局集成已通过 |
| host integration | 实际宿主入口、操作与展示结果 | 其他平台也已验证 |

使用 `customization_validate` 或 `nekomimi extensions validate <id>`，根据文件位置修复并重新检查。`customization_candidate` 的检查、模拟和激活绑定内容摘要；修改后不能复用旧通过结果。`customization_sdk` 读取安装版本契约，不猜接口。

UI 验收：激活 → 应用完整主题 → 实际执行命令 → 直接看到内容 → 面板交互与草稿冲突 → 刷新摘要 → 显式重开 → 禁用/卸载回退 → 离线阅读。记录资源 revision、浏览器平台、各阶段状态和未完成项。用户取消开发或候选失败时继续使用原活动版本。

面板未出现时先检查当前/历史状态和是否收起，再查看开发详情中的授权、版本、props schema、构建、握手或实例失效原因。不要通过重复执行原命令来重试挂载。不要把 credentials 放进 props 或调试截图。

全局样式异常可使用「恢复默认界面」；主题素材失败使用文本和系统字体回退。工作流 unknown 需人工核对真实外部结果，恢复或导入不自动重跑副作用。真实模型密钥不是离线验证和 CI 的前提。
